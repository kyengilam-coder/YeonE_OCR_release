# YeonE_OCR · 연어OCR

세로쓰기 한자·한글 혼용 문헌(풍수·역학서 등 스캔 PDF)과 가로쓰기 한문(간체) 문헌을 `yeone_ocr/지침.md`에 따라 OCR·교정해 **HWPX 또는 검색 가능한 문자 PDF**로 만드는 PC 프로그램입니다.
기존 AI 판독에서는 **Gemini·ChatGPT(OpenAI)·Claude(Anthropic)** 중 고른 모델이 읽고, 프로그램은 영역 잘라내기·두 판독 비교·3차 글자 판별·문서 조립·상태 기록을 맡습니다. **0.9.0**은 AB_OCR의 **Tesseract·RapidOCR·EasyOCR 비교·원본 대조 편집**에 **AI 이미지·문맥 재검증과 번체자·중문부호 제안**을 연결합니다.
PDF는 **[일반 OCR]**, 이미지와 캡처는 세 번째 **[이미지(스크린샷) OCR]** 탭에서 원본을 고르고 **[한 번에 인식]**을 누릅니다. 읽기 방향·인쇄 쪽수 차이·이전 판 기록 갱신·2차 비교·3차 판별·문서·검수 화면·보고를 프로그램이 알아서 이어서 합니다.

## 0.9.0 · 세 엔진 비교와 AI 재검증

상단의 **[3엔진 비교·교정]**을 누르면 현재 일반 OCR·책갈피 OCR·이미지 OCR에서 고른 원본으로 편집 창이 열립니다. 기존 세로 읽기·책갈피 교정·캡처 입력·HWPX 및 검색 PDF 작업은 기존 작업 탭에서 계속 사용합니다. **로컬 세 엔진 인식은 외부 전송 없이 실행**합니다. AI 재검증을 실행할 때만 선택한 제공사·모델에 지정한 쪽의 이미지·문맥을 전송합니다.

1. 비교 창의 **[엔진 폴더…] → [설치 확인]**에서 세 엔진을 확인합니다. 현재 PC에서는 기존 AB_OCR의 실행 환경·공개 모델을 재사용하며, 인식 코드는 연어OCR에 포함되어 있습니다. 새 PC 설치는 [로컬 엔진 안내](docs/LOCAL_OCR.md)를 따르십시오.
2. **번체·한문 / 간체·중문 / 한글·한자 혼용**, 읽기 방향과 쪽 범위를 고르고 **[현재 쪽 · 세 엔진 인식]** 또는 **[지정 범위 · 이어 읽기]**를 실행합니다. 완료한 엔진마다 기록을 저장하며 중지 후 이어 읽을 수 있습니다.
3. 왼쪽 원본을 확대하고 오른쪽의 엔진별 원문·불일치 후보·교정문을 대조합니다. 후보를 채택하거나 기준을 유지하고, 직접 수정·되돌리기·사람의 검수 완료를 기록할 수 있습니다. **다수결이나 confidence로 자동 치환하지 않습니다.**
4. **AI 검증**에서는 기존 설정의 제공사·모델·키와 대상 쪽·번체자·중문부호 정책을 확인하여 실행합니다. 불일치의 이미지 재판독 뒤 선택한 쪽의 번체자·부호 제안을 만듭니다. **AI 검증 제안**에서 사유와 수정 전후를 보고 채택·기각합니다. 원시 OCR·AI 응답과 제안·사람의 확정 이력을 구분해 보존하며, AI 응답을 현재 교정문에 자동으로 덮어쓰지 않습니다. [AI 사용·저장 안내](docs/AI_REVIEW.md)
5. **[저장]**으로 원시 판독·AI 제안·교정 이력을 보관하고 **[내보내기…]**로 TXT·HWPX·DOCX를 만듭니다. 기존 연어 기록과 AB 프로젝트는 원본 지문을 확인한 뒤 읽기 전용으로 가져옵니다.

두 신경망 엔진의 한국어 모델은 한자를 지원하지 않습니다. 지원하지 않는 글자의 누락은 채택 가능한 판독 근거에서 제외합니다. 새 로컬 세로 비교는 시험 기능이며, 기존 AI 세로 읽기의 품질을 대체하거나 개선했다고 주장하지 않습니다. [통합 기능·저장 정책](docs/INTEGRATION.md) · [개발 인수인계](docs/HANDOFF.md)

명령줄에서도 같은 로컬 비교 프로젝트를 만들 수 있습니다.

```powershell
python -m yeone_ocr compare-engines "D:\문헌\원본.pdf" --pages 1-3 --profile traditional --direction horizontal --work "D:\문헌\작업" --engine-root "D:\OCR엔진"
```

0.9.0 다운로드 주소는 [v0.9.0 릴리스](https://github.com/kyengilam-coder/YeonE_OCR_release/releases/tag/v0.9.0)입니다. 배포 완료 후 설치 파일·포터블·소스·라이선스 ZIP과 SHA-256 목록을 이 주소에서 받습니다. 로컬 빌드 위치는 `dist/0.9.0`이며 검증 범위는 [릴리스 기록](docs/release-notes.md)에 정리했습니다.

통합 전 AB_OCR 0.3.0의 공개 소스는 [원본 코드 보존 안내](references/README.md)에 따라 소스 저장소와 소스 ZIP에 함께 보관합니다. 이 보존 사본은 실행에 사용하지 않습니다. 실제 앱은 `yeone_ocr`와 루트의 `ab_ocr` 통합 코드를 사용하며, 보존 사본에는 개인 문서·작업 기록·엔진 실행 환경·모델 가중치를 넣지 않습니다.

## 시작하기 (Windows)

**Windows 10/11 x64 설치판에는 앱 실행에 필요한 Python과 패키지가 포함됩니다.** 배포 완료 후 [0.9.0 다운로드](https://github.com/kyengilam-coder/YeonE_OCR_release/releases/tag/v0.9.0)에서 **`YeonE_OCR-0.9.0-Setup-x64.exe`**를 받아 실행한 뒤 시작 메뉴의 **연어OCR**을 여십시오. 기본 설치 위치는 `%LOCALAPPDATA%\Programs\YeonE_OCR`이며 현재 Windows 사용자 계정에 설치됩니다. 바탕 화면 바로가기는 설치 중 선택할 수 있습니다. 로컬 세 엔진의 실행 환경과 공개 모델은 별도로 설치합니다. [로컬 엔진 설치 안내](docs/LOCAL_OCR.md)를 따르십시오.

네 번째 **[설정]** 탭에서 **Gemini / ChatGPT(OpenAI) / Claude(Anthropic)**를 고르고 해당 제공사의 API 키와 모델을 설정합니다. **[설정 저장] → [OCR로 돌아가기]**를 누른 뒤 PDF는 **[일반 OCR]**의 **[PDF 고르기…]**, PNG·JPG 등은 **[이미지(스크린샷) OCR]**의 **[이미지 고르기…]**에서 선택하고 **[한 번에 인식]**을 누릅니다. 세 작업 탭의 원본 선택은 각각 유지하며 공통 설정을 함께 사용합니다. API 사용 권한과 비용은 별도이며 ChatGPT·Claude 웹 구독으로 로그인하는 방식은 아닙니다. 설치판에는 API 키가 들어 있지 않습니다.

작업 탭에는 원본 선택과 쪽 범위, 현재 판독기·모델·읽기 방향 요약, 실행·결과 열기를 둡니다. **[설정 바꾸기]**를 누르면 **[설정]** 탭으로 이동합니다. 설정 탭은 Windows 설정처럼 줄마다 이름과 한 줄 설명(왼쪽)·조작(오른쪽)을 두고 두 열로 나눕니다 — 왼쪽(읽는 쪽) **판독**(판독기·모델·API 키·기록 있는 쪽도 다시 판독, [세부 설정 ▾]에 2차 판독 모델·속도·조각·판독 단계·1차 판독·호출 상한) · **이 책 — <원본 이름>**(쪽 범위·읽기 방향·문서 짜임·양식 HWPX·짜임 규칙·획 굵기, 끝의 접힌 **[고급 ▸]**에 인쇄 쪽수 보정 — 값이 있으면 펼친 채) · 접힌 **책갈피 OCR 교정 ▸**(교정 정책·메모·재판독), 오른쪽(만드는 쪽) **문서 만들기** · **자동 교정** · **모델 단계**. 켜거나 끄면 모델 호출 수가 바뀌는 줄에는 영수증 표, 비용 창 [아니요]로 이번 실행에서 빠지는 것에는 `[아니요]면 뺌` 꼬리표가 붙습니다. 창이 좁으면(논리 너비 1100 미만) 한 열로 쌓입니다. 설정 탭 바닥에 늘 보이는 **[설정 저장]·[OCR로 돌아가기]**로 설정을 저장하고 작업 화면으로 돌아오며, 그 옆 알림 줄에 저장 결과 같은 마지막 소식이, 오른쪽 끝에 **시작할 때 업데이트 확인**이 있습니다. 작업 탭은 위·아래 칸으로 나누지 않고 한 화면에 카드로 둡니다 — 책 카드 아래 **진행** 카드(상태 알약 · 전체 막대 · 단계 띠 준비 → 판독 → 3차 판별 → 문서 만들기(문자 PDF면 글자층 넣기) → 검수 화면 → 보고, 단계마다 예상 비용과 영수증·`[아니요]면 뺌` 표지 · 큰 숫자 · 지난·남은 시간 · 이번 실행 호출 · 쪽 띠), 그 아래 **[진행 기록 | 쪽별 상태]** 기록 카드가 남은 높이를 채웁니다. 쪽 띠는 판독하는 동안 쪽마다 바로 바뀝니다(끝남 · 지금 판독 중 · 실패 '!' · 기록 있어 건너뜀 · 남음 — 큰 숫자 줄에 '지금 14~18쪽 판독 중 (동시 5쪽)', 멈추면 읽던 쪽은 다시 '남음'). 칸이 모자라면(수백 쪽) 한 칸에 여러 쪽을 담고, 칸을 누르면 쪽별 상태에서 그 쪽 줄을 보입니다. 단계별 실행·도구는 기록 카드 머리의 **[고급 도구 ▸]**로 펼칩니다(실행 중에는 잠김).

**화면 일부를 읽으려면:** `Win+Shift+S`로 글이 있는 부분을 캡처한 뒤 세 번째 **[이미지(스크린샷) OCR]** 탭의 **원본 미리보기 상자를 클릭하고 `Ctrl+V`**를 누릅니다. 상자에서 마우스 오른쪽 버튼 → **[이미지 붙여넣기]**로도 불러오며, 기존 `Ctrl+Shift+V` 단축키도 사용할 수 있습니다. 붙인 이미지가 상자에 나타나고, 두 번 클릭하거나 오른쪽 메뉴의 **[원본 크게 보기]**로 원본을 엽니다. 확인한 뒤 **[한 번에 인식]**을 누르십시오. 붙여넣기는 원본을 저장하고 선택하는 단계이며 API를 호출하지 않습니다. 이미지의 읽기 방향은 **자동 판정이 기본**이며 실제 그림의 글줄을 분석해 가로쓰기·세로쓰기를 고릅니다. 일반 OCR의 읽기 방향과 별도로 저장하므로 PDF 작업에서 선택한 방향이 새 이미지에 그대로 적용되지 않습니다.

**여러 장을 붙여넣으려면:** 첫 이미지를 붙인 뒤 다음 이미지를 캡처하여 다시 `Ctrl+V`를 누르십시오. 기존 쪽 뒤에 붙여넣은 순서대로 추가하고, 새로 추가한 마지막 쪽을 보여 줍니다. 미리보기 아래의 **[이전]·[다음]과 `현재 / 전체 쪽수`**로 모든 쪽을 확인할 수 있습니다. 파일 탐색기에서 이미지 여러 개를 복사해 한 번에 붙여넣어도 됩니다(한 번에 복사한 파일끼리는 이름의 숫자 순서). 같은 이미지를 다시 붙이면 한 쪽을 더 추가합니다. 쪽 범위를 비우고 실행하면 쌓인 이미지 전체를 HWPX 또는 문자 PDF로 만듭니다. **[이미지 고르기…]는 새 원본 선택**, **[입력 비우기]는 새 묶음 시작**에 사용합니다.

방향 판정은 내 PC에서 처리하며 추가 API 호출이나 요금이 없습니다. 글자층이 있으면 먼저 활용하고, 없거나 부족하면 이미지의 글줄 간격·배치를 분석합니다. 빈 화면·그림 위주·가로와 세로 근거가 비슷한 경우에는 불확실한 이유를 알리고 세로쓰기 기본값을 사용합니다. 이때는 이미지 탭의 **[설정 바꾸기] → [읽기 방향]**에서 직접 고르십시오. [읽기 방향]은 현재 작업에 맞춰 일반·책갈피 OCR용과 이미지용 설정을 각각 기억합니다.

**다음 이미지를 기다리려면 [입력 비우기]를 누르십시오.** 이미지 탭의 선택 원본·쪽 범위·인쇄 쪽수 보정·강제 재판독과 저장 위치·진행 표시를 초기화하고 새 파일이나 캡처를 기다립니다. 디스크의 원본 이미지·판독 기록·HWPX와 화면의 진행 기록 이력은 보존합니다. 일반 OCR·책갈피 OCR의 원본 선택, API·모델·문서 설정도 유지합니다.

**HWPX와 문자 PDF 중 원하는 출력으로 실행합니다.** 일반 OCR·이미지 탭 오른쪽 **실행** 카드의 **[▶ 한 번에 인식 (HWPX 만들기)]**(인주 채움 — 주)와 그 아래 **[▶ 한 번에 인식 (문자 PDF 만들기)]**(인주 테두리)는 둘 다 판독부터 해서 호출이 듭니다. 문자 PDF 쪽은 새 판독부터 검색·복사 가능한 PDF 만들기까지 이어서 합니다. 둘 아래 **[■ 중지]**는 두 작업에서 함께 사용하며, 누르면 지금 쪽이 끝날 때까지 '멈추는 중…'으로 바뀝니다. 실행 중에는 도는 실행의 단추만 잠긴 모양('… · 판독 중')이 되고 단추 자리는 바뀌지 않습니다. 결과는 실행 카드의 **[HWPX 열기]·[문자 PDF 열기]·[검수 화면]·[결과 폴더]**로 확인합니다 — 열기만 하므로 실행 중에도 눌리며, 그때는 실행이 끝날 때 다시 쓸 파일을 한글·PDF 뷰어가 쥐지 않게 지난 결과의 읽기용 사본(`%TEMP%\YeonE_OCR\보기`)을 엽니다. 왼쪽 **책 카드**는 도장·책 제목과 대상·판독 기록·새로 읽을 쪽 수, 원본 경로(가운데를 줄이고 풍선 도움말·오른쪽 클릭 '경로 복사'로 전체 경로), **결과 저장**(읽기 전용 — `out` 폴더의 전체 경로) 칸과 **[저장 폴더]**, 그리고 **이 책의 설정** 판(쪽 범위·읽기 방향·문서 짜임·양식·짜임 규칙·획 굵기, 인쇄 쪽수 보정은 값이 있을 때만 · 모든 책 공통 판독기·모델·자동 교정 · `book_settings.json` 저장 상태)을 보입니다. 실행 중에는 책 카드가 한 줄로 접히고('이 책의 설정 · 잠김 ▸'로 펼쳐 볼 수 있음) 쪽 범위 칸이 잠깁니다. 원본을 고르기 전에는 실행 단추·열기 단추가 꺼져 있습니다. 일반 OCR·책갈피 OCR에서 고른 원본은 이미지 입력을 바꿔도 유지됩니다.

캡처 원본은 `%LOCALAPPDATA%\YeonE_OCR\screenshots`에 **원래 해상도의 RGB PNG**로 보관합니다. 같은 픽셀의 캡처는 같은 PNG를 재사용합니다. 여러 장을 붙이면 기존 원본과 결과를 보존하면서 `이미지모음-<지문>.pdf`를 만들고, 그 묶음에 별도 결과 폴더를 사용합니다. 앱을 다시 열어도 선택한 묶음을 이어 쓸 수 있습니다. 저장된 PNG를 나중에 수정했다면 그 파일을 보존하고 새 파일을 만듭니다. 붙여넣기가 성공하면 쪽 범위와 인쇄 쪽수 차이는 비우고 "기록 있는 쪽도 다시 판독"은 꺼서 전체 묶음을 읽을 수 있게 합니다. 파일을 묶지 못하면 이전 선택과 설정을 유지합니다.

**업데이트:** 작업을 마치고 프로그램을 닫은 뒤 [0.9.0 릴리스](https://github.com/kyengilam-coder/YeonE_OCR_release/releases/tag/v0.9.0)의 설치 파일을 같은 위치에 설치하십시오. 사용자 설정과 API 키는 기존 `사용자 폴더\.yeone_ocr\config.json`을 사용하며, 원본 옆의 판독 기록·결과 폴더와 저장한 스크린샷도 그대로 이어 씁니다. 0.7.0의 단일 실행 파일을 사용하던 경우에도 같은 Windows 계정으로 설치판을 열면 기존 설정을 사용합니다. 예전 바로가기가 남아 있으면 시작 메뉴의 새 **연어OCR**을 열고 창의 **0.9.0** 표시를 확인하십시오.

설치 없이 쓰는 **`YeonE_OCR-Windows-x64.exe`**도 같은 릴리스의 배포 대상입니다. 기존 단일 실행 파일의 자동 업데이트에 쓰는 이름과 `update.json` 형식을 유지합니다. 설치판 업데이트는 설치 파일을 이용하십시오. 배포 파일에는 현재 코드 서명이 없으며, 릴리스의 `SHA256SUMS.txt`와 파일의 SHA-256을 비교할 수 있습니다. 빌드·검증·배포 자료는 [Windows 배포 안내](docs/windows-release.md)에 정리했습니다.

### 소스로 실행하기

1. **Python 설치** — [Python 다운로드](https://www.python.org/downloads/)에서 받아 설치합니다. 설치 첫 화면의 "Add python.exe to PATH" 를 체크하십시오. (3.10 이상)
2. **코드 받기** — [공개 배포 저장소](https://github.com/kyengilam-coder/YeonE_OCR_release)에서 "Code → Download ZIP" 으로 받아 `C:\Projects\YeonE_OCR` 에 풉니다. git 이 있으면 `git clone https://github.com/kyengilam-coder/YeonE_OCR_release.git C:\Projects\YeonE_OCR` 로 받고, 새 판은 그 폴더에서 `git pull` 로 받습니다. 창 머리 오른쪽의 `v0.x.y` 와 진행 기록 첫 줄의 "프로그램 위치"로 어느 판이 떠 있는지 확인할 수 있습니다.
3. **`YeonE_OCR.pyw` 더블클릭** — 창이 뜹니다. 뜨지 않으면 `YeonE_OCR.bat` 을 더블클릭하십시오(오류 글이 보입니다).
4. **[패키지 설치·점검]**(작업 탭 기록 카드의 [고급 도구 ▸] 안) — 처음 한 번. 빠진 패키지가 있으면 켤 때 설치할지 먼저 묻습니다. 아래 "진행 기록"에 설치 과정이 흐르고(진행 막대: 확인 → 내려받기 → 설치), 끝나면 화면 맨 위 오른쪽에 "패키지 모두 있음"이 뜹니다.
5. **제공사·API 키** — 네 번째 **[설정]** 탭에서 Gemini / ChatGPT(OpenAI) / Claude(Anthropic)를 고르고 해당 제공사의 API 키를 넣은 뒤 **[키 확인·모델 고르기]**를 누릅니다. 키 발급은 [Google AI Studio](https://aistudio.google.com/apikey), [OpenAI](https://platform.openai.com/api-keys), [Anthropic](https://platform.claude.com/settings/keys)에서 합니다. **[설정 저장]**으로 키·모델 설정을 제공사별로 내 PC의 `사용자 폴더\.yeone_ocr\config.json`에 저장하고 **[OCR로 돌아가기]**를 누릅니다. 제공사를 바꿨다가 돌아와도 다시 입력할 필요가 없습니다.
   ChatGPT·Claude 웹 서비스 구독 계정으로 로그인하는 방식이 아닙니다. 각 제공사의 API 키와 API 사용 권한·결제 설정이 필요합니다.
6. PDF는 **[일반 OCR]**의 **[PDF 고르기…]**, 이미지·캡처는 세 번째 **[이미지(스크린샷) OCR]**의 **[이미지 고르기…]** 또는 원본 미리보기 상자에서 `Ctrl+V` → 원하는 출력의 **[한 번에 인식]**으로 시작합니다. 작업 탭의 쪽 범위를 비워 두면 전체, `1-5`처럼 적으면 그 쪽만 합니다. 탭별 원본 선택은 독립적이며 API·모델·문서 설정은 공유합니다.
   스캔 **이미지**(PNG·JPG·TIFF·BMP·WEBP 등)도 됩니다. 한 장이면 그대로, 여러 장을 함께 고르면 이름의 숫자 순서(p2 가 p10 앞)로 한 권으로 묶은 PDF(`<첫 이름>~<끝 이름> (N장 xxxxxxxx).pdf`, 무손실 — 끝의 여덟 자는 고른 이미지들의 이름·크기·내용으로 만든 지문이라, 고른 장이나 그림이 바뀌면 새로 묶고 결과 폴더도 따로 씁니다. 폴더를 옮기거나 복사해도 지문은 같아 판독 기록을 이어 씁니다)를 이미지 옆에 만들어 읽습니다. 묶기는 창이 멈추지 않게 뒤에서 합니다. 휴대전화 사진의 회전 정보(EXIF)를 따라 바로 세우되 JPEG 는 원래 바이트 그대로 쪽 위에서 돌려(무손실·크기 그대로) 넣고, 16비트(12비트 자료 포함) 회색조 PNG·TIFF 도 읽습니다. 여러 쪽 TIFF 는 쪽마다 한 쪽입니다. 명령줄에서는 이미지 폴더를 통째로 줄 수도 있습니다(`yeone-ocr run D:\스캔\권1`). 이미지 탭은 기본 "자동 판정"으로 실제 글줄의 가로·세로 방향을 확인합니다.
   읽기 방향의 자동 판정 결과는 결과 폴더에 기록합니다. PDF의 "인쇄 쪽수 = PDF 쪽수 + N"(빈 칸)은 글자층으로 판정합니다. 판정 결과를 직접 바꾸려면 [설정] → 이 책의 읽기 방향을 선택하거나 **[설정] → 이 책 → [고급 ▸]의 인쇄 쪽수 보정**을 적으십시오.
   쪽이 많으면 오래 걸립니다(쪽당 30초~1분). **[■ 중지]** 로 멈춰도 끝난 쪽은 남고, 다시 누르면 남은 쪽부터 이어서 합니다. 제공사·모델을 바꾸고 같은 PDF·이미지와 결과 폴더로 실행해도 이어 읽습니다. 이미 판독한 쪽을 새 모델로 처음부터 읽으려는 경우에만 "기록 있는 쪽도 다시 판독"을 켭니다.
7. 끝나면 실행 카드의 **[HWPX 열기]** 또는 **[문자 PDF 열기]**(방금 끝난 실행의 단추가 굵은 테두리로 강조됨)로 결과를 보고, **[검수 화면]**에서 원본과 대조합니다(검수 화면을 새로 만들려면 기록 카드의 [고급 도구 ▸]에서 **[⑤ 검수 화면]**). HWPX 작업은 끝날 때 검수 화면을 열지 묻고, 문자 PDF 작업은 완성된 PDF를 엽니다. 〔 〕로 남은 자리는 검수 화면에서 확인하십시오.
   단계별 단추(①~⑥)와 도구는 작업 탭 기록 카드의 **[고급 도구 ▸]**(진행 카드와 기록 카드 사이에 펼쳐짐), 2차 판독 모델·속도 같은 옵션은 [설정] 탭 판독 섹션의 **[세부 설정 ▾]**에서 찾습니다. 단추에 마우스를 올리면 하는 일이 나옵니다.

결과는 PDF 와 같은 폴더의 `<PDF 이름>_YeonE_OCR\`(이미지는 `<이름>_<확장자>_YeonE_OCR\`, 이미지 폴더는 `<폴더>_이미지_YeonE_OCR\`) 안에 생기고, 전체를 넣은 HWPX 는 `out\<PDF 이름>.hwpx`, 일부만 넣은 것은 `out\<PDF 이름>_p001-005.hwpx` 입니다.
붙여넣은 스크린샷도 저장한 PNG 옆에 결과 폴더가 생깁니다. 기본 HWPX 경로는 `%LOCALAPPDATA%\YeonE_OCR\screenshots\screenshot-<hash>_png_YeonE_OCR\out\screenshot-<hash>.hwpx`이며, 문자 PDF는 같은 폴더의 `screenshot-<hash>_글자층.pdf`입니다. `<hash>` 부분은 캡처마다 달라집니다. 0.7.2에서 쓰던 저장 위치와 기록을 유지합니다. 책 카드의 **결과 저장** 칸에 폴더의 전체 경로를 표시하므로 **[저장 폴더]**와 실행 카드의 **[HWPX 열기]·[문자 PDF 열기]**로 바로 확인할 수 있습니다.

## 단추가 하는 일

| 단추 | 하는 일 |
|---|---|
| PDF 고르기… / 이미지 고르기… | [일반 OCR]은 PDF를, 세 번째 [이미지(스크린샷) OCR]은 PNG·JPG 등 저장된 이미지를 고릅니다. 다른 작업 탭의 원본 선택은 유지합니다. |
| 설정 바꾸기 | 현재 판독기·모델·읽기 방향 요약 옆에서 네 번째 [설정] 탭으로 이동합니다. |
| 설정 저장 / OCR로 돌아가기 | [설정] 탭 바닥 줄에서 공통 설정(과 이 책의 책별 설정)을 저장하고 작업 탭으로 돌아갑니다. |
| 이미지 미리보기 · 붙여넣기 | 원본 상자 클릭 후 `Ctrl+V` 또는 오른쪽 메뉴 [이미지 붙여넣기]로 이미지를 기존 쪽 뒤에 추가합니다. [이전]·[다음]과 전체 쪽수로 묶음을 확인하며, 두 번 클릭하면 원본을 엽니다. `Ctrl+Shift+V`도 유지하며, 붙여넣기만으로 모델을 호출하지 않습니다. |
| 입력 비우기 | 이미지 탭의 선택 원본·쪽 범위·인쇄 쪽수 보정·강제 재판독·저장 위치와 진행 표시를 초기화하고 새 입력을 기다립니다. 디스크의 원본·판독 기록·완성 HWPX와 진행 기록 이력, 다른 탭의 원본, API·모델·문서 설정은 보존합니다. |
| 원본 보기 / 원본 크게 보기 | 일반 OCR은 [원본 보기], 이미지 탭은 미리보기 두 번 클릭 또는 오른쪽 메뉴 [원본 크게 보기]로 현재 원본을 엽니다. |

[▶ 한 번에 인식]은 3차 판별 뒤에 문서를 만들므로, 앞서 답을 얻은 문맥 후보라도 앞뒤 글의 `〔a/b〕` 를 3차가 정하면 다시 묻습니다 — 그런 후보 수를 문맥 교정 줄의 위쪽 범위로 두고 근거에 '3차가 바꿀 〔a/b〕 곁 n건은 다시 물을 수 있음'이라 적습니다. 다른 판에서 만든 기록 가운데 영역 좌표가 밀려 실행할 때 `readings/stale/` 로 옮겨 다시 판독할 쪽은 판독 줄과 새로 읽을 쪽 어림에 넣고(진행 기록의 '이전 기록 n쪽은 … 다시 판독합니다' 와 같은 규칙), 나머지 이전 판 기록은 실행 때 다시 비교되어 '정확' 수가 조금 달라질 수 있다고 [근거·가정]에 적습니다. 어림은 작업 스레드에서 하므로(462쪽이면 몇 초 — 작은 진행 창, [취소] 가능) 창이 멈추지 않습니다. **어림하지 못한 단계가 있으면** 물을 것이 0 이어도 창을 띄워 까닭을 빨간 줄로 보이고, 기본 단추(Enter)를 [아니요 · 모델 단계 없이](판독 어림이 실패했으면 [취소])로 둡니다. |
| 비교 다시 계산 | 저장된 1차·2차 판독으로 확인 표시만 다시 만듭니다(모델 호출 없음). [▶ 한 번에 인식] 이 이전 판 기록을 만나면 저절로 하므로 보통은 누를 일이 없습니다. `merged` 를 손으로 고친 내용은 사라집니다. |
| 패키지 설치·점검 ([고급 도구 ▸]) | 소스로 실행할 때 `pip install -r requirements.txt`를 대신 실행합니다. |
| 키 확인·모델 고르기 | 키가 쓸 수 있는지 확인하고, 쓸 수 있는 모델 이름 목록에서 고릅니다. 키·권한·모델 이름 오류는 알기 쉬운 한 줄로 알려 줍니다. |

"쪽별 상태" 탭에서 쪽마다 상태·확인 필요 건수·도판 수를 봅니다.

## 책갈피 OCR (두 번째 탭) — HWPX 교정

이미 입력된 HWPX 가 있고 같은 책의 PDF 가 있을 때, PDF 원본을 판독해 HWPX 글자와 맞춰 보고 고친 사본을 만듭니다.
창 위의 두 번째 탭 **[책갈피 OCR]**에서 합니다. 책갈피가 든 원본 PDF와 교정할 HWPX를 이 탭에서 고르고, 판독기·모델·API 키·속도·읽기 방향은 네 번째 **[설정]**의 공통 값을 씁니다(읽기 방향은 자동 판정). **[설정 바꾸기]**로 이동하여 책갈피 교정 정책·메모·재판독 옵션을 바꾼 뒤 **[OCR로 돌아가기]**를 누릅니다.

**기본 동작은 [▶ HWPX 전체 교정] 입니다.** [PDF 고르기…] → [HWPX 고르기…] → [▶ HWPX 전체 교정] 을 누르면 구획을 차례로 전부 대조해 사본 `<이름>_교정.hwpx` 하나에 고쳐 넣고
`collate/_전체_요약.html` 에 구획별 자동 교정·표시 건수와 건너뛴 구획(PDF 쪽을 못 찾음)을 적습니다. 기록이 없는 쪽은 모델로 읽고(있으면 안 부름), 入/人·曰/日 같은 자형 편향 자리는 그 글자 조각을 모델에 다시 물어 인쇄가 HWPX 글자면 차이에서 빼고 판독 글자면 교정 후보로 올립니다(못 가리면 표시만).
구획 전체 대조에서는 급과 무관하게 바로 다음 기준 직전까지를 한 구획으로 보아 겹침·빠짐이 없습니다. 아래는 구획 하나만 할 때의 설명입니다.

1. **[PDF 고르기…]**, **[HWPX 고르기…]** → "책갈피로 쓸 스타일" 확인 → **[구획 색인]**. HWPX 에 한컴 책갈피가 없어도 됩니다. HWPX 를 고르면 이름에 '제목'이 든 스타일(예: 제목-장, 제목-본초명, 제목-본초명(소))을 자동으로 채워 주고, **[스타일 고르기…]** 에서 문단 수를 보며 바꿀 수 있습니다(앞에 적은 스타일이 큰 단위). 제목 스타일조차 없는 문서는 기준을 'PDF 책갈피 이름으로 HWPX 본문 검색'으로 바꾸면 PDF 책갈피 이름을 본문에서 찾아 구획으로 삼습니다.
   "찾기" 칸에는 한자뿐 아니라 **한글 독음**(대계 → 大薊, 인삼 → 人參·人蔘, 삼릉/삼능 → 三棱)을 넣어도 됩니다. 표의 독음 열은 참고용 자동 변환입니다. HWPX 의 책갈피(한컴 책갈피)와 제목 스타일 문단(이름에 "제목"이 든 스타일, 예: 제목-장·제목-절·제목-본초명)을 구획 기준으로 뽑고,
   PDF 책갈피와 이름을 맞춥니다(부호·공백·이체자·간체/번체 차이를 접고 비교). 표에 번호·급·HWPX 제목·문단·PDF 책갈피·쪽·짝 상태가 나옵니다. "찾기" 칸으로 거릅니다.
2. 구획을 고르고 **[이 구획 대조만]** 또는 **[이 구획 교정]**. PDF 책갈피 짝이 없는 구획은 PDF 글자층에서 제목을 찾고, 그래도 없으면 PDF 쪽 범위를 물어봅니다.
   그 쪽들을 판독하고(기록이 있으면 모델을 부르지 않음), 구획 제목부터 다음 구획 제목 직전까지만 잘라 HWPX 구획 글과 글자 단위로 맞춥니다.
3. 차이는 네 갈래로 나뉩니다. 비교는 간체 공간에서 하므로 번체 HWPX 와 간체 PDF 사이의 변환 차이는 차이로 세지 않습니다.

| 갈래 | 뜻 | 정책 "확실한 것만"(기본) | 정책 "전부 자동" | 문서 표시 |
|---|---|---|---|---|
| A | 판독이 확실(〔〕 없음)하고 간→번이 1:1 인데 HWPX 와 다름 | 글자 교체·삽입·삭제 | 같음 | 파랑 + 파선 밑줄(3차 자형 판별 근거면 초록 + 점선 밑줄). 지운 글자에만 메모 |
| B2 | 간체 한 글자가 여러 번체(发→發/髮, 术→術/朮)로 갈라짐 | 표시만 | 어구 사전으로 고른 번체로 교체, 다른 후보는 보고에 | 파란 글자 + 연파랑 음영 + 파선 밑줄 |
| C 누락 | HWPX 에 없는 긴 구간(20자 이상)이 PDF 에 있음 | 넣지 않고 삽입 제안만 | 같음(0.6.8 부터 어느 정책에서도 자동으로 넣지 않음) | 빨강 + 삽입 제안 메모(범위·중복 확인) |
| B1 | 그 자리의 판독이 불확실(〔疑〕·〔a/b〕), 또는 자형이 헷갈리기 쉬운 쌍(問/間·卯/卵·王/玉·宜/宣 …)·자형 편향 쌍(入/人·曰/日 …)의 한 글자 차이 | 글자 그대로 둠. 혼동·편향 쌍은 3차 자형 판별이 인쇄 = 판독 글자로 가리면 교정 후보로(번체가 하나면 A — 이 정책에서 고침, 于·干 처럼 번체가 여럿이면 B2 — "전부 자동"에서만 고침). 1차만 읽은 영역의 차이는 늘 표시만 | 같음 | 빨간 굵은 글자 + 노란 형광펜(폭 없는 자리·한글 풀이 자리만 메모) |
| C 그 밖 | PDF 에 없는 긴 구간, 여러 글자 차이 | 그대로 둠 | 같음 | 빨간 굵은 글자 + 노란 형광펜 + 고지 메모 |
| D | 부호·띄어쓰기·이체자(參/蔘)만 다름 | 무시 | 같음 | 없음 |

   기본 정책은 0.6.8 부터 "확실한 것만"(A 만 고치고 B2 는 표시만)입니다. "전부 자동"으로 바꾸면 B2 도 사전으로 고른 번체로 고칩니다. "메모만"은 아무 글자도 바꾸지 않습니다(반영하지 않은 제안은 고지 메모로). [메모] 를 "모든 표시에 근거"로 두면 0.6.3 처럼 항목마다 근거 메모를, "메모 없이 글 속 〔 〕"이면 고지만 글 뒤에 〔삭제: ○〕 처럼 짧게 적습니다. 원래 글자·근거 전체는 늘 보고(html·json)에 있습니다.
4. 결과는 원본 옆에 `<이름>_교정.hwpx` 로 저장됩니다(원본은 그대로). 여러 구획을 이어서 교정하면 같은 사본에 쌓입니다.
   대조 보고 `<작업 폴더>/collate/<구획>.html` 에 갈래별 표와 HWPX·판독 원문 대조가 있습니다. **[보고 열기]**, **[교정본 열기]** 단추로 엽니다.

于·干·於·幹·乾 묶음은 판독기가 자주 섞으므로 따로 다룹니다. 지시문에서 자형·문맥을 다시 확인하게 하고, 대조에서는 HWPX 앞뒤 글자의 문맥 규칙(生於·從於 ↔ 能幹·乾薑)과 PDF 글자층(다른 OCR 엔진의 글자)을 증인으로 삼아 어느 쪽이 맞는지 가립니다. 못 가리면 표시만 합니다. 글자층 증인은 다른 한 글자 차이에도 적용되어, 글자층이 HWPX 와 같으면 판독 오류로 보고 차이에서 뺍니다.

한계: 1:多 묶음 안에서 HWPX 가 다른 번체를 쓴 경우(乾薑↔幹薑)는 간체로 접으면 같아져 비교로 잡히지 않습니다. 교정본은 한컴에서 열어 메모와 색 표시를 확인하며 받아들이십시오.
명령줄: `yeone-ocr collate <pdf> --hwpx <hwpx> --all --apply`(전체 교정), `--list`(구획 목록), `--section "大薊" --apply`(구획 하나). `--no-glyph-check` 면 자형 3차 판별을 하지 않습니다.

## 검색 가능한 PDF — 원본 PDF 에 글자층 넣기

판독한 글을 원본 스캔 PDF 의 각 쪽 위에 **보이지 않는 글자층**으로 넣은 사본을 만듭니다. 화면은 원본 그대로이고, PDF 뷰어(Acrobat·PDF-XChange·브라우저)에서 찾기(`Ctrl+F`)·복사·끌어 고르기가 됩니다. 원본 PDF 는 고치지 않습니다.

- **새로 판독하며 만들기**: 일반 OCR·이미지 탭의 **[한 번에 인식 (문자 PDF 만들기)]**를 누릅니다. HWPX 작업과 같은 판독·3차 판별을 거쳐 `out\<이름>_글자층.pdf`를 만들며, 완료한 판독 기록은 재사용합니다. HWPX·DOCX와 HWPX 중간 저장본은 만들지 않고 양식·짜임·문서 자동 교정도 적용하지 않습니다. 새 판독과 필요한 3차 판별에는 API 비용이 들며 실행 전 비용 창으로 확인합니다.
- **기록으로만 다시 만들기**: [고급 도구 ▸]의 **[PDF 글자층 넣기]**는 이미 판독한 기록으로만 만듭니다(모델 호출 없음). 문서 옵션 **"검색 가능한 PDF 도 만들기"**를 켜면 HWPX 작업 끝에 함께 만들 수도 있습니다.
- **쪽 범위와 중지**: 선택한 범위의 판독 기록이 있는 쪽에 글자층을 넣으며 PDF의 전체 쪽 순서·화면은 유지합니다. 두 실행 단추 아래 **[■ 중지]**로 OCR과 PDF 만들기를 중지할 수 있습니다. 완료한 판독은 남고, PDF 저장·검증이 끝나기 전에 중지하면 이전 완성 PDF를 보존합니다. 다시 실행하면 판독 기록을 이어 쓰고 PDF를 다시 조립합니다.
- **넣는 글**: 판독 기록(`readings\pNNN.json` 의 `merged`, 3차 판별·손 고침 포함)을 **인쇄된 그대로** 넣습니다. 간체 책이면 간체로 찾습니다(HWPX 의 번체 교정은 넣지 않음). `〔a/b〕` 는 1차 글자, `〔疑: X〕` 는 X 로 넣고 `〔판독불명〕` 자리는 글 없이 비워 둡니다. 쪽번호·머리말도 쪽에 보이는 글이므로 넣습니다.
- **글자 자리**: 판독 기록에는 영역 상자만 있으므로 판독에 쓴 쪽 이미지에서 줄마다 잽니다. ① 먹 띠(줄·열)와 먹 구간(글자)을 실측해 글자 수와 꼭 맞으면 그 자리(획이 떨어진 三·二 같은 글자는 묶음) → ② 원본에 다른 OCR 글자층이 있으면 그 글자 상자를 빌림(글은 판독대로, 번체로 읽은 층도 맞춤) → ③ 먹 범위를 글자 수로 나눔 → ④ 영역 상자를 균등 분할. 모델 좌표가 조금 밀려도 줄을 찾습니다. 세로쓰기 열은 위→아래로 가는 줄로 넣습니다.
- **원래 있던 글자층**: 판독 기록이 있는 쪽에서는 다른 OCR 의 숨은 글자층을 지우고 넣습니다(검색이 두 번 걸리지 않게, 그림·선·링크는 그대로 — 링크는 지운 뒤 같은 자리에 다시 넣음). 남기려면 명령줄에 `--keep-old-layer`. 이 프로그램이 전에 넣은 글자층은 `--keep-old-layer` 여도 그것만 가려내 지우고 새로 넣습니다(두 번 들어가지 않게). 판독 기록이 없는 쪽과 보이는 글자가 있는 쪽(스캔이 아닌 쪽)은 손대지 않으며, 넣은 쪽이 하나도 없으면 PDF 를 만들지 않습니다. 전각 간격으로 찍힌 반각 숫자·부호(`卷第12`)는 글자마다 자리를 맞춰 넣어 한 낱말로 검색됩니다. 글자층 글꼴은 글리프 없는 작은 TrueType 을 내장합니다(내장하지 않으면 Acrobat 이 열 때마다 글꼴을 찾을 수 없다고 알림). 원본 PDF 의 쪽 내용이 간접 배열로 묶여 있어도 그대로 보입니다(검토에서 백지가 되던 경우를 고침).
- **희귀 한자**: 글리프 없는 글꼴과 유니코드 대응표(ToUnicode)로 넣어 확장 A·B 한자(㐀·䗪·𠮷)·호환 한자·한글이 그대로 검색·복사됩니다.
- **다시 넣어도 안전**: 이 PDF 를 다시 연어OCR 에 넣으면 이 글자층은 자기 판독이므로 기존 OCR(증인)로 읽지 않습니다 — 판독을 판독과 대조하는 순환이 생기지 않습니다.
- **확인**: 임시 PDF를 저장한 뒤 다시 열어 넣은 글이 그대로 읽히는지 쪽마다 확인하고 최종 파일로 바꿉니다. 검증 결과는 진행 기록에 남깁니다.

한계: 도판·표 영역 안의 글자는 아직 넣지 않습니다. PDF/A 적합성은 검증하지 않습니다. 협주(쌍행 소주)처럼 판독의 줄 수와 먹 띠 수가 다르면 균등 분할로 넣어 자리가 덜 맞을 수 있습니다.

명령줄: 새 판독부터 문자 PDF만 만들려면 `yeone-ocr run 책.pdf --pdf-only --pages 1-20`, 저장된 기록으로만 만들려면 `yeone-ocr textlayer 책.pdf [--pages 1-20] [--out 경로.pdf] [--keep-old-layer]`, HWPX와 함께 만들려면 `yeone-ocr run 책.pdf --textlayer-pdf`를 사용합니다. `run --pdf-only`는 이미지 파일·이미지 폴더도 받습니다. 작업 폴더를 직접 지정했다면 각 명령에 같은 `--work 경로`를 줍니다.

## 내용별 문서 — 원본 쪽 대신 제목·문단으로 짠 HWPX

기본 문서(**원본 쪽대로**)는 원본 PDF 한 쪽을 HWPX 한 쪽에 담고 쪽마다 메모로 원본 쪽수를 적어 검수하기 좋습니다. **내용별**로 만들면 쪽 경계를 지우고 글을 장·절 제목, 약재명, 본문·주석 문단으로 이어 짠 아래한글 문서가 됩니다.

**짜임 규칙**은 판독한 제목·본문·소주 등을 어떤 문단 역할로 분류하고 어느 스타일에 연결할지 정합니다. **한글 스타일**은 연결된 문단의 글꼴·크기·정렬 등 모양을 정합니다. 새 설정의 **기본 규칙**(`basic`)은 원본에서 판독한 구조를 다음 스타일에 연결하며, 양식 HWPX가 없어도 여덟 문단 스타일을 만듭니다.

| 원본에서 판독한 쓰임 | 기본 문단 스타일 |
|---|---|
| 제목 1단계 / 2단계 / 3단계 | 대제목 / 중제목 / 소제목 |
| 본문 | 문단-1 |
| 주석·해설 | 문단-2 |
| 소주 | 문단-3 |
| 그림·표 제목 | 문단-4 |
| 작업 메모 | 문단-5 |

`문단-1`~`문단-5`는 쓰임별 이름이며 제목 단계나 자동 문단 번호가 아닙니다. 원문에 없는 제목·주석을 만들지 않습니다. 양식이 있으면 그 안의 대응 스타일을 우선 사용하고, 기존에 선택한 `regions`·`kaibao`·사용자 규칙은 그대로 유지합니다.

- **켜는 법**: [설정] → 이 책 → **문서 짜임: 내용별(제목·문단)**. 명령줄은 `yeone-ocr build 책.pdf --layout flow`.
- **원본 쪽 정보**: 각 원본 쪽의 첫 글자 자리에 **책갈피**(`PDF 6쪽 · 인쇄 394쪽`)를 넣습니다. 아래한글 [입력 → 책갈피](`Ctrl+K,B`)에서 쪽 번호로 바로 갑니다. 본문에는 쪽 표시가 보이지 않습니다. 쪽에 걸쳐 나뉜 문단은 한 문단으로 잇습니다.
- **양식**: **양식 HWPX**를 고르면(명령줄 `--template 양식.hwpx`) 그 파일의 스타일·쪽 설정·글꼴을 그대로 쓰고 본문만 새로 채웁니다(양식의 본문 글과 그림은 지움). 판독에서 가른 짜임은 **짜임 규칙 파일의 `styles`** 에 적힌 양식 스타일 이름에 맞춥니다. 앞 이름이 없으면 다음 이름을 쓰고, 다 없으면 바탕글로 둡니다. 아래는 **kaibao 규칙 파일의 styles**(본초학 양식의 이름)입니다 — `regions`는 이 가운데 장·절·소제목·본문·소주·그림 제목 줄을 같은 이름으로 씁니다.

  | 쓰임(`styles.paragraph` 열쇠) | 문단 스타일(앞에서부터 찾음) |
  |---|---|
  | 장 제목 `chapter` | 제목-장, 편명 |
  | 절 제목 `section` | 제목-절 |
  | 소제목 `subsection` | 제목-본초명(소), 제목-절 |
  | 약재명 `entry` | 제목-본초명+생약명, 약재제목, 제목-본초명 |
  | 본경(굵은 글씨) `bonjing` | 본경 원문, 본문 |
  | 별록 `bielu` | 별록원문, 본문 |
  | 주석 `［唐本注云］`·`［臣禹錫等謹按］` `commentary` | 주석, 본문 |
  | 본문·소주 `body`·`small` | 본문 |
  | 그림·표 제목 `caption` | 그림캡션, 캡션 |

  문단 안 범위(`styles.character`)에는 글자 스타일 **출처**(`source` — 문단 끝 `唐附`·`今附`·`宋附` 같은 출전 표시), **본경 조문**(`bonjing` — 한 문단 안의 굵은 글씨), **소주**(`small`)를 씁니다. 양식의 본문 문단이 어절 단위 줄 나눔이면 한문 문단에서 띄어쓰기 없는 긴 줄이 벌어지므로, 한자가 많은 문단에는 같은 모양에 글자 단위 줄 나눔만 바꾼 사본을 씁니다(라틴 쪽도 — 판독이 쉼표·마침표를 반각 `,` `.`로 적으면 `就州者大,徑二四寸.` 가 라틴 단어 하나로 묶여 앞 줄이 벌어지므로). 양식 없이 내용별로 만들면 기본 모양(개요 번호 없는 제목)으로 만듭니다.
- **짜임 가르기**([설정] → 이 책 → **짜임 규칙**, 명령줄 `--preset basic|regions|kaibao|규칙.json`, 새 설정의 기본 `basic`): 책마다 다른 규칙(약재명·주석·출처·굵은 글씨·스타일 이름)은 코드가 아니라 **짜임 규칙**(preset) 파일에 있습니다.
  - **기본 규칙**(`basic`): 위의 대제목·중제목·소제목·문단-1~5에 연결합니다. 책별 약재명·출처·굵기 해석은 하지 않습니다.
  - **영역 종류만**(`regions`): 판독의 영역 종류(제목 1·2·3단계·본문·소주·그림·표 제목)만으로 짜고 이전 스타일 이름을 사용합니다.
  - **本草 조문**(`kaibao`, 開寶本草·證類 계열): 영역 종류에 本草 조문 규칙을 더합니다. 문단 첫머리 `약재명 + 빈칸 + 味/一名/主/性/氣…` 는 약재명 제목으로 떼고, `［…云］`·`［…按］`·`［今詳］` 처럼 괄호로 여는 문단(표지 16자까지)은 주석, 문단 끝 `唐附`·`今附`·`新補`·`陳藏器餘` 등은 출처로 표시합니다. 판독에 빈칸이 빠졌어도 쪽 이미지에서 약재명 뒤 빈칸을 재어 뗍니다(양식 HWPX 를 쓸 때 획 굵기와 함께 잼 — 양식이 없거나 `--no-bold`·획 굵기 칸을 끄면 판독 글의 빈칸으로만 뗌). 수량사로 끝나는 이름(`桂枝三兩 …`, 처방의 약재 목록)·허사로 시작하는 이름(`凡藥 …`)·`云·經·按`으로 끝나는 토막은 약재명으로 보지 않습니다. 약재명 떼기는 그 꼴이 세 번 이상이고 문단의 1% 이상인 문서에서만 씁니다(본초서가 아닌 책에서 문단 첫 글자를 잘못 떼지 않게).
  - **파일에서 고르기…**: 다른 책에 맞춰 만든 규칙 JSON(아래 [짜임 규칙 파일 만들기](#짜임-규칙-파일-만들기-다른-책)). 창은 고를 때 파일을 검사해 쓸 수 없으면 까닭을 알리고 앞의 규칙을 그대로 두며, 실행 전에도 다시 확인합니다(명령줄은 끝 코드 2 — 모델을 부르기 전).
  - 예전 이름 `--structure auto|bencao|none` 도 그대로 받습니다: `auto` = kaibao, `bencao` = kaibao 에서 약재명을 늘 떼기(창에는 '本草 조문 · 약재명 늘 떼기(예전 설정 bencao)'), `none` = regions. `--preset` 과 함께 주면 오류입니다. **이전 판에서 내용별 문서를 쓰던 설정은 本草 조문(kaibao)으로 옮겨 같은 문서를 만듭니다**(문서 짜임이 내용별이었거나, 검수용으로 잠시 원본 쪽대로 두었어도 양식 HWPX 를 고른 적이 있으면. '本草 조문 규칙 늘'이었으면 그것 그대로, '규칙 없음'이었으면 영역 종류만). 내용별을 쓴 적이 없고 규칙도 저장하지 않은 설정은 기본값(기본 규칙)이 됩니다 — 이전 판이 설정을 '원본 쪽대로·양식 없음' 으로 덮어 둔 채 올렸다면 여기에 듭니다. 그래서 양식을 고를 때 그 양식에 本草 조문 스타일(`제목-본초명+생약명`·`본경 원문`·`별록원문` 등)이 있는데 짜임 규칙에 약재명 떼기가 없으면 **本草 조문으로 바꿀지 묻습니다**([아니요]면 그대로 두고 진행 기록에 한 줄). 원본 쪽대로 문서는 짜임 규칙을 쓰지도 검사하지도 않습니다.
- **머리말·약재명 제목**: 판독이 쪽마다 찍힌 머리말(書眉, `開寶本草序例下卷第二`)을 '제목'으로 읽으면 내용별 문서에서 글을 끊는 장 제목이 되므로, 쪽 맨 위(좌표로 가장 위 영역)이거나 권 이름(卷)이 든 제목이 바로 앞에서 남긴 쪽머리·권 제목과 비슷하면(잘못 읽은 변형 포함) 빼고 끊긴 문단을 다시 잇습니다. 권 번호·품급(上品·中品·下品·之上·之下)·부 이름(木部·草部)이 하나라도 다르면 새 장으로 남깁니다. 앞 쪽의 머리말 칸(판독이 적은 것)과 같은 제목도 뺍니다(이 쪽 머리말과 같은 첫 장 제목은 남김). 뺀 제목은 쪽 번호와 함께 진행 기록에 남습니다. 本草 조문 규칙(kaibao)에서는 약재명을 제목으로 읽은 블록은 다음 문단이 `味`·`一名`으로 시작하면 약재명으로 봅니다(앞에 되읽은 이름 `〔疑: 雄黄〕` 가 있으면 제목과 같은 이름이어야 — 간체·한 글자 차이는 같은 것으로). 제목에 `味…` 가 붙었으면(`孔公孽 味辛，溫，無毒。`) 떼어 다음 문단 앞에 잇고, 약재명 둘이 잇달아 제목으로 읽혔으면 둘 다 약재명입니다. `生`으로 여는 문단(序例의 병증 제목 뒤 약재 목록 `吐唾血　生地黃…`)과 `云·經·按`으로 끝나는 토막(`陶隱居云`, `本經`)은 약재명으로 보지 않습니다. 쪽 첫머리(책갈피 자리)에서 새 조문·주석이 시작되는데 판독이 앞 문단에 이은 것(`cont`)은 거기서 가릅니다. kaibao 는 약재명 꼴이 셋 이상이고 문단의 1% 이상일 때만 떼기를 켭니다(규칙 파일의 `entry.min_hits`·`min_ratio`). 획 굵기를 재지 않았거나(`--no-bold`·OpenCV 없음·양식 없음) 문서 어디에도 굵은 범위가 없으면(本經을 굵게 찍지 않은 책) 本經·別錄을 가르지 않고 조문을 본문으로 둡니다. 끝 글자(`…并治上/中/下`)·`第N` 만 다른 형제 장 제목은 머리말로 보지 않습니다.
- **本經·別錄**: 輯復本처럼 본경을 굵게 찍은 책은 쪽 이미지에서 글자마다 **획 굵기**(먹 넓이×2 ÷ 먹 둘레)를 재어 가릅니다. 책 전체 중앙값의 1.25배를 넘는 글자가 앞뒤 일곱 자의 중앙값으로도 이어지면 굵은 글씨로 보고, 문단 한자의 절반 넘게 굵으면 본경 문단, 그 밖은 별록 문단에 굵은 범위만 본경 조문 글자 스타일로 둡니다(네 자보다 짧은 흔들림은 무시). 끄려면 [설정]의 **굵은 글씨·보통 글씨를 획 굵기로 가르기 (本草: 本經·別錄)**를 끄거나 `--no-bold`. 판독한 쪽 이미지를 다시 쓰므로 모델을 부르지 않습니다. **짜임 규칙에 약재명 떼기(`entry`)가 있고 양식 HWPX 를 쓸 때만 잽니다** — 굵은 글씨 해석(`emphasis`)은 `entry` 가 있어야 쓰고, 해석이 없고 약재명 떼기만 있는 규칙도 판독이 빠뜨린 약재명 뒤 빈칸을 찾으려고 잽니다(진행 기록에 그렇다고 한 줄). 영역 종류만(regions)처럼 둘 다 없는 규칙이나 기본 모양(본경·별록 스타일이 없음)에서는 잰 결과가 쓰이지 않으므로 쪽 그림을 다 그려 재는 몇 분을 쓰지 않고, 진행 기록에 까닭을 한 줄 남깁니다(그때는 창의 체크 상자도 흐려집니다 — 양식 칸을 비우거나 채우면 바로 바뀜). 굵은/보통 글씨를 어느 쓰임으로 넣을지도 규칙 파일이 정합니다(kaibao: 본경·별록).
- **그대로인 것**: 확인 등급 색·〔 〕 표시·고지 메모·번체와 문맥 교정은 원본 쪽대로 문서와 같습니다. 판독 기록과 원본 쪽대로 문서는 그대로 두고, 같은 판독으로 언제든 다시 만들 수 있습니다.

한계: 내장 本草 조문 규칙(kaibao)은 證類 계열 本草(本經·別錄·開寶·嘉祐)의 조문 꼴(`약재명 味… 唐附`, `［陶隱居云］`)에 맞춘 것으로 개보본초 輯復本 네 쪽(394·395·396·413)의 판면과 판독 결과 전체(약재명 760여 개)에서 확인했습니다. 다른 갈래의 책(方劑書·醫經·本草綱目처럼 `【釋名】` 으로 여는 책, 한글 鄕名이 끼는 鄕藥本草)은 **영역 종류만**(기본)으로 두거나, 그 책의 꼴에 맞춘 규칙 파일을 만드십시오(아래). 양식의 스타일 이름 대응도 규칙 파일의 `styles` 에 있어, 다른 양식은 규칙 파일의 이름을 그 양식에 맞게 고치면 됩니다(양식에 없는 이름은 바탕글). 규칙 파일은 낱말·글자 목록으로 적는 꼴이라 「문단 첫머리 이름 + 빈칸 + 여는 낱말」·「괄호 + 표지 + 닫는 괄호」·「문단 끝 출처」 밖의 짜임(`【釋名】` 같은 항목 머리 등)은 아직 나타낼 수 없습니다. 모델에게 문단마다 짜임을 묻는 방식은 넣지 않았습니다. 표는 칸만 옮기고 양식의 표 모양은 쓰지 않습니다. 양식의 글꼴은 문서를 여는 PC 에 있어야 그 모양으로 보입니다.
명령줄: `yeone-ocr build 책.pdf --layout flow [--template 양식.hwpx] [--preset basic|regions|kaibao|규칙.json] [--no-bold]`(예전 `--structure auto|bencao|none` 도 받음).

### 짜임 규칙 파일 만들기 (다른 책)

내장 규칙은 `yeone_ocr/data/preset_basic.json`(기본 규칙), `yeone_ocr/data/preset_regions.json`(영역 종류만), `yeone_ocr/data/preset_kaibao.json`(本草 조문)입니다. 새 책은 kaibao 파일을 복사해 고치는 것이 빠릅니다 — [설정] → 이 책 → 짜임 규칙 → **本草 조문 규칙을 파일로 저장…** 이 그 사본을 고른 자리에 남깁니다(고르던 규칙은 그대로). Windows 설치판에서는 `%LOCALAPPDATA%\Programs\YeonE_OCR\_internal\yeone_ocr\data\preset_kaibao.json` 에도 있습니다(그 자리의 파일은 고치지 말고 복사해 쓰십시오 — 새 판을 설치하면 덮입니다). 실행 파일 하나(portable) 판은 파일이 실행 파일 안에만 있으므로 위 저장 항목을 쓰십시오. 파일은 UTF-8 JSON 이고(메모장의 BOM 도 됨 — ANSI·CP949 로 저장했으면 '다른 이름으로 저장 → 인코딩 UTF-8' 로 다시 저장하라고 알립니다), [설정] → 이 책 → 짜임 규칙 → **파일에서 고르기…** 로 고르거나 명령줄 `--preset D:/규칙/내책.json` 으로 줍니다(상대 경로는 지금 폴더 기준, 창은 절대 경로로 기억). 정규식은 쓰지 않습니다 — 낱말 목록·글자 모음·수를 적으면 프로그램이 정규식으로 짭니다(kaibao 는 0.7.x 의 코드 상수와 같은 정규식이 됨을 시험으로 확인).

| 칸 | 꼴(기본값) | 뜻 |
|---|---|---|
| `schema` | `1`(꼭) | 규칙 파일 판 |
| `id`·`label`·`description` | 글(파일 이름) | 이름·창과 진행 기록에 보일 이름·설명 |
| `entry` | `{…}` 또는 `null` | 약재명(조문 제목) 떼기 — null 이면 하지 않음. 있으면 양식 HWPX 를 쓸 때 쪽 이미지를 재어 판독이 빠뜨린 약재명 뒤 빈칸도 찾습니다(획 굵기와 함께 · `--no-bold` 면 재지 않음) |
| `entry.when` | `"auto"`·`"always"`(`auto`) | auto: 그런 문단(제목으로 읽힌 약재명 포함)이 `min_hits` 이상이고 문단의 `min_ratio` 이상인 문서에서만 |
| `entry.min_hits`·`entry.min_ratio` | 1 이상 정수(3)·0~1 수(0.01) | auto 의 문턱 |
| `entry.max_name` | 1~12 정수(6) | 이름 한자 수 상한 |
| `entry.openers` | 낱말 목록(꼭) | 「이름 + 빈칸」 뒤에 오는 조문 첫 낱말(`味`·`一名`·`主`…) |
| `entry.heading_openers` | 낱말 목록(openers) | 판독이 제목으로 읽은 이름 다음 문단이 이것으로 시작하면 약재명(kaibao 는 `味`·`一名` 만 — 序例 목록의 `生…` 을 떼지 않게) |
| `entry.name_end_not`·`entry.name_start_not` | 글자 모음(`""`) | 이 글자로 끝나는 / 시작하는 이름은 약재명이 아님(`云`·`按`·`兩`… / `凡`·`又`…) |
| `commentary` | `{…}` 또는 `null` | 주석 문단 — `open`·`close`(여는·닫는 괄호 글자들, 꼭), `max_label`(0~40 정수, 16: 괄호 안 표지 앞 글자 수 상한), `markers`(표지 끝 낱말 목록, 꼭: `云`·`按`…). `/`·`:` 가 든 괄호는 판독 표시라 주석이 아님 |
| `source` | `{…}` 또는 `null` | 문단 끝 출처 — `after`(바로 앞에 올 수 있는 글자, `。，、；：` — 빈칸·문단 첫머리도 됨), `tags`(출처 글 목록, 꼭) |
| `emphasis` | `{"bold": 쓰임, "plain": 쓰임}` 또는 `null` | 굵은 글씨·보통 글씨 조문의 쓰임(`body`·`bonjing`·`bielu`·`commentary`, 서로 달라야). `entry` 가 있어야 씁니다. 있으면 그 잰 획 굵기로 굵은/보통 글씨 조문을 가릅니다 |
| `styles.paragraph` | `{쓰임: [스타일 이름, …]}` | 쓰임 → 양식 문단 스타일(앞 이름이 양식에 없으면 다음) |
| `styles.character` | `{종류: [스타일 이름, …]}` | 문단 안 범위의 글자 스타일 — `small`(소주)·`source`(출처)·`emphasis.bold` 의 쓰임(섞인 문단의 굵은 범위) |

쓰임: `chapter` 장 제목 · `section` 절 제목 · `subsection` 소제목(판독의 제목 1·2·3단계) · `entry` 약재명 · `body` 본문 · `bonjing`/`bielu` 굵은/보통 글씨 조문(本草: 本經·別錄) · `commentary` 주석 · `small` 소주 · `caption` 그림·표 제목 · `note` 작업 표시(확인 목록·작업 기록). 모르는 칸은 오류입니다(오타가 조용히 무시되어 짜임이 바뀌지 않게). 규칙에 없는 쓰임·종류의 스타일 이름은 regions 의 것(장 `제목-장`·`편명`, 절 `제목-절`, 소제목 `제목-본초명(소)`·`제목-절`, 본문·소주 `본문`, 그림 제목 `그림캡션`·`캡션`, 작업 표시 `바탕글`, 소주 글자 `소주`)을 쓰고, 그것도 양식에 없으면 바탕글입니다.

예(經文 뒤에 `［王冰注］`·`（新校正云）` 로 여는 주석 문단이 오는 醫經 注本 — 약재명·출처·굵기 규칙 없음, 사용자 양식의 스타일 이름):

```json
{
  "schema": 1,
  "label": "醫經 注本",
  "description": "經文 + ［王冰注］·（新校正云） 주석 문단.",
  "entry": null,
  "commentary": {"open": "［（", "close": "］）", "markers": ["注", "云", "曰", "按"]},
  "source": null,
  "emphasis": null,
  "styles": {
    "paragraph": {"chapter": ["편명"], "section": ["장 제목"], "body": ["경문"], "commentary": ["주석"]},
    "character": {"small": ["협주"]}
  }
}
```

틀린 파일은 쓰지 않습니다: 창은 고를 때와 실행 전에 알림 창으로, 명령줄은 `오류: 짜임 규칙 파일 D:/규칙/내책.json: 모르는 칸 'entry.opener' — 쓸 수 있는 칸: when, min_hits, …` 처럼 파일·칸 이름(JSON 문법 오류면 줄과 글자 자리, 그리고 '쉼표(,)가 빠졌습니다'·'칸 이름은 큰따옴표 "…" 로 감싸야 합니다' 처럼 고칠 길)을 찍고 끝 코드 2 로 판독·문맥 교정 전에 멈춥니다. 규칙 파일을 옮기거나 지웠으면 내용별 문서를 만들기 전에 알리니 다시 고르십시오.

## 자동 교정 — 최종 HWPX·DOCX에 적용할 항목 선택

**[설정] → [자동 교정]**의 **[간체→번체]·[云/雲 문맥 판별]·[중문부호 수정 규칙]**을 각각 켜고 끕니다(기본 모두 켬). 선택한 교정만 최종 HWPX·DOCX에 적용하며 OCR 판독 기록, 중간 저장 HWPX, 문자 PDF의 글자층에는 적용하지 않습니다. 변경·보류 내역은 `out`의 교정 보고에 남깁니다.

**[번체·云/雲의 불확실한 후보에 모델 사용]**은 간체→번체 또는 云/雲 교정을 선택했을 때만 사용합니다(둘 다 끄면 이 줄이 흐려집니다 — 값은 그대로). 자동 교정 섹션에서 영수증·`[아니요]면 뺌` 표지가 붙는 줄은 이것 하나입니다(규칙 셋은 모델을 부르지 않음). 끄면 규칙으로 정할 수 있는 변환만 하고 불확실한 후보는 보류합니다. 부호만 수정할 때에는 문맥 교정 모델을 부르지 않습니다. 자동 교정 선택과 사용자 부호 규칙 경로는 공통 설정으로 저장합니다.

중문부호는 **[규칙 추가·수정…]**에서 찾을 부호·바꿀 부호를 추가하거나 선택한 행을 수정·삭제하고(표의 공백은 `␣`, 빈 바꿀 부호는 `(지움)`으로 보이며 저장 값은 그대로, 부호 칸의 Enter 는 아무것도 하지 않음), **[위로]·[아래로]**로 순서를 정합니다. **[파일로 저장하고 적용…]**을 누르면 JSON 파일로 저장해 선택합니다. **[파일에서 고르기…]**로 기존 파일을 불러오거나 **[기본 규칙]**으로 내장 목록을 다시 선택할 수 있습니다. 사용자 목록은 내장 부호 목록을 대체하며 위에서 아래 순서대로 적용합니다.

```json
{
  "rules": [
    {"find": "，", "replace": ", "},
    {"find": "。", "replace": ". "},
    {"find": "《", "replace": "〈"},
    {"find": "》", "replace": "〉"}
  ]
}
```

UTF-8 JSON의 배열 자체(`[ ... ]`)도 받습니다. `find`는 비어 있으면 안 되며 `replace`의 빈 문자열은 삭제입니다. 부호·기호·공백만 허용하고 공백도 그대로 보존합니다. 정규식·매크로·검색 플래그는 지원하지 않습니다.

명령줄 `run`·`build`도 항목별 선택을 지원합니다.

| 선택 | 옵션 |
|---|---|
| 간체→번체 및 한자 치환 후보 끄기 | `--no-traditional` |
| 云/雲 교정 끄기 | `--no-yun` |
| 중문부호 교정 끄기 | `--no-punctuation` |
| 사용자 부호 목록 선택 | `--punctuation-rules D:/규칙/중문부호.json` |
| 교정 모델 호출만 끄기 | `--no-context-model` |
| 세 교정 모두 끄기 | `--no-normalize` |

예: `yeone-ocr build 책.pdf --no-traditional --no-yun --punctuation-rules D:/규칙/중문부호.json`은 선택한 부호 목록만 적용합니다. `run --pdf-only`는 위 문서 자동 교정을 사용하지 않습니다.

## 책별 설정

책마다 다른 설정은 그 책의 결과 폴더(`<원본 이름>_YeonE_OCR/book_settings.json`)에 따로 남깁니다. 책을 바꾸거나 창을 다시 열거나 새 판으로 올려도 그 책의 양식·짜임 규칙이 그대로 돌아옵니다.

- **남기는 것**: 문서 짜임(원본 쪽대로·내용별)·양식 HWPX 경로·짜임 규칙·획 굵기 가르기·쪽 범위·인쇄 쪽수 보정·읽기 방향. '기록 있는 쪽도 다시 판독'은 남기지 않고, 다른 책을 고르면 끕니다(켜진 채 다른 책을 읽으면 기록 있는 쪽을 모두 다시 삽니다). 판독기·모델·API 키·색·메모·문단 잇기 같은 나머지는 모든 책이 함께 쓰는 전체 설정(`사용자 폴더\.yeone_ocr\config.json`)에 있습니다.
- **쓰는 때**: 결과 폴더가 이미 있으면 [설정 저장]·창 닫기·다른 책이나 다른 입력 탭으로 옮길 때(앞 책의 값)·실행 단추를 누를 때(비용 창이 뜨기 전 — 그래서 비용 창에서 [취소]해도 그때까지 고친 값은 남습니다) 그 책의 파일에 씁니다. 결과 폴더를 **새로 만드는 것은** 실행할 때뿐입니다(비용 창에서 [예]·[아니요]를 고른 뒤, 또는 물을 것이 없어 창 없이 시작할 때 — [취소]·[비용 미리 보기]로는 폴더가 생기지 않음). 이전 판에서 만든 결과 폴더에 아직 파일이 없으면 그 책을 처음 보고 다른 책으로 옮길 때 지금 값으로 파일이 생깁니다.
- **아직 실행하지 않은 책**(결과 폴더 없음): 그 책에서 고친 짜임·양식·짜임 규칙·획 굵기·쪽 범위는 창이 기억해 둡니다(전체 설정의 `book_pending`, 책 30권까지). 다른 책을 보고 돌아오거나 창을 다시 열어도 그 값이 돌아오고(진행 기록에 '아직 실행하지 않은 책: … 되살림'), 처음 실행할 때 결과 폴더의 파일로 옮긴 뒤 지웁니다. 보기만 하고 고치지 않은 책은 기억하지 않습니다(새 책 기본값을 그대로 이어 씀). 쓸 때는 파일을 새로 읽어 이 창이 바꾼 값만 얹어 원자적으로 바꿔 넣으므로, **두 창**이 같은 책을 열어 한 창은 양식을, 다른 창은 쪽 범위를 바꿔도 둘 다 남고, **두 책**을 연 두 창은 서로의 파일을 건드리지 않습니다. 바뀐 것이 없으면 다시 쓰지 않습니다. 읽기 전용·네트워크 폴더라 읽거나 쓰지 못하면 '주의:' 한 줄만 남기고 실행은 막지 않습니다.
- **읽는 때**: 원본을 고를 때·일반과 이미지 탭을 바꿀 때·창을 열 때 그 책의 파일을 읽어 칸에 넣고 진행 기록에 `책별 설정을 불러옴(…/book_settings.json): 짜임 … · 양식 … · 짜임 규칙 …` 을 남깁니다. 적힌 양식·규칙 파일이 그 사이 없어졌으면 다른 것으로 바꾸지 않고 실행 전에 알립니다(창의 설정 요약에도 '(읽지 못함)').
- **어느 책의 칸인지**: [설정] 탭의 **이 책 — <원본 이름>** 섹션(쪽 범위·읽기 방향·문서 짜임·양식·짜임 규칙·획 굵기·고급의 인쇄 쪽수)은 **마지막에 쓴 입력 탭(일반·이미지 OCR)의 책** 것입니다. 섹션 머리에 그 책 이름·도장과 '{일반|이미지} OCR 탭에서 고른 책'이, 바닥에 저장 상태(결과 폴더에 저장됨 · 바뀜 · 첫 실행 때 저장)와 그 파일이 보이고, [설정 저장] 뒤 바닥 알림 줄도 그 책의 파일(폴더가 없으면 '처음 실행할 때')을 말합니다 — 이미지 탭을 잠깐 쓴 뒤 설정 탭에서 양식을 바꾸면 그 캡처의 설정이 바뀌므로, 일반 OCR 책의 양식을 바꾸려면 일반 OCR 탭을 한 번 누른 뒤 고치십시오.
- **전체 설정과 두 창**: 책을 불러와 칸에 넣은 값은 이 창이 바꾼 것으로 보지 않습니다 — 책 하나를 띄워 두기만 한 창이 닫힐 때, 다른 창이 저장한 새 책 기본값(양식·짜임 규칙)을 그 책의 값으로 덮지 않습니다. 불러온 뒤 사용자가 고친 값만 전체 설정에도 남깁니다.
- **새 책**(설정 파일도 기억해 둔 값도 없음): 문서 설정(짜임·양식·짜임 규칙·획 굵기)과 읽기 방향은 지난 설정을 이어 쓰고, 앞 책의 쪽 범위·인쇄 쪽수 보정은 비우며 '다시 판독'은 끕니다. 진행 기록에 늘 한 줄 — `새 책: … 문서 설정은 지난 설정(짜임 내용별 · 양식 본초학.hwpx · 짜임 규칙 本草 조문 …)을 이어 씁니다` — 을 남기므로, 다른 갈래의 책이면 거기서 보고 [설정] → 이 책에서 고치십시오. 창을 열 때는 비우지 않습니다 — 이전 판에서 탭마다 기억하던 쪽 범위가 그대로 남습니다. 곧 전체 설정의 문서 설정은 **새 책의 기본값**(마지막에 쓴 값)입니다.
- **원본을 바꿔 넣으면**: 판독 기록·문서·state.json 은 `archives/input-<시각>/` 에 보관하지만 book_settings.json 은 그 자리에 둡니다(경고 줄에 '책별 설정(book_settings.json)은 그대로 둡니다'). 스캔을 다시 떠도 양식·짜임 규칙을 다시 고르지 않아도 됩니다.
- **파일**: UTF-8 JSON `{"schema_version": 1, "saved_by": "0.9.0", "updated": "2026-10-15 12:00:00", "layout": "flow", "template": "D:/양식/본초학.hwpx", "preset": "kaibao", "bold_split": true, "pages": "", "print_offset": "", "mode": "vertical"}`(`preset` 은 내장 이름·예전 이름 `bencao`·규칙 파일 경로, `mode` 는 `auto`·`vertical`·`horizontal_zh`). 꼴이 틀린 값은 읽을 때 빼고(창의 값을 씀) 모르는 열쇠는 그대로 둡니다. 쓰다 만 파일은 `book_settings.json.broken` 으로 옮기고 알립니다.
- **명령줄**은 이 파일을 읽지 않습니다 — 창이 늘 `--layout`·`--template`·`--preset`·`--pages`·`--mode` 를 넘기고, 명령줄에서는 직접 적습니다. 대신 문서를 만들 때마다 무엇으로 만들었는지 `state.json` 의 `last_build`(시각·짜임·양식·짜임 규칙·만든 HWPX 이름)에 남깁니다.

## 0.7.4 — 이미지 입력 비우기·가로와 세로 자동 판정

- 기존 네 탭 구성, 스크린샷 저장·재사용, 세 제공사 전환, 번체·MSR·云/雲 문맥 교정을 유지합니다.

- **이전 캡처 기록 유지**: 스크린샷 PNG와 HWPX의 기존 저장 위치를 사용하므로 같은 캡처의 판독 기록을 이어 쓸 수 있습니다. 붙여넣기에서 API를 호출하지 않으며 번체·MSR·云/雲 교정도 그대로 적용합니다.

## 0.7.1 — 제공사 전환·이어서 판독·번체와 문맥 교정

- **Gemini·ChatGPT·Claude 선택**: 1차·2차·3차와 책갈피 OCR에서 선택한 제공사를 사용합니다. 2차 모델 `auto`는 Gemini에서 같은 세대(없으면 더 새) flash를 고르고(그것도 없으면 1차 모델) OpenAI·Anthropic에서는 1차 모델을 그대로 사용합니다. Gemini 전용 생각 수준·해상도·지침 캐시 옵션은 다른 제공사에 보내지 않습니다.
- **중단 뒤 다른 제공사로 계속**: 같은 PDF와 결과 폴더에서 제공사·모델을 바꾸고 다시 실행합니다. 완료한 쪽, 저장한 1차 판독, 완료한 2차 영역을 재사용하고 남은 영역부터 처리합니다. 판독 기록에 각 단계의 제공사·모델 출처가 남습니다. 입력 확대·읽기 방식 등 1차 판독 조건을 바꾸거나 강제 재판독을 고르면 다시 읽습니다.
- **최종 HWPX·DOCX 자동 변환**: 간체를 번체로 바꾸고, `중문부호-한국부호 변환(2023년식) - 260929.msr`에서 추출한 부호 규칙을 적용합니다. 매크로를 실행하지 않고 저장소에 동봉한 치환 데이터만 읽습니다. 제목·본문·표를 처리하며 원래 OCR 기록과 의심 표시 `〔〕`는 보존합니다. 중간 저장용 `_진행중.hwpx`에는 이 최종 변환을 적용하지 않습니다.
- **한자 규칙은 문맥으로 판단**: MSR의 한자 치환은 후보로만 쓰고, 선택한 모델이 앞뒤 문맥을 확인해 유지 또는 교체를 고릅니다. 예를 들어 매크로에 `髒→臟`가 있어도 무조건 바꾸지 않습니다. `云/雲`도 인용·말하다와 자연의 구름 문맥을 구분하며, 확정하지 못하면 원문을 유지하고 확인 목록에 남깁니다. `O/o`나 `고` 같은 OCR 교정 규칙이 영문 낱말·한글 문장을 훼손하지 않도록 보호합니다.
- **변경 내역과 재사용**: `out/<문서 이름>_normalization.html`과 `.json`에 변경 전후·적용 규칙·문맥 판단·미확정 후보를 저장하고 검수 화면 상단에서 비교합니다. `normalization_cache.json`은 같은 제공사·모델·규칙·문맥의 확정 답을 재사용해 문서 재생성 때 중복 호출을 줄입니다. 문맥 교정에 추가 모델 호출이 생기며 `--max-calls` 상한을 함께 따릅니다. 미확정 문맥 교정은 HWPX를 저장한 뒤 종료 코드 **5**와 "문맥 교정 확인 필요"로 알립니다.
- **문맥 교정 호출 줄이기**: 모델에는 후보마다 앞뒤 60자(원문은 30자)만 보내고 한 호출에 80건씩 묻습니다(전에는 앞뒤 600자를 두 벌 붙여 32건씩 — 462쪽 책에서 후보 1만여 건을 수백 번에 걸쳐 차례로 물었습니다). 앞뒤 글이 같은 후보는 한 번만 묻고, 모델이 고르지 못한 후보도 `normalization_cache.json` 에 기억해 문서를 다시 만들 때 다시 묻지 않습니다(전에 고른 답도 그대로 재사용). 판독기·모델을 바꿔도 다른 모델이 앞서 고른 답은 그대로 쓰고 그 모델이 고르지 못한 후보는 묻지 않고 원문대로 둡니다 — 462쪽 책에서 1만여 건을 다시 사지 않게(**다른 모델이 이미 물은 자리·후보는 다시 묻지 않기**, 기본 켬 · `--skip-answered any-model`). 다른 모델의 답은 이번 모델의 기록으로 옮겨 적지 않으므로, 더 나은 모델로 다시 고르게 하려면 그 칸을 끄면(`--skip-answered same-model`) 이번 모델로 다시 묻습니다(호출 듦). 어느 모델이 물었는지는 재사용 기록의 `askers` 와 교정 보고(`out/*_normalization.json` 의 `reader`)로 찾고, 교정 보고에 다른 모델 답을 쓴 수가 나옵니다(옛 기록도 그대로 읽힘). 진행 기록에 30초마다 `문맥 교정 n/N건` 줄이 남고 진행 막대에도 보입니다. [설정] → 문서의 **번체 문맥 교정에 모델 쓰기**를 끄면(`--no-context-model`) 규칙 변환(간체→번체·부호)만 하고 갈리는 후보는 원문을 두며 교정 보고에 남깁니다. [▶ 한 번에 인식]·[④ 문서 만들기] 전 **비용 한 창**에 새로 물을 후보 수·호출·금액이 판독·3차 판별과 함께 나옵니다([아니요] 면 모델 단계 모두 없이 — 문서 만들기는 문맥 교정 모델만 끔). 어림은 문서를 만들 때와 같은 조건(짜임·쪽 잇기·짜임 규칙)으로 세며, 어림하지 못했으면(기록을 읽지 못함 등) 까닭을 보이고 기본 단추를 [아니요]로 둡니다. 재사용 기록의 열쇠에는 프로그램 판 번호를 넣지 않으므로 판을 올려도 이미 산 답을 다시 사지 않습니다(답이 달라질 제공사·모델·규칙 파일·지시문이 바뀔 때만 다시 묻음). 문맥 교정 판독기는 생각을 줄여(thinking=low) 만들고, 재사용 기록을 저장하지 못하면 한 번 알리고 더 묻지 않습니다(기억하지 못하는 답은 다음 실행에서 또 사게 되므로).
- **돈을 쓰기 전에 막는 것**: 양식 HWPX 가 없거나 HWPX 꾸러미가 아니면, 또 원본 쪽대로 문서에 양식을 주었으면 판독·문맥 교정 전에 오류로 멈춥니다(전에는 문맥 교정을 다 산 뒤 양식 없이 만들었습니다). 창도 실행 전에 양식 파일을 확인하고, 작업 탭의 설정 요약에 양식 파일 이름(없으면 '양식 없음(기본 모양)')을 보입니다. 창의 설정 저장은 파일을 새로 읽어 이 창이 바꾼 값만 얹고 임시 파일에 다 쓴 뒤 바꿔 넣습니다 — 다른 창이나 옛 판이 저장한 양식·짜임이 되돌아가거나 설정이 반쪽만 남는 일이 없게. [PDF 글자층 넣기]는 판독 기록을 읽기만 하며, 원본 PDF 가 기록의 원본과 다르면(다시 저장한 PDF 등) 기록을 옮기지 않고 멈춥니다.
- **선택 옵션**: 명령줄 `build`·`run`의 `--no-normalize`는 최종 표기 변환을 생략합니다. `build`도 `--reader`, `--model`, `--max-calls`를 받습니다. API를 사용할 수 없으면 확정할 수 없는 한자 후보는 바꾸지 않고 보고에 남깁니다.

## 0.6.8 — 조용히 틀리던 자리를 막고, 재는 길을 열고, 저장을 안전하게

0.6.7 까지의 실행 기록과 코드를 정확성·안전성·속도 세 갈래로 따로 검토하고(`docs/정확성_안전성_신속성_검토.md`), 겹친 결론을 고쳤습니다.

**정확성**
- **표시 곁 갈림이 사라지던 문제**: 1차가 〔疑: 肝〕 처럼 표시를 단 글자 바로 곁에서 2차와 갈리면 그 갈림이 표시 없이 1차 글자로 들어갔습니다. 이제 표시는 그대로 두고 곁의 다른 글자만 따로 표시합니다(「能入〔疑: 肝〕」 ↔ 「能人肝」 → 「能〔入/人〕〔疑: 肝〕」). 1차 표시 안 글자와 2차가 다르면 글은 그대로 두고 확인 항목에 「↔ 2차 「丁」」 으로 남깁니다.
- **이체자 호환 한자 보존**: 塚(U+FA10)·諸(U+FA22)·者(U+FA5B) 같은 U+FA0E~FAFF 호환 한자는 획이 다른 이체자라 NFC 로 표준 글자에 접지 않고 그대로 저장합니다(지침 21). 발음 중복 호환 한자(樂 U+F914 등)는 전처럼 접습니다. 비교할 때만 같은 글자로 보아 가짜 〔a/b〕 는 생기지 않습니다.
- **가로쓰기 표기 차이 알림**: 1차가 번체(後·體)로, 2차가 인쇄대로 간체(后·体)로 읽어 접으면 같아지는 자리는, 글은 그대로 두고 영역마다 확인 항목 「1차·2차 표기 차이(간체·번체·이체) N자 …」 로 알립니다.
- **좌표 보정**: 약재마다 「【性味】…」처럼 첫 줄이 되풀이되는 쪽에서 1차가 가운데 영역을 빠뜨려도 다음 영역의 상자가 빠진 영역까지 넓어지지 않습니다. 맞춘 줄 수가 영역 줄 수와 맞지 않으면 손대지 않고 사유를 기록(`bbox_fix.regions[id].why`)에 남깁니다.
- **3차 판별**: 다시 계산 뒤 같은 열에 같은 표시가 여럿이면 기록한 앞뒤 글자가 맞는 자리만 바꿉니다(못 찾으면 표시 그대로, 기록 줄에 "3차 확정 위치 못 찾음"). 조각 검사는 앞뒤 글자가 자리를 사이에 두고 이어져 보여야 통과합니다. 묶음은 고르게 나눕니다(9자리 → 5+4).
- **합의 판독 의심(새)**: 1차·2차가 같게 읽어 〔a/b〕 가 없는 글자도, PDF 글자층과 한 글자만 다르고 그 두 글자가 인쇄된 꼴로 헷갈리는 쌍(入/人·曰/日·問/間 …)이면 3차 판별과 같은 방식(눈가림·섞은 후보·묶음·창 검사)으로 글자 조각을 묻습니다. 자형이 글자층 쪽이면 **본문은 판독대로 두고** 그 글자에 메모 「[합의 의심] 1차·2차 「X」, 자형 판별 「Y」(글자층도 「Y」) … — 원본 확인」을 달고 쪽을 '판독 확인 필요'로 둡니다(지침 20: 기존 OCR 은 의심만 올림). 판독 쪽이면 알림이 없습니다.
  묻지 않는 자리: 글자층 일치율 0.5 미만인 쪽(지침 28), 〔〕 표시 안과 바로 곁, 3차가 정한 글자와 그 곁, 1차만 읽은 영역·긴 구간, 숫자·부호·한글, 이체자·간번체 쌍(지침 21), 원본 글자가 `--adjudicate-min-px` 보다 작은 자리(지침 24). 쪽당 최대 8곳(`--suspect-max`, 혼동 장부가 있으면 잦은 쌍부터)이고, 물은 자리는 기록(`suspects`)에 남아 다시 묻지 않습니다(`--force-suspects`). `adjudicate`·`run` 이 〔a/b〕 판별 뒤에 저절로 하며 `--no-suspects` 또는 세부 설정 '3차 판별'의 "합의 판독도 글자층과 다르면 자형으로 확인(표시만)"(기본 켬)으로 끕니다. 실행 전 비용 창은 이 자리 수와 호출·금액도 함께 보입니다.
- **2차 조각 차례 검사**: 긴 영역을 나눠 묶음으로 보낸 2차 조각의 응답이 같은 영역 안에서 번호가 바뀌거나 한 조각을 두 번 돌려주면(1차 글 안 위치로 알아봄) 그 조각들을 낱개로 다시 읽습니다(조각마다 한 번까지, 진행 기록에 남김). 조각은 그림에서 자른 차례 그대로 두고 1차 위치로 옮기지 않습니다 — 낱개로 읽어도 차례가 1차와 다르면 1차 판독의 글 차례를 의심하는 확인 항목을 남기고 본문은 1차대로 둡니다.
- **사용자 영역 글자 보존**: 판독 글에 사용자 영역 글자(U+E000~F8FF — 옛 글꼴이 드문 한자를 넣는 자리)가 있으면 병합 때 표시 토큰과 겹쳐 엉뚱한 표시로 바뀌던 문제를 고쳤습니다.
- **3차 확정 글자의 색 위치**: 같은 열에 같은 표시가 여럿이고 이웃이 다른 후보로 정해지면(〔於/不〕×3 → 於·不·不) 초록이 엉뚱한 글자에 칠해지던 문제를 고쳤습니다(확정 기록을 차례대로 다시 놓아 찾음).
- **책갈피 교정**: 기본 정책을 "전부 자동" → **"확실한 것만"** 으로 낮췄습니다(옛 기본값으로 저장된 설정도 옮김). 자형이 헷갈리기 쉬운 쌍(問/間·卯/卵·王/玉·宜/宣 …)의 한 글자 차이는 두 판독이 같은 쪽으로 틀릴 수 있어 바로 고치지 않고 3차 자형 판별로 넘깁니다. 20자 이상 긴 구간은 어느 정책에서도 자동으로 넣지 않고 삽입 제안 메모만 남깁니다. 3차 자형 판별을 PDF 글자층 대조보다 먼저 하고, 글자층이나 같은 쌍의 반복만으로 교정 후보를 올리는 일은 3차 판별을 할 수 없을 때만 합니다(헷갈리기 쉬운 쌍은 반복돼도 올리지 않음). 2차가 빠져 **1차만으로 읽은 영역**(2차 실패·조각 일부 실패·1차만 들어간 긴 구간)의 차이는 어느 정책에서도 표시만 하고, 2차가 덜 된 쪽은 대조 전에 그 영역의 2차만 다시 묻습니다.

**측정 — `yeone-ocr eval`(새 명령, 모델 호출 없음)**
- 결과 폴더의 판독 기록을 **사람이 입력한 원본 HWPX** 와 맞춰 단계별(글자층·1차·2차·병합 첫 후보·병합 oracle·3차 뒤) 글자 오류율(CER), 표시 밖 오류율, 표시 정밀도, 3차 확정 정밀도·결정률, 1차·2차 공통 오류·오류 상관비, 긴 구간 수를 잽니다. 구획 짝(책갈피·제목)이 있으면 구획마다, 없으면 요청한 쪽 전체를 한 단위로 잽니다. 교정본(`_교정.hwpx`)과 그 사본(`.bak`·`_이전_N`·이름을 바꾼 교정본 — 내용의 교정 표지로 알아봄)은 기준으로 받지 않습니다(순환 평가 방지).

- **1차 측정 손잡이**: `--page-thinking {auto,low,medium,high}`·`--page-media-resolution {auto,high,ultra_high}` 와 [세부 설정] '1차 판독 — 생각 수준 · 쪽 해상도'(기본 auto = 0.6.7 과 같음). Gemini 3 은 생각 수준으로, 2.5 는 생각 예산(low 512 · medium 4096 · high 24576, 2.5 Pro 32768)으로 보내고, 모델이 받지 않으면 모델 기본으로 계속합니다. 판독 진행 기록 첫 줄에 어느 설정으로 돌렸는지 적고, 1차 설정이 바뀐 쪽은 남은 1차를 재사용하지 않습니다.

**안전성**
- **실패한 쪽이 "완료"로 보이지 않음**: 판독에 실패한 쪽이 있으면 창은 "끝 (실패한 쪽 있음)" 과 경고창(실패 쪽 목록)을 보이고 명령줄은 3 을 돌려줍니다. 문서·검수 화면·보고는 그대로 만들고, 다시 누르면 실패한 쪽만 다시 시도합니다. 쪽은 다 읽었는데 3차 글자 판별만 못 마쳤으면 따로 "끝 (3차 글자 판별 못 마침)"·4 로 알립니다. 성공으로 끝나도 "주의:" 줄(깨진 기록 치움 등)이 있으면 알림창에 모아 보입니다. 책갈피 교정은 쪽 기록을 다시 계산했거나 교정본을 `_이전_N` 으로 옮겼거나 판독이 덜 된 구획·오류 난 구획이 있으면 창은 "끝 (확인할 것 있음)"과 알림창, 명령줄은 3 으로 알리고, 교정본을 저장하지 못하면(한컴에 열려 있음 등) "오류:" 와 1 로 멈춥니다.
- **기록이 깨지지 않게**: 판독 기록·상태 파일·쪽 이미지는 임시 파일에 다 쓴 뒤 바꿔 넣습니다. 그래도 깨진 기록이 있으면 `readings/broken/`(상태는 `state.json.broken`)으로 옮기고 그 쪽만 다시 읽습니다. 작업 중 창을 닫으면 중지를 걸어 지금 쪽을 마저 쓴 뒤(최대 15초) 닫습니다.
- **산 판독은 버리지 않음**: 2차 판독 도중 오류가 나도 1차(pro) 결과를 `readings/partial/` 에 남겨 다음 실행에서 재사용합니다(2차만 다시). 조각 하나의 일시 오류는 그 영역만 1차로 넣고 확인 항목으로 표시하되, 그 쪽은 2차가 덜 된 쪽으로 알리고(3) 다음 실행에서 **덜 된 영역의 2차만** 다시 묻습니다(다른 영역의 글·손 고침·3차 판별·합의 의심 기록은 그대로, 바꾸기 전 기록은 `readings/prev/`). 문자 영역 모두의 2차가 실패한 쪽은 실패한 쪽으로 셉니다. 3차 판별로 정한 〔a/b〕 는 합의 의심 단계 전에 저장되어, 그 단계가 호출 상한·한도로 멈춰도 다시 사지 않습니다.
- **호출 상한(비용 안전장치)**: `--max-calls N`(read·run·adjudicate·collate, 기본 0 = 상한 없음)과 [세부 설정] '호출 상한'. 한 명령에서 1차·2차·3차 판독기가 함께 세며 재시도와 실패한 호출도 셉니다. 닿으면 더 보내지 않고 "모델 호출 상한 N회에 닿아 멈춤" 으로 멈춥니다(끝난 쪽은 남음, 다시 누르면 새로 셈).
- **손으로 고친 글 보존**: 이전 판 기록을 다시 비교하기 전, 책갈피 교정이 쪽 기록을 다시 계산하기 전에 `readings/prev/pNNN.json` 에 사본을 남깁니다(그 뒤 내용이 달라졌으면 `pNNN.<시각>.json` 으로 하나 더 — 앞의 사본을 덮지 않음). '기록 있는 쪽도 다시 판독'(`--force`)도 덮어쓰기 전에 같은 사본을 남깁니다. 책갈피 교정은 같은 판·같은 읽기 방향 기록은 다시 계산하지 않습니다. 중간 저장(진행중 HWPX)은 판독 기록을 건드리지 않습니다.
- **교정본 보호**: 교정본은 임시 파일에 쓴 뒤 바꿔 넣고, 있던 교정본은 `<이름>_교정.bak.hwpx` 로 한 세대 남깁니다. 교정본의 구획 목록이 원본과 달라졌으면(한컴에서 제목을 넣은 경우 등) 덮어쓰지 않고 `<이름>_교정_이전_1.hwpx` 로 옮긴 뒤 원본에서 다시 시작하며 "주의:" 로 알립니다.
- **설정 오류는 바로 멈춤**: 설치된 google-genai 가 생각 수준·해상도 설정을 모르면 쪽마다 30초씩 헛재시도하지 않고 바로 멈춰 알립니다. 응답 형식 오류는 3번까지만 다시 묻습니다. 2차 묶음 호출이 실패하면 두 반으로 한 번 더 묻고 빠진 조각만 낱개로 갑니다.
- 설정 파일(API 키 포함)은 본인만 읽는 권한(0600)으로 만듭니다(Windows 는 해당 없음). 패키지 설치(pip)·결과 열기에는 API 키 환경 변수를 넘기지 않습니다. 환율은 하루 한 번만 조회합니다. 여러 판독 스레드가 함께 써도 진행 기록의 '오류:'·'주의:' 줄이 섞이거나 빠지지 않습니다. 창에서 API 키를 바꾸면 책갈피 교정의 3차 판독기도 새 키를 씁니다.

**속도**
- 한 번에 인식이 쪽 이미지·글자층을 전부 꺼낸 뒤가 아니라 판독과 나란히 미리 만듭니다(300쪽이면 첫 호출까지 7~15분 기다리던 것이 사라짐). '기록 있는 쪽도 다시 판독' 은 쪽 파일을 다시 꺼내지 않습니다(다시 꺼내려면 `prepare --force`).
- 동시 판독 쪽 수 최대 6 → **8**(옛 기본값 6 으로 저장된 설정은 8 로, 직접 고른 값은 그대로). 429 자동 조절은 성공한 쪽만 "깨끗한 쪽"으로 셉니다.
- Gemini 3 계열은 쪽 이미지를 2배로 키우지 않습니다(토큰 예산이 고정이라 CPU·전송만 들었음). 모델에 보내는 PNG 를 빠른 압축으로 만듭니다(무손실 그대로).
- 2차 묶음은 고르게 나눕니다(9장 → 5+4, 이전 8+1).
- 쪽별 상태 표는 판독 기록을 작업 스레드에서 읽습니다(300~700쪽에서 창이 1~3초 멈추던 것).

**이전 판 기록**: 0.6.7 이하로 만든 판독 기록은 처음 실행할 때 새 병합 규칙으로 다시 비교합니다(모델 호출 없음, 사본은 `readings/prev/`). 표시 곁 갈림이 새로 드러날 수 있습니다.

## 0.6.7 — API 키 여러 개: 하루 한도에 걸리면 다음 키로

"API 키" 칸에 **다른 프로젝트의 키를 쉼표로 이어** 여러 개 넣을 수 있습니다(예: `AIza…, AIza…`). Gemini 의 하루 한도는 프로젝트마다 따로 매겨지므로,
한 키가 하루 한도에 걸리면 멈추지 않고 다음 키로 바꿔 같은 쪽부터 이어서 읽습니다(진행 기록에 "키 1/2 … 키 2 로 바꿔 계속" 이 남음). 넣은 키가 모두 한도에 걸렸을 때만 멈춥니다.
[키 확인·모델 고르기] 는 첫 키로 모델을 고르고, 나머지 키도 쓸 수 있는지 확인합니다.

## 0.6.6 — 하루 한도에 걸리면 바로 멈춤 · 크게 잘린 도판 복구

Gemini 의 **하루** 요청 한도(429, quotaId `…PerDay…`)에 걸리면 120초씩 다시 시도하며 남은 쪽을 실패로 넘기지 않고 곧바로 멈춥니다.
끝난 쪽은 기록에 남고, 한도가 다시 차는 시각(태평양 시간 자정, 이 PC 시각으로 환산)을 진행 기록에 알려 줍니다. 그 뒤 [▶] 를 다시 누르면 남은 쪽부터 이어서 합니다('기록 있는 쪽도 다시 판독' 은 끄십시오).
분당 한도는 지금처럼 기다렸다 다시 시도합니다.

**도판이 크게 잘리던 문제.** 모델이 준 도판 좌표가 원형 도판의 반쪽만 잡는 등 크게 어긋나면, 전에는 바깥으로 3% 남짓만 넓혀 보다 그만두어 도판이 잘린 채 문서에 들어갔습니다.
이제는 좌표 테두리를 가로지르는 큰 먹 덩어리(도판의 테두리·선)를 찾아 그 전체를 품도록 넓힙니다. 글자 같은 작은 덩어리와 판 테두리(版框)는 끌려오지 않습니다.
예전 판으로 잘라 둔 도판은 [④ 문서 만들기] 또는 [▶ 한 번에 인식] 때 다시 자릅니다(모델 호출 없음).

## 0.6.5 — 3차 눈가림 (연구 문서 `docs/인식률_제고_방안.md` 의 단계 2)

3차 글자 판별이 문맥으로 고르지 못하게, **묻는 방식 자체**를 바꿨습니다. 글자를 정하는 규칙(후보 안 답만, 조각 자리 검사, 못 가리면 표시 그대로)은 같습니다.

- **앞뒤 글자를 글로 주지 않습니다.** (조각 그림에는 이웃 글자가 그대로 보입니다.) 이전에는 질문에 「앞뒤 글자: 小肠，能 _ 阴分」 이 들어가 모델이 「能入」 같은 낱말로 고를 여지가 있었습니다.
  이제 모델은 조각과 "조각 안 위에서 3번째 글자(조각의 글자 5자)" 같은 순번만 받습니다. 판독기 함수가 앞뒤 글자를 받지 않으므로(GlyphAsk) 프롬프트에 새어 들어갈 길이 없습니다.
  앞뒤 글자는 답을 받은 뒤 프로그램이 "조각에 보인 글(w)"과 맞춰 조각 자리를 검사하는 데만 씁니다(이전과 같음 — 초록·파랑 구분도 그대로).
- **눈금**: 자리를 실측한 경우(글자층의 글자 상자, 또는 먹 구간 수가 글자 수와 꼭 맞을 때)에는 조각 바깥에 흰 띠를 덧대 대상 글자 옆에 빨간 꺾쇠를 그립니다.
  글자 획 위에는 아무것도 그리지 않습니다. 실측하지 못한 자리는 눈금 없이 "순번은 어림"이라고 알립니다(획이 갈라지는 二·三·川·八 이 든 줄은 먹 셈이 안 맞아 어림이 됩니다).
- **후보 차례를 섞습니다.** 늘 1차 글자를 먼저 적던 것을 자리 정보로 만든 고정 씨앗으로 섞습니다(먼저 적힌 후보를 고르는 위치 편향을 덜고, 다시 실행해도 같은 질문).
- **자형 전용 시스템 지시**: 3차 판별기는 지침 전문(혼동 카드의 "장부 앞은 入이 흔하다", 가로 모드의 于 용법 목록 같은 문맥 단서 포함) 대신
  지침 2·7·19·21·24장 요지와 묶음별 자형 단서만 담은 짧은 지시를 씁니다. 짧아서 컨텍스트 캐시는 쓰지 않습니다(캐시 최소 길이에 못 미침).
- **보고 → 적고 → 고르게**: 답의 차례를 w(조각에 보이는 글자) → e(본 자형) → c(고른 글자)로 바꿨습니다. 모델이 먼저 보고 적은 뒤에 고릅니다.
- **저해상이면 묻지 않음**(지침 24): 원본 이미지에서 잰 글자 크기가 16px(`--adjudicate-min-px`, 0=끔)보다 작으면 묻지 않고 표시를 그대로 둡니다.
  확대해도 없는 획이 살아나지 않기 때문입니다. 300dpi 로 그린 10pt 글자는 약 42px, 75dpi 스캔의 10.5pt 는 약 11px 입니다. 16px 은 잠정값이며 실측으로 고칠 값입니다.
- **후보 없이 재확인**(선택): 판독 칸 [세부 설정 ▾] → 3차 판별 → [후보 없이 한 번 더 읽어 같을 때만 확정] (`--adjudicate-blind`). 고른 자리만 후보도 주지 않고
  한 번 더 읽게 해(그 자리의 답을 낸 판독기에), 두 답이 같을 때만 확정합니다. 간체·번체·이체는 같게 보되, 두 후보가 이체자 쌍(黃/黄·苡/苢)이거나 숫자·부호면
  글자 그대로 맞춰 봅니다(인쇄된 꼴을 고르는 자리라서). 빈 답·다른 답·재확인 실패면 표시를 그대로 둡니다.
  호출이 더 듭니다: 일반 OCR 은 쪽마다 확정 자리 8곳당 1회, 책갈피 OCR 교정은 확정 항목마다 1회(같은 선택을 씁니다).
- 눈금·"실측" 순번은 확실할 때만: 두 후보의 글자 수가 다르면(〔日一/旦〕) "n번째 글자부터 1~2자"로만 가리키고 눈금을 그리지 않습니다.
  글자층이 대상 글자를 빠뜨리거나 쪼갠 자리, 먹 셈이 공백을 뺀 글자 수와 맞지 않는 줄도 어림으로 알립니다.
- 책갈피 OCR 의 자형 3차 판별(入/人·曰/日 항목)도 같은 방식으로 묻습니다.
- 기록(readings/pNNN.json 의 adjudications)에 `pos`(순번)·`asked`(물은 후보 차례)·`em_px`(글자 크기)·`blind`(재확인 답)가 더 남습니다. 위치 편향·저해상 문턱을 잴 때 씁니다.
- 아직 재지 않은 것: 눈가림이 확정 정밀도·결정률을 얼마나 바꾸는지는 실제 책으로 재야 합니다(연구 문서의 '앵무 시험'). 이 판에는 측정 결과가 없습니다.

## 0.6.4 — 이미지 입력 · 확인 등급 색 · 문맥 추정 · 고지 사항만 메모

- **이미지도 판독**: [PDF·이미지 고르기…] 에서 PNG·JPG·TIFF·BMP·WEBP 등을 고르면 그대로 판독합니다. 여러 장을 고르면 이름의 숫자 순서(p2 가 p10 앞)로
  한 권(PDF, 무손실)으로 묶고, 여러 쪽 TIFF 는 쪽마다 한 쪽입니다. 명령줄은 이미지 폴더도 받습니다. 이미지에는 글자층이 없으므로 읽기 방향은 세로쓰기로 봅니다.
- **확인 등급 색**: 문서의 글자를 얼마나 믿어도 되는지 색과 밑줄로 보입니다. 글 자체는 한 글자도 바꾸지 않고 글자 모양만 입힙니다.

  | 파랑 + 파선 밑줄 | 정했지만 근거가 약함 — 확인 권장 | 3차가 골랐지만 조각 위치를 확인 못 했거나 이 판독의 다른 대목과 어긋남 | 판독(1차·2차 일치)만으로 고친 글자(정밀도 미측정), 사전으로 번체를 고른 글자(B2), 글자층·반복 근거, 지운 자리 |
  | 빨강 굵게 + 노랑 〔 〕 | 정하지 못함 — 원본 확인 필수(지침 19) | 〔a/b〕·〔疑: x〕·〔판독불명〕·〔원본 결락〕 | 확인 요청(글자는 HWPX 그대로) |
  | 〔 〕 안 한 후보의 실선 밑줄 | 문맥 추정 — 확정 아님(문턱 미측정) | 이 판독의 다른 대목이 더 많이 쓰는 후보 | — |

  색은 색각 이상·흑백 인쇄에서 구별되지 않을 수 있어 밑줄 모양을 함께 다르게 둡니다. 가장 믿을 수 있는 것은 **괄호 〔 〕** 입니다: 색이 사라져도 남으므로
  한컴에서 Ctrl+F 로 〔 를 찾아 남은 자리를 돌 수 있습니다. 확인한 글자는 모양 복사(Alt+C)로 색을 지우면 '색이 남은 곳 = 아직 확인하지 않은 곳'이 됩니다.
  초록은 기계(3차) 판별이고 정밀도는 아직 재지 않았습니다. 0.6.5 부터 3차 질문에는 앞뒤 글자를 넣지 않습니다(위 '3차 눈가림').
- **문맥 추정**(모델 호출 없음): 자형으로 가리지 못한 〔a/b〕 자리에서, 이 판독의 다른 대목(1차·2차가 같게 읽은 글)이 앞뒤 글자와 함께 어느 후보를 더 쓰는지 셉니다
  (예: 入肝 17번 · 人肝 0번). 한 후보가 충분히(3번 이상이면서 다른 후보의 4배, 入/人 같은 자형 편향 쌍은 6번 — 아직 재지 않은 문턱) 앞서면 그 후보에 실선 밑줄만 긋습니다.
  괄호와 두 후보는 그대로이고 글은 바꾸지 않습니다(지침 2·7·21). 3차가 고른 글자를 다른 대목이 강하게 반대하면 초록을 파랑으로 낮추고 쪽마다 3곳까지 메모로 알립니다.
  〔판독불명〕·〔원본 결락〕·〔疑〕, 두 글자 후보, 숫자, 干支·방위 나열, 괘상, 이체자 쌍, 한글 후보, 자형이 닮지 않은 쌍, 표시가 몰린 곳·글자층과 크게 어긋난 쪽(지침 28)에는 하지 않습니다.
  1차 모델이 〔자형 글자/문맥 글자〕 로 적은 표시의 두 번째(문맥) 후보는 다시 밀지 않습니다. 세는 바탕도 OCR 이라 두 판독이 같은 방향으로 틀린 글자는 수를 그쪽으로
  기울이므로, 밑줄은 '힌트'일 뿐입니다. 근거 수는 검수 화면의 쪽마다 '문맥 추정' 표와 결과 폴더의 `context.json` 에 있습니다(판독 기록은 건드리지 않음). 끄려면 문서 칸의 [문맥 추정 밑줄] 을 끄십시오(`--no-context`).
- **메모는 고지 사항만**(기본): 색으로 전할 수 있는 것에는 메모를 달지 않고, 색으로 전할 수 없는 것에만 글자 하나에 답니다.
  - 일반 OCR: 첫머리의 표시 범례 하나, 본문에 표시되지 않은 확인 항목(긴 구간 갈림·영역 밖 글줄 등 — 지금까지 문서에 전혀 보이지 않던 것), 구조 검사 오류,
    도판 가장자리 닿음, 3차와 다른 대목의 어긋남, 3차로 정했지만 본문에서 찾지 못한 자리, 한 쪽 안에서 영역 id 가 겹친 경우([영역 id 겹침] — 그 영역에는 등급·문맥 밑줄을 칠하지 않음). 쪽 고지는 쪽 기록 줄 끝 글자에 하나로 모읍니다.
  - 책갈피 OCR: 지운 글자, 폭 없는 표시, 구조 차이(C), 반영하지 않은 제안(정책 sure·memo), 구조 규칙이 붙인 고지(한글 풀이·숫자 체계·각주·서명), 그리고 범례 하나(문단은 넣지 않고 첫 글 앞의 빈 자리에 — 이어 교정할 때 문단 번호가 밀리지 않게).
    **주의**: 기본(고지 사항만)에서는 자동으로 고친 글자의 원래 HWPX 글자가 문서 메모에 남지 않습니다. 보고(collate 폴더의 html·json)와 손대지 않은 원본 HWPX 에 있습니다. 0.6.3 처럼 모든 교정에 메모를 원하면 [메모] 를 '모든 표시에 메모(근거, 이전 방식)' 로(`--memo all`).
    판독 일치만으로 한 자동 교정을 초록이 아니라 파랑으로 칠하는 까닭: 초록은 두 탭 모두 '3차가 글자 조각을 보고 고름' 이라는 같은 뜻이고, 판독 일치만의 자동 교정은 정밀도를 아직 재지 않았기 때문입니다.
  - [메모] 고르기: 고지 사항만 메모(기본) / 모든 표시에 메모(근거, 이전 방식) / 메모 없이 글 속 〔…〕. 명령줄 `--memo notice|all|inline`(책갈피 `--no-memo` 는 inline). DOCX 는 Word 주석으로 같습니다(python-docx 1.2 이상).
  - 2차 판독 없이 1차만 들어간 쪽은 범례 메모에 쪽 목록으로, 일부 영역만 2차가 없으면 그 쪽의 고지로 알립니다(갈림 표시가 없어도 원본 확인).

## 0.6.3 — 화면 다듬기

- **탭 이름**: "세로쓰기 인식" → **"일반 OCR"**(가로쓰기 한문 책도 같은 탭에서 읽으므로). 맨 위의 두 갈래 단추 [일반 OCR | 책갈피 OCR] 로 바꿉니다.
- **글자가 잘리던 단추**: 단추 너비를 글자 수로 고정하던 것을 없애 [결과 폴더]·[④ 문서 만들기]·[비교 다시 계산]·[패키지 설치·점검]·[이 구획 대조만] 같은 이름이 다 보입니다. 고르기 칸도 가장 긴 값이 다 보이는 너비로 잽니다.
- **체크 표시**: ☒(가위표) 대신 강조색 상자 안의 흰 **✓** 로, 라디오 단추도 같은 모양으로 그립니다.
- **진행 막대**: 좌우로 오가던 막대 대신 **처음부터 끝까지 한 방향으로 차는 막대**입니다. 단계마다(준비·판독·3차 판별·문서·검수 화면·보고, 책갈피 OCR 은 구획) 진행을 알려 오른쪽에 "44% · 판독 22/40쪽 · 남은 시간 약 13분" 처럼 보이고, 끝나면 "100% · 완료 · 걸린 시간" 이 남습니다.
- **배치**: 카드(둥근 모서리 판) 셋 — PDF · 이미지 / 판독 / 문서. 2차 판독 모델·속도·조각·단계 설정은 판독 카드의 **[세부 설정 ▾]** 에 접었고(펼친 상태는 기억), 단계별 단추는 **[▸ 고급]** 에 그대로 있습니다. 긴 설명문은 줄이고 **단추에 마우스를 올리면** 하는 일이 나옵니다.
- **실행 줄은 늘 보이는 자리**: [▶ 한 번에 인식]·[■ 중지]·[비용 미리 보기]·[결과 폴더]·[HWPX 열기] 는 진행 막대 바로 위에 고정되어, 설정 칸을 펼쳐도 가려지지 않습니다(책갈피 OCR 탭에서는 [▶ HWPX 전체 교정]·[■ 중지]·[보고 열기]·[교정본 열기] 와 그 아래 줄의 교정 정책·한컴 메모·[이 구획 대조만]·[이 구획 교정]). 위 설정 칸은 넘치면 스크롤되고(휠로 굴려도 고르기 칸 값은 바뀌지 않음), 가운데 손잡이(━)를 끌어 기록 칸 높이를 바꿀 수 있습니다. 창을 줄여도 실행 줄·진행 막대·기록 몇 줄은 남깁니다.
- **진행 글**: 진행률을 셀 수 없는 작업(키 확인·구조 보기·혼동 장부 등)은 "진행 중 · 12초" 처럼 지난 시간을 보여 줍니다. [■ 중지] 로 멈춘 작업은 "중지됨" 으로 남고 막대가 끝까지 차지 않습니다.
- **단추 위계**: 강조(진한 옻칠색, 실행) · 보통(흰 바탕 테두리 단추) · 글자 단추(펼치기·접기) 세 단계로 나눠, 무엇을 눌러야 하는지 한눈에 보이게 했습니다. 고해상도 화면에서는 그림·여백을 화면 배율에 맞춰 키웁니다.
- 그림(둥근 단추·카드·✓)은 외부 패키지 없이 표준 라이브러리로 그린 PNG 라서, 패키지를 설치하기 전에도 창이 뜹니다(빠진 패키지 수는 머리띠에, 목록은 진행 기록에).
- **읽기 쉬움**: 흐리던 안내 글·꺼진 체크 상자·입력칸 테두리를 짙게 해 대비를 높였습니다(글자 4.5:1, 테두리 3:1 이상). Tab 으로 옮겨 간 칸에는 짙은 금빛 고리가 둘리고(Tab 으로 가려진 칸에 가면 그 칸이 보이게 굴러감), 마우스로 누를 때는 고리가 남지 않습니다. 창이 낮은 노트북 화면에서는 설정 칸에 먼저 자리를 주고 기록 칸을 2~5줄로 줄이며, [구획 색인] 이 끝나면 구획 표가 보이게 굴러갑니다. [▸ 고급]·[세부 설정 ▾] 을 펼치면 펼친 칸이 보이게 굴러갑니다.

## 0.6.2 — 3차 글자 판별을 빠르고 정확하게 (연구 보고 `docs/한번에인식_개선_연구.md` 의 1단계)

- **3차 판별 묶음·동시 호출**: 자리마다 한 번씩 차례로 묻던 것을 쪽마다 8자리씩 묶어 한 호출로(`--batch-sites`, 1=낱개) 묻고, 쪽은 판독과 같은 자동 조절(동시 4→6, 429 면 줄임)로 돌립니다. 300쪽·쪽당 5자리면 호출 1,500회가 약 300회(쪽당 1회)로 줄고 그것도 여섯 쪽씩 동시에 나갑니다. 묶음 응답에서 빠졌거나 조각에 보인 글(w)이 앞뒤 글자와 안 맞는 자리만 낱개로 다시 묻고, 묶음 호출 자체가 실패하면(한도 초과 등) 그 자리들은 "판별 실패"로 남겨 낱개로 번지지 않습니다(표시가 남으니 다음 실행에서 다시). 생각 수준은 기본 LOW(`--adjudicate-thinking full` 로 되돌림) — 객관식 자형 질문이라 깊은 생각이 필요 없습니다.
- **판별 모델 선택**: `--adjudicate-model` 을 비우면 1차 모델(기본), 이름을 주면 그 모델, `auto` 면 같은 세대 flash 로 먼저 묻고 못 가린 자리만 1차 모델로 보완합니다(기록에 어느 모델이 가렸는지 남음). 확정률이 떨어지는지는 표본 쪽으로 실측해 보고 쓰십시오.
- **글자 자리 실측**: 글자 창을 "영역 상자를 줄 수·글자 수로 균등 분할" 하던 것에서, ① 글자층의 글자별 상자(`rawdict`, 쪽 이미지가 놓인 사각형 기준으로 환산) → ② 쪽 이미지의 먹 띠(줄)·먹 구간(글자) 실측 → ③ 균등 분할 순으로 바꿨습니다. 300dpi 한자 렌더 실측(세로·가로, 줄 길이 제각각, 영역 상자 잡음 8%)에서 목표 글자가 창 안에 든 비율이 ③ 87% → ① 98%·② 98% 였습니다. 어느 방법을 썼는지 기록(`adjudications[].loc`)과 진행 기록 요약에 남습니다. 책갈피 OCR 의 자형 판별도 같은 자리 실측을 씁니다.
- **같은 열의 같은 표시**: `〔入/人〕` 이 한 열에 둘일 때 앞 자리가 미정이고 뒤 자리만 확정되면 첫 표시를 바꾸던 잘못을 고쳤습니다(글자 번호로 자리를 찾음). [비교 다시 계산] 뒤 다시 적용할 때도 같습니다.
- **조각 해상도 3단**: 2차 조각 이미지의 토큰 예산을 기본 / 높음(high) / **최고(ultra_high, Gemini 3 조각당 2,240 토큰)** 에서 고릅니다(`--media-resolution ultra_high`, 화면의 "조각 해상도"). 최고는 조각마다 붙여 보내고 모델이 거부하면 높음 → 기본값 순으로 자동으로 내립니다. 이전 판 설정(켬/끔)은 높음/기본으로 옮겨집니다. [비용 미리 보기] 의 첫 어림(실측이 없을 때)은 조각 해상도 설정과 무관한 타일 셈법이라 기본·높음·최고가 같은 값으로 나오며, 몇 쪽 실측(usage)이 쌓이면 실제 토큰으로 보정됩니다.
- **중지**: 3차 판별 중 [■ 중지] 를 누르면 진행 중인 쪽의 남은 묶음·보완을 건너뛰고(끝난 자리는 적용·저장, 묻지 못한 자리는 표시와 기록을 그대로 둠) 멈춥니다. 후보 밖 글자를 답한 자리는 미정으로 다뤄 보완 판독기에 넘기고, 보완 호출이 실패하면 첫 판독기의 답을 남깁니다.

## 0.6.1 — 첫 실측(중의역대약론선 130·131쪽)에서 드러난 결함을 고침

- **영역 좌표 보정**: Gemini 가 준 영역 좌표가 글이 빽빽한 쪽에서 아래로 갈수록 밀렸습니다(130쪽 맨 아래 영역 7.8% = 글줄 4개). 그대로 쓰면 2차 조각이 이웃 인용문을 읽어 가짜 차이가 쏟아지고(확인 필요 77건), 3차 판별도 엉뚱한 글자를 보고 확정했습니다. 이제 1차 판독 직후 영역 좌표를 글자층 줄 위치(가장 정확)나 쪽의 먹 띠(글줄)에 맞춘 뒤 조각을 자릅니다. 고친 내역은 기록(bbox_fix)과 진행 기록("좌표 보정 — …")에 남습니다.
- **이전 기록 자동 재판독**: 좌표가 2% 넘게 밀려 있던 이전 판 기록은 `readings/stale/` 로 옮기고 다시 판독합니다. 조금 밀린 기록은 좌표만 고쳐 다시 비교합니다(모델 호출 없음).
- **가로쓰기 덮개 검사**: 영역 밖 글을 줄 단위로 찾습니다(머리글 한 줄이 글자 수만큼 "글 기둥" 20건으로 쪼개지던 잡음 제거). 쪽 가장자리 줄은 머리글·쪽번호로 보고 본문에 붙이지 않습니다.
- **2차 묶음 호출**: 한 호출에 조각 8장까지만 넣고(`--batch-crops`), 돌아온 글이 제 영역의 1차 글과 안 맞고 다른 영역과 맞으면 버리고 낱개로 다시 읽습니다(모델이 조각과 영역 번호를 섞는 일 대비).
- **3차 판별 자리 검사**: 모델에게 조각에 보이는 글 전부(w)도 적게 하고, 기대한 앞뒤 글자와 이어지지 않으면 확정하지 않습니다(조각이 엉뚱한 자리면 "조각 위치가 어긋남"으로 보류).
- **인쇄 쪽수 차이 자동 판정 보강**: 머리글·꼬리글 자리의 숫자만인 줄(114)도 쪽번호로 봅니다. 글자층으로 못 정하면 판독한 쪽번호가 2쪽 이상 모이는 대로 판정해 결과 폴더에 적고, 어긋난 쪽을 표시합니다. 화면의 "인쇄 쪽수" 칸은 비우거나 0 이면 자동입니다.

## 인식률을 위해 0.6.0 에서 바뀐 것

중의역대약론선 결과 폴더(판독 9쪽·대조 4구획)와 HWPX 85만 자·300dpi 쪽 이미지를 실측한 결과를 바탕으로 고쳤습니다.

- **2차 조각을 작게**: 가로쓰기 모드에서 조각을 좌우로만 넓히고 위·아래는 글줄 사이 공백에 맞춥니다(이웃 줄을 끌어들여 "1차 판독에 없고 2차에만 있음"이 확인 목록의 65%를 차지하던 과확장 방지). 글줄(세로쓰기는 열)이 "2차 조각 한 장에 N줄"(기본 8)을 넘으면 나눠 보내고 돌아온 열을 이어 붙입니다. 글자당 픽셀이 늘어 획 하나 차이(入/人·曰/日·于/干)를 가립니다. 쪽 전체 확대는 그대로 두되 조각 긴 변은 3000px 안으로 둡니다(모델이 그 이상은 줄여 버림).
- **조각 고해상**: 2차 판독기에 `media_resolution=high`(Gemini 이미지 토큰 예산)를 씁니다. 모델이 거부하면 자동으로 기본값으로 돌아갑니다. (0.6.2: Gemini 3 에서는 `ultra_high` 로 조각당 두 배까지)
- **혼동 글자 카드**: 지침 7·8·14장의 목록을 "자형 기술 + 문맥 단서 + 출력 규칙" 카드로 지시문 끝에 붙였습니다(세로·가로 모드 공통). 자형과 문맥이 어긋나면 `〔자형/문맥〕` 두 후보를 적게 합니다.
- **3차 글자 판별**과 **혼동 장부**(위 표). [▶ 한 번에 인식] 안에 들어 있어 따로 누르지 않아도 됩니다(`--no-adjudicate` 로 끔 — 0.6.8 의 합의 판독 의심도 함께 꺼짐).
- **한 번에 인식·전체 교정**: 사용자가 단계와 설정을 이해하지 않아도 되게 했습니다. 읽기 방향과 인쇄 쪽수 차이는 PDF 글자층으로 판정해 결과 폴더에 적고, 이전 판으로 만든 판독 기록은 지금 규칙으로 저절로 다시 비교하며, 단계별 단추는 "고급"으로 접었습니다. 책갈피 OCR 은 구획 전체를 한 단추로 대조·교정하고 요약을 남깁니다. 빠진 패키지는 켤 때 설치할지 묻습니다.
- **글자층 대조에서 부호 접기**: 전각·반각 부호(，↔,)와 `〔〕` 표시는 차이로 세지 않습니다(실측에서 글자층 차이의 60%가 부호였음).
- **책갈피 OCR 대조 규칙**:
  - 이체자 표 보강(澁·沈·汚·昻·濬·擧·脇·袪·塡·巓·愼·蔲·苢·着) — "확실한 오탈(A)"로 잘못 잡혀 HWPX 표기를 바꾸던 가짜 차이(실측 A 의 30%)가 사라집니다.
  - 아라비아 숫자만인 삽입·삭제(인용 번호 1. 2. 3.)는 표기 차이로, 숫자와 글자가 섞인 치환(「本草」→「4」)·한자 숫자만의 삽입·삭제·각주(注1…) 삽입·서명(『』) 일부로 보이는 짧은 삭제(「本草」綱目)는 표시만 합니다.
  - HWPX 쪽에만 한글이 있는 자리(편집자의 풀이)는 어떤 정책에서도 자동 반영하지 않습니다.
  - 入/人·曰/日·土/士·未/末·己/已/巳·大/太/犬·白/自 는 OCR 엔진들이 같은 방향으로 틀리고 인쇄 자체가 오자인 일도 있어, 한 글자 차이를 자동 교정하지 않고 글자층도 증인으로 쓰지 않습니다(3차 판별로).
  - 같은 (HWPX, 판독) 한 글자 쌍이 한 구획에서 5회 이상 되풀이되고 문맥으로 못 가리면(간체 于를 幹으로 일괄 변환한 HWPX 등) 책 전체의 변환 오류로 보고 교정 후보로 올립니다.
  - 혼동 묶음 보강(府腐·山由·失尖·信倍·届属·镇慎·宜宣·囊裹·胀脓·恶悉, 疒·艹·木·月 부수 가족 등), 구획 제목이 되풀이된 줄 제거, 보고와 json 에 기준 HWPX 파일(원본인지 교정본인지) 기록.
- 2차 판독의 사용량 필드를 한 번 그대로 진행 기록에 적습니다(생각 토큰이 0 으로만 기록되던 원인 확인용).

## 지침과의 대응

- 영역 분류(3장) → 모델 출력 스키마로 강제. 도판은 글자를 적지 못하게 하고 좌표만 받습니다(9~11장).
- 읽기 순서(4장) → 열마다 "오른쪽에서 n번째" 번호와 위→아래 글을 받고, 열 바꿈은 아무것도 넣지 않고 잇습니다(18장).
- 판독 불명(19장) → `〔판독불명〕〔疑: ○〕〔○/△〕〔원본 결락〕` 과 위치(쪽·열·구간)를 함께 기록. 2차 판독과 다른 자리는 자동으로 표시.
- 기존 OCR(20장) → 참고용 차이 목록만, 자동 반영 안 함.
- 구조 검사 → 괘상 ASCII 대체, 한글 자모 분리, 쪽번호 혼입, 그림 안 글자 전사, 괄호 불균형, 표 셀 수 불일치, 인쇄 쪽수 불일치.
- HWPX(23장) → 실제 OWPML 구조로 만들고 다시 열어 그림 수·구조를 검사. 확장자만 바꾼 파일은 걸립니다.
- 보고(33장) → 프로그램은 자동 OCR 범위만 완료로 적고, "원본 대조 완료(사람)" 은 사람만 붙입니다.

## 속도 (정확도는 그대로)

- **동시 판독(자동 조절)**: 4쪽에서 시작해 10쪽 연속 문제없으면 하나씩 늘리고(최대 8, 설정 가능 — 0.6.8 에서 6 → 8), 한도 초과(429)가 보이면 하나 줄이고 20초 쉽니다. 쪽별 기록은 독립이라 결과는 같습니다.
- **2차 판독 묶음 호출**: 한 쪽의 문자 영역 조각들을 한 호출로 보냅니다(기본). 확대 조각은 그대로라 정확도는 같고, 호출 수와 지침 재전송이 절반 이하로 줍니다. 빠진 영역은 자동으로 낱개 호출합니다.
- **지침 캐시**: 호출마다 보내던 지침 전문(약 9천 토큰)을 Gemini 컨텍스트 캐시에 올려 참조합니다. 모델이 지원하지 않으면 자동으로 일반 호출로 돌아갑니다. 진행 기록 첫 줄에 "지침 캐시 사용/미사용"이 찍힙니다.
- **2차 판독 모델 `auto`(기본)**: Gemini는 1차와 같은 세대의 flash 모델(lite 제외, 정식판 우선)을, 없으면 더 새 세대 flash 를 자동으로 골라 2차 전사에 쓰고, 그것도 없으면 1차 모델로 읽습니다(비용 창도 같은 규칙으로 셈). OpenAI·Anthropic은 1차와 같은 모델을 씁니다. 같은 제공사의 다른 모델 이름을 직접 지정할 수도 있습니다. 두 판독이 다른 자리는 모두 표시합니다.
- **2차 생각 줄이기(기본 켬)**: 2차는 확대 조각의 순수 전사라 깊은 생각이 필요 없습니다. 3.x 는 thinking_level LOW, 2.5 는 thinking_budget 512 로 보냅니다. 모델이 거부하면 자동으로 기본값으로 돌아갑니다. 1차(영역 분류)는 모델 기본 그대로 둡니다.
- **3차 판별 묶음·동시(0.6.2)**: 〔a/b〕 자리를 한 호출에 8장씩 묶고 쪽을 동시에(판독과 같은 자동 조절) 돌립니다. 생각 수준 LOW. 이전에는 자리마다 한 번씩 차례로 불러 책 한 권의 3차 꼬리가 판독보다 길었습니다.
- **이전 판 설정**: 0.4.0 이하에서 저장한 설정(동시 3, 2차 모델 비움)은 처음 실행할 때 새 기본값(동시 6 자동 조절, 2차 `auto`)으로 올려 줍니다. 직접 바꾼 값은 그대로 둡니다.
- **짧은 JSON 키**: 모델이 돌려주는 JSON 의 키를 짧게(n, t, cols, paras…) 해 출력 토큰을 줄였습니다. 저장 파일(readings/*.json)은 읽기 쉬운 긴 이름 그대로입니다.

- **중간 저장**: "중간 저장 N쪽마다"(기본 20) 판독이 진행될 때마다, 그리고 중지·오류로 멈출 때 `out\<PDF 이름>_진행중.hwpx` 를 다시 만듭니다. 최종 문서가 만들어지면 진행중 파일은 지웁니다.

- 쪽마다 기록이 남으므로 **중단·재개**가 됩니다. [■ 중지] 뒤 다시 [▶] 를 누르면 기록이 있는 쪽은 건너뛰고 이어서 합니다.
- 한 쪽이 일시 오류(응답 형식 불량 등)로 여러 번 실패하면 그 쪽만 건너뛰고 계속하며, 끝에 실패한 쪽 번호를 알려 줍니다. 이때 창은 "완료"가 아니라 "끝 (실패한 쪽 있음)"과 경고창을 보이고, 명령줄은 3 을 돌려줍니다(0.6.8). 다시 [▶] 나 [③ 판독] 을 누르면 그 쪽들만 다시 시도합니다. 키·권한·모델·한도 0 같은 오류는 전체를 멈춥니다.
- 10쪽마다 쪽당 소요 시간과 남은 시간을 진행 기록에 적습니다. 700쪽이면 쪽당 30초~1분 기준 6~12시간입니다.
- 도판은 JPEG 로 넣어 수백 장이 들어가도 문서가 지나치게 커지지 않습니다. 권별로 나누려면 명령줄 `--split 200`(200쪽씩) 을 쓰십시오.
- [비용 미리 보기](와 실행 전 비용 창)가 판독·3차 판별·합의 의심·문맥 교정까지 한 창에 호출·토큰·금액을 어림합니다. 세는 일은 작업 스레드에서 하므로 수백 쪽이어도 창이 멈추지 않습니다(462쪽이면 몇 초). 몇 쪽을 먼저 돌려 기록이 쌓이면 남은 쪽의 어림도 이 책 쪽당 평균·실측 토큰으로 더 정확해지고, 다시 판독(force)도 이 책 평균으로 셉니다.

## 알려진 한계

- 글자 정확도는 모델에 달려 있습니다. 153dpi 스캔의 작은 글자(쌍행소주, 나경도 안 글자)는 확대해도 한계가 있고, 나경도 안 글자는 지침대로 전사하지 않습니다. "최적화" PDF 는 쪽마다 해상도가 다를 수 있습니다(실측: 같은 책에서 300dpi 와 150dpi 쪽이 섞임). 300dpi 쪽 이미지가 따로 있으면 그 PDF 를 만들어 쓰는 편이 낫습니다.
- 入/人처럼 인쇄 자체가 오자인 자리는 모델이 자형대로 읽기도, 문맥대로 고쳐 읽기도 합니다. 3차 판별은 자형만 묻지만 최종 판단은 사람 몫입니다.
- 영역 좌표 보정은 1차 판독의 줄 수(열 수)와 영역 순서가 맞다는 전제 위에 섭니다. 글자층이 없고 1차가 줄 수를 잘못 세면 확신이 없어 고치지 않고 모델 좌표를 그대로 씁니다(진행 기록에 "좌표 보정" 줄이 없으면 그 경우).
- 읽기 방향의 자동 판정은 글줄 배치가 흐리거나 가로·세로 글이 섞인 이미지에서 확실하지 않을 수 있습니다. 판정 결과와 원본을 확인하고 필요하면 [설정]에서 읽기 방향을 직접 고르십시오. 인쇄 쪽수 차이는 PDF 글자층을 활용하므로 글자층이 없으면 직접 확인해야 합니다. 판정 결과는 결과 폴더(state.json)에 남습니다.
- 모델이 주는 도판 좌표는 수 픽셀 어긋날 수 있어 외곽 먹 검사로 보정하고, 그래도 닿으면 "판독 확인 필요"에 올립니다.
- 손글씨 밑줄·동그라미는 글자로 옮기지 않도록 지시했지만 검수에서 확인이 필요합니다.
- HWPX 의 글꼴·문단 모양은 python-hwpx 기본 서식입니다.
