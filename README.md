# YeonE_OCR · 연어OCR

세로쓰기 한자·한글 혼용 문헌(풍수·역학서 등 스캔 PDF)과 가로쓰기 한문(간체) 문헌을 `yeone_ocr/지침.md`에 따라 OCR·교정해 **HWPX**로 만드는 PC 프로그램입니다.
글자는 **Gemini**가 읽고, 프로그램은 영역 잘라내기·두 판독 비교·3차 글자 판별·문서 조립·상태 기록을 맡습니다.
쓰는 법은 **PDF 고르기 → [▶ 한 번에 인식]** 두 번입니다. 읽기 방향·인쇄 쪽수 차이·이전 판 기록 갱신·2차 비교·3차 판별·문서·검수 화면·보고를 프로그램이 알아서 이어서 합니다.

## 시작하기 (Windows)

1. **Python 설치** — https://www.python.org/downloads/ 에서 받아 설치합니다. 설치 첫 화면의 "Add python.exe to PATH" 를 체크하십시오. (3.10 이상)
2. **코드 받기** — https://github.com/kyengilam-coder/YeonE_OCR 에서 "Code → Download ZIP" 으로 받아 `C:\Projects\YeonE_OCR` 에 풉니다. git 이 있으면 `git clone https://github.com/kyengilam-coder/YeonE_OCR.git C:\Projects\YeonE_OCR` 로 받고, 새 판은 그 폴더에서 `git pull` 로 받습니다. 창 머리 오른쪽의 `v0.x.y` 와 진행 기록 첫 줄의 "프로그램 위치"로 어느 판이 떠 있는지 확인할 수 있습니다.
3. **`YeonE_OCR.pyw` 더블클릭** — 창이 뜹니다. 뜨지 않으면 `YeonE_OCR.bat` 을 더블클릭하십시오(오류 글이 보입니다).
4. **[필요한 패키지 설치·점검]** — 처음 한 번. 아래 "진행 기록"에 설치 과정이 흐르고, 끝나면 오른쪽 아래에 "패키지 모두 있음"이 뜹니다.
5. **API 키** — https://aistudio.google.com/apikey 에서 키를 만들어 "Gemini API 키" 칸에 통째로 붙여 넣고 **[키 확인·모델 고르기]**. 키가 맞는지 Gemini 에 확인하고, 쓸 수 있는 모델 목록에서 고릅니다(pro 계열이 품질, flash 계열이 속도·비용). 키는 내 PC의 `사용자 폴더\.yeone_ocr\config.json` 에만 저장됩니다.
6. **[PDF 고르기…]** → **[▶ 한 번에 인식 (PDF → HWPX)]**. 이것이 기본 동작이고 보통은 이것만 누르면 됩니다. 쪽 범위를 비워 두면 전체, `1-5` 처럼 적으면 그 쪽만 합니다.
   읽기 방향("자동 판정")과 "인쇄 쪽수 = PDF 쪽수 + N"(빈 칸)은 PDF 글자층으로 프로그램이 판정해 결과 폴더에 적어 둡니다. 틀리게 판정했을 때만 직접 고르거나 적으십시오.
   쪽이 많으면 오래 걸립니다(쪽당 30초~1분). **[■ 중지]** 로 멈춰도 끝난 쪽은 남고, 다시 누르면 남은 쪽부터 이어서 합니다.
7. 끝나면 **[HWPX 열기]** 로 결과를 보고, **[검수 화면 열기]** 로 원본과 대조합니다. 〔 〕 로 남은 자리만 사람이 보면 됩니다.
   단계별 단추(①~⑥)와 도구는 **"고급 — 단계별 실행·도구"** 를 펼쳤을 때만 보입니다. 일부 단계만 다시 하거나 기록을 손볼 때 씁니다.

결과는 PDF 와 같은 폴더의 `<PDF 이름>_YeonE_OCR\` 안에 생기고, 전체를 넣은 HWPX 는 `out\<PDF 이름>.hwpx`, 일부만 넣은 것은 `out\<PDF 이름>_p001-005.hwpx` 입니다.

## 단추가 하는 일

| 단추 | 하는 일 |
|---|---|
| ▶ 한 번에 인식 (PDF → HWPX) | 기본 동작. 준비 → 읽기 방향·인쇄 쪽수 차이 자동 판정 → 이전 판 기록 갱신(모델 호출 없음) → 판독(1차·2차) → 3차 글자 판별 → 문서 → 검수 화면 → 보고·혼동 장부. 먼저 예상 비용을 보여 주고 [계속 실행]을 묻습니다. **■ 중지** 는 지금 쪽이 끝나면 멈춥니다(끝난 쪽은 남음). 다시 누르면 기록이 있는 쪽은 건너뛰고 이어서 합니다. |
| 읽기 방향 | "자동 판정"(기본)이면 PDF 글자층의 세로 열·가로 줄 글자 수로 세로쓰기 한자·한글 / 가로쓰기 한문(간체)을 고르고 결과 폴더(state.json)에 적어 둡니다. 비교 다시 계산·3차 판별·책갈피 OCR 이 같은 값을 따릅니다. 글자층이 없으면 세로쓰기(지침 기본). |
| 고급 — 단계별 실행·도구 | 아래 ①~⑥ 과 도구 단추를 펼칩니다. 보통은 필요 없습니다. |
| ① 구조 보기 | 쪽수, 쪽마다 스캔 이미지인지, 기존 텍스트 레이어 글자 수, 쪽번호 표기를 보여 줍니다. |
| ② 준비 | 쪽 이미지(내장 스캔을 재압축 없이)와 기존 텍스트 레이어를 결과 폴더에 꺼냅니다. |
| ③ 판독 | (기록이 있는 쪽은 건너뜀. "기록 있는 쪽도 다시 판독" 을 켜면 덮어씀) Gemini 가 쪽 전체로 영역을 나누며 1차 판독하고, 문자 영역을 확대해 2차 독립 판독한 뒤 열 단위로 비교합니다. 다른 자리는 `〔甲/화〕`·`〔疑: ○〕` 로 표시됩니다. 기존 텍스트 레이어와의 차이와 구조 검사 결과도 기록합니다. |
| ④ 문서 만들기 | 도판을 원본 이미지로 잘라(외곽 잘림 자동 보정) HWPX(+DOCX)를 만들고 파일 구조를 다시 검사합니다. 문서에는 OCR 본문(제목·문단·도판·표)만 들어가고, 의심 자리는 본문 안에 붉은 글자·노란 형광펜으로만 표시됩니다. 확인 항목 목록은 검수 화면(⑤)에 있습니다. 원하면 "쪽 끝 확인 목록"을 켜 문서 끝에도 넣을 수 있습니다. |
| ⑤ 검수 화면 열기 | `review.html` — 왼쪽 원본 이미지 위에 모델이 나눈 영역 상자와 "영역 밖 글줄 흔적"(붉은 점선)을 그려 주고, 오른쪽에 판독문·확인 필요 목록·기존 OCR 차이·구조 검사를 보여 줍니다. |
| ⑥ 보고 보기 | `report.md` — 쪽별 상태와 **다발 오인식 장부**(어느 글자가 어느 글자로 읽혔는지)를 "진행 기록"에 보여 줍니다. |
| 3차 글자 판별 | 1차·2차가 갈린 `〔a/b〕` 자리마다 그 글자 하나를 ±2자 창으로 크게(6배) 잘라 모델에 **자형만으로** 묻습니다(자리마다 호출 한 번). 획이 보이면 확정해 본문에 넣고 확인 목록에 "3차 판별" 메모를 남기며, 보이지 않으면 표시를 그대로 둡니다. [비교 다시 계산] 뒤에도 확정은 유지됩니다. |
| 혼동 장부 | `confusion.json` — 결과 폴더의 판독 기록(1차↔2차 갈림, 판독↔글자층)과 책갈피 OCR 대조(HWPX↔판독)에서 글자 쌍 빈도를 모읍니다(모델 호출 없음). 혼동 묶음 후보도 알려 줍니다. |
| 결과 폴더 열기 / HWPX 열기 | 탐색기·한컴오피스로 엽니다. |
| 검수 결과 기록… | 사람이 대조를 마친 쪽에 "원본 대조 완료(사람)" 을 남깁니다. 프로그램은 이 상태를 스스로 붙이지 않습니다. |
| 비용 미리 보기 | 쪽 수·이미지 크기·지침 길이로 호출·토큰을 어림하고 금액(달러·원)까지 바로 보여 줍니다. 단가는 내장 요금표(Gemini 3.1/3/2.5 계열, 캐시 입력 단가 포함)에서 모델 이름으로 찾고, 환율은 자동 조회합니다(실패 시 1,400원). 이미 판독한 쪽이 있으면 그 실측(모델별)으로 보정합니다. 요금이 바뀌었을 때만 대화 상자에서 고쳐 저장하면 됩니다. [▶] 를 누르면 같은 내용을 먼저 보여 주고 [계속 실행] 을 묻습니다. |
| 비교 다시 계산 | 저장된 1차·2차 판독으로 확인 표시만 다시 만듭니다(모델 호출 없음). [▶ 한 번에 인식] 이 이전 판 기록을 만나면 저절로 하므로 보통은 누를 일이 없습니다. `merged` 를 손으로 고친 내용은 사라집니다. |
| 필요한 패키지 설치·점검 | `pip install -r requirements.txt` 를 대신 실행합니다. |
| 키 확인·모델 고르기 | 키가 쓸 수 있는지 확인하고, 쓸 수 있는 모델 이름 목록에서 고릅니다. 키·권한·모델 이름 오류는 알기 쉬운 한 줄로 알려 줍니다. |

"쪽별 상태" 탭에서 쪽마다 상태·확인 필요 건수·도판 수를 봅니다.

## 책갈피 OCR (두 번째 탭) — HWPX 교정

이미 입력된 HWPX 가 있고 같은 책의 PDF 가 있을 때, PDF 원본을 판독해 HWPX 글자와 맞춰 보고 고친 사본을 만듭니다.
창 위의 두 번째 탭 **[책갈피 OCR]** 에서 합니다. 책갈피가 든 원본 PDF 와 교정할 HWPX 를 이 탭에서 고르고, 판독기·모델·API 키·속도·읽기 방향은 첫 탭의 설정을 씁니다(읽기 방향은 자동 판정).

**기본 동작은 [▶ HWPX 전체 교정] 입니다.** [PDF 고르기…] → [HWPX 고르기…] → [▶ HWPX 전체 교정] 을 누르면 구획을 차례로 전부 대조해 사본 `<이름>_교정.hwpx` 하나에 고쳐 넣고
`collate/_전체_요약.html` 에 구획별 자동 교정·표시 건수와 건너뛴 구획(PDF 쪽을 못 찾음)을 적습니다. 기록이 없는 쪽은 모델로 읽고(있으면 안 부름), 入/人·曰/日 같은 자형 편향 자리는 그 글자 조각을 모델에 다시 물어 인쇄가 HWPX 글자면 차이에서 빼고 판독 글자면 교정 후보로 올립니다(못 가리면 표시만).
구획 전체 대조에서는 급과 무관하게 바로 다음 기준 직전까지를 한 구획으로 보아 겹침·빠짐이 없습니다. 아래는 구획 하나만 할 때의 설명입니다.

1. **[PDF 고르기…]**, **[HWPX 고르기…]** → "책갈피로 쓸 스타일" 확인 → **[구획 색인]**. HWPX 에 한컴 책갈피가 없어도 됩니다. HWPX 를 고르면 이름에 '제목'이 든 스타일(예: 제목-장, 제목-본초명, 제목-본초명(소))을 자동으로 채워 주고, **[스타일 고르기…]** 에서 문단 수를 보며 바꿀 수 있습니다(앞에 적은 스타일이 큰 단위). 제목 스타일조차 없는 문서는 기준을 'PDF 책갈피 이름으로 HWPX 본문 검색'으로 바꾸면 PDF 책갈피 이름을 본문에서 찾아 구획으로 삼습니다.
   "찾기" 칸에는 한자뿐 아니라 **한글 독음**(대계 → 大薊, 인삼 → 人參·人蔘, 삼릉/삼능 → 三棱)을 넣어도 됩니다. 표의 독음 열은 참고용 자동 변환입니다. HWPX 의 책갈피(한컴 책갈피)와 제목 스타일 문단(이름에 "제목"이 든 스타일, 예: 제목-장·제목-절·제목-본초명)을 구획 기준으로 뽑고,
   PDF 책갈피와 이름을 맞춥니다(부호·공백·이체자·간체/번체 차이를 접고 비교). 표에 번호·급·HWPX 제목·문단·PDF 책갈피·쪽·짝 상태가 나옵니다. "찾기" 칸으로 거릅니다.
2. 구획을 고르고 **[이 구획 대조만]** 또는 **[이 구획 교정]**. PDF 책갈피 짝이 없는 구획은 PDF 글자층에서 제목을 찾고, 그래도 없으면 PDF 쪽 범위를 물어봅니다.
   그 쪽들을 판독하고(기록이 있으면 모델을 부르지 않음), 구획 제목부터 다음 구획 제목 직전까지만 잘라 HWPX 구획 글과 글자 단위로 맞춥니다.
3. 차이는 네 갈래로 나뉩니다. 비교는 간체 공간에서 하므로 번체 HWPX 와 간체 PDF 사이의 변환 차이는 차이로 세지 않습니다.

| 갈래 | 뜻 | 정책 "전부 자동"(기본)에서 | 문서 표시 |
|---|---|---|---|
| A | 판독이 확실(〔〕 없음)하고 간→번이 1:1 인데 HWPX 와 다름 | 글자 교체·삽입·삭제 | 파란 글자 + 연두 형광펜 + 메모(원래 글자·PDF 쪽) |
| B2 | 간체 한 글자가 여러 번체(发→發/髮, 术→術/朮)로 갈라짐 | 어구 사전으로 고른 번체로 교체, 다른 후보는 메모에 | 파란 글자 + 연두 형광펜 + 메모 |
| C 누락 | HWPX 에 없는 긴 구간(20자 이상)이 PDF 에 있음 | 판독 글을 그 자리에 삽입 | 파란 글자 + 연두 형광펜 |
| B1 | 그 자리의 판독이 불확실(〔疑〕·〔a/b〕) | 글자 그대로 둠 | 빨간 글자 + 노란 형광펜 + 메모(판독 후보) |
| C 그 밖 | PDF 에 없는 긴 구간, 여러 글자 차이 | 그대로 둠 | 빨간 글자 + 노란 형광펜 + 메모 |
| D | 부호·띄어쓰기·이체자(參/蔘)만 다름 | 무시 | 없음 |

   정책을 "확실한 것만"으로 바꾸면 A 만 고치고 B2 도 표시만 합니다. "메모만"은 아무 글자도 바꾸지 않습니다. "한컴 메모로 근거 남기기"를 끄면 글 뒤에 〔원: ○〕 처럼 짧게 적습니다.
4. 결과는 원본 옆에 `<이름>_교정.hwpx` 로 저장됩니다(원본은 그대로). 여러 구획을 이어서 교정하면 같은 사본에 쌓입니다.
   대조 보고 `<작업 폴더>/collate/<구획>.html` 에 갈래별 표와 HWPX·판독 원문 대조가 있습니다. **[보고 열기]**, **[교정본 열기]** 단추로 엽니다.

于·干·於·幹·乾 묶음은 판독기가 자주 섞으므로 따로 다룹니다. 지시문에서 자형·문맥을 다시 확인하게 하고, 대조에서는 HWPX 앞뒤 글자의 문맥 규칙(生於·從於 ↔ 能幹·乾薑)과 PDF 글자층(다른 OCR 엔진의 글자)을 증인으로 삼아 어느 쪽이 맞는지 가립니다. 못 가리면 표시만 합니다. 글자층 증인은 다른 한 글자 차이에도 적용되어, 글자층이 HWPX 와 같으면 판독 오류로 보고 차이에서 뺍니다.

한계: 1:多 묶음 안에서 HWPX 가 다른 번체를 쓴 경우(乾薑↔幹薑)는 간체로 접으면 같아져 비교로 잡히지 않습니다. 교정본은 한컴에서 열어 메모와 색 표시를 확인하며 받아들이십시오.
명령줄: `yeone-ocr collate <pdf> --hwpx <hwpx> --all --apply`(전체 교정), `--list`(구획 목록), `--section "大薊" --apply`(구획 하나). `--no-glyph-check` 면 자형 3차 판별을 하지 않습니다.

## 0.6.1 — 첫 실측(중의역대약론선 130·131쪽)에서 드러난 결함을 고침

- **영역 좌표 보정**: Gemini 가 준 영역 좌표가 글이 빽빽한 쪽에서 아래로 갈수록 밀렸습니다(130쪽 맨 아래 영역 7.8% = 글줄 4개). 그대로 쓰면 2차 조각이 이웃 인용문을 읽어 가짜 차이가 쏟아지고(확인 필요 77건), 3차 판별도 엉뚱한 글자를 보고 확정했습니다. 이제 1차 판독 직후 영역 좌표를 글자층 줄 위치(가장 정확)나 쪽의 먹 띠(글줄)에 맞춘 뒤 조각을 자릅니다. 고친 내역은 기록(bbox_fix)과 진행 기록("좌표 보정 — …")에 남습니다.
- **이전 기록 자동 재판독**: 좌표가 2% 넘게 밀려 있던 이전 판 기록은 `readings/stale/` 로 옮기고 다시 판독합니다. 조금 밀린 기록은 좌표만 고쳐 다시 비교합니다(모델 호출 없음).
- **가로쓰기 덮개 검사**: 영역 밖 글을 줄 단위로 찾습니다(머리글 한 줄이 글자 수만큼 "글 기둥" 20건으로 쪼개지던 잡음 제거). 쪽 가장자리 줄은 머리글·쪽번호로 보고 본문에 붙이지 않습니다.
- **2차 묶음 호출**: 한 호출에 조각 8장까지만 넣고(`--batch-crops`), 돌아온 글이 제 영역의 1차 글과 안 맞고 다른 영역과 맞으면 버리고 낱개로 다시 읽습니다(모델이 조각과 영역 번호를 섞는 일 대비).
- **3차 판별 자리 검사**: 모델에게 조각에 보이는 글 전부(w)도 적게 하고, 기대한 앞뒤 글자와 이어지지 않으면 확정하지 않습니다(조각이 엉뚱한 자리면 "조각 위치가 어긋남"으로 보류).
- **인쇄 쪽수 차이 자동 판정 보강**: 머리글·꼬리글 자리의 숫자만인 줄(114)도 쪽번호로 봅니다. 글자층으로 못 정하면 판독한 쪽번호가 2쪽 이상 모이는 대로 판정해 결과 폴더에 적고, 어긋난 쪽을 표시합니다. 화면의 "인쇄 쪽수" 칸은 비우거나 0 이면 자동입니다.

## 인식률을 위해 0.6.0 에서 바뀐 것

중의역대약론선 결과 폴더(판독 9쪽·대조 4구획)와 HWPX 85만 자·300dpi 쪽 이미지를 실측한 결과를 바탕으로 고쳤습니다.

- **2차 조각을 작게**: 가로쓰기 모드에서 조각을 좌우로만 넓히고 위·아래는 글줄 사이 공백에 맞춥니다(이웃 줄을 끌어들여 "1차 판독에 없고 2차에만 있음"이 확인 목록의 65%를 차지하던 과확장 방지). 글줄(세로쓰기는 열)이 "2차 조각 한 장에 N줄"(기본 8)을 넘으면 나눠 보내고 돌아온 열을 이어 붙입니다. 글자당 픽셀이 늘어 획 하나 차이(入/人·曰/日·于/干)를 가립니다. 쪽 전체 확대는 그대로 두되 조각 긴 변은 3000px 안으로 둡니다(모델이 그 이상은 줄여 버림).
- **조각 고해상**: 2차 판독기에 `media_resolution=high`(Gemini 이미지 토큰 예산)를 씁니다. 모델이 거부하면 자동으로 기본값으로 돌아갑니다.
- **혼동 글자 카드**: 지침 7·8·14장의 목록을 "자형 기술 + 문맥 단서 + 출력 규칙" 카드로 지시문 끝에 붙였습니다(세로·가로 모드 공통). 자형과 문맥이 어긋나면 `〔자형/문맥〕` 두 후보를 적게 합니다.
- **3차 글자 판별**과 **혼동 장부**(위 표). [▶ 한 번에 인식] 안에 들어 있어 따로 누르지 않아도 됩니다(`--no-adjudicate` 로 끔).
- **한 번에 인식·전체 교정**: 사용자가 단계와 설정을 이해하지 않아도 되게 했습니다. 읽기 방향과 인쇄 쪽수 차이는 PDF 글자층으로 판정해 결과 폴더에 적고, 이전 판으로 만든 판독 기록은 지금 규칙으로 저절로 다시 비교하며, 단계별 단추는 "고급"으로 접었습니다. 책갈피 OCR 은 구획 전체를 한 단추로 대조·교정하고 요약을 남깁니다. 빠진 패키지는 켤 때 설치할지 묻습니다.
- **글자층 대조에서 부호 접기**: 전각·반각 부호(，↔,)와 `〔〕` 표시는 차이로 세지 않습니다(실측에서 글자층 차이의 60%가 부호였음).
- **책갈피 OCR 대조 규칙**:
  - 이체자 표 보강(澁·沈·汚·昻·濬·擧·脇·袪·塡·巓·愼·蔲·苢·着) — "확실한 오탈(A)"로 잘못 잡혀 HWPX 표기를 바꾸던 가짜 차이(실측 A 의 30%)가 사라집니다.
  - 아라비아 숫자만인 삽입·삭제(인용 번호 1. 2. 3.)는 표기 차이로, 숫자와 글자가 섞인 치환(「本草」→「4」)·한자 숫자만의 삽입·삭제·각주(注1…) 삽입·서명(『』) 일부로 보이는 짧은 삭제(「本草」綱目)는 표시만 합니다.
  - HWPX 쪽에만 한글이 있는 자리(편집자의 풀이)는 어떤 정책에서도 자동 반영하지 않습니다.
  - 入/人·曰/日·土/士·未/末·己/已/巳·大/太/犬·白/自 는 OCR 엔진들이 같은 방향으로 틀리고 인쇄 자체가 오자인 일도 있어, 한 글자 차이를 자동 교정하지 않고 글자층도 증인으로 쓰지 않습니다(3차 판별로).
  - 같은 (HWPX, 판독) 한 글자 쌍이 한 구획에서 5회 이상 되풀이되고 문맥으로 못 가리면(간체 于를 幹으로 일괄 변환한 HWPX 등) 책 전체의 변환 오류로 보고 교정 후보로 올립니다.
  - 혼동 묶음 보강(府腐·山由·失尖·信倍·届属·镇慎·宜宣·囊裹·胀脓·恶悉, 疒·艹·木·月 부수 가족 등), 구획 제목이 되풀이된 줄 제거, 보고와 json 에 기준 HWPX 파일(원본인지 교정본인지) 기록.
- 2차 판독의 사용량 필드를 한 번 그대로 진행 기록에 적습니다(생각 토큰이 0 으로만 기록되던 원인 확인용).

## 지침과의 대응

- 영역 분류(3장) → 모델 출력 스키마로 강제. 도판은 글자를 적지 못하게 하고 좌표만 받습니다(9~11장).
- 읽기 순서(4장) → 열마다 "오른쪽에서 n번째" 번호와 위→아래 글을 받고, 열 바꿈은 아무것도 넣지 않고 잇습니다(18장).
- 판독 불명(19장) → `〔판독불명〕〔疑: ○〕〔○/△〕〔원본 결락〕` 과 위치(쪽·열·구간)를 함께 기록. 2차 판독과 다른 자리는 자동으로 표시.
- 기존 OCR(20장) → 참고용 차이 목록만, 자동 반영 안 함.
- 구조 검사 → 괘상 ASCII 대체, 한글 자모 분리, 쪽번호 혼입, 그림 안 글자 전사, 괄호 불균형, 표 셀 수 불일치, 인쇄 쪽수 불일치.
- HWPX(23장) → 실제 OWPML 구조로 만들고 다시 열어 그림 수·구조를 검사. 확장자만 바꾼 파일은 걸립니다.
- 보고(33장) → 프로그램은 자동 OCR 범위만 완료로 적고, "원본 대조 완료(사람)" 은 사람만 붙입니다.

## 속도 (정확도는 그대로)

- **동시 판독(자동 조절)**: 4쪽에서 시작해 10쪽 연속 문제없으면 하나씩 늘리고(최대 6, 설정 가능), 한도 초과(429)가 보이면 하나 줄이고 20초 쉽니다. 쪽별 기록은 독립이라 결과는 같습니다.
- **2차 판독 묶음 호출**: 한 쪽의 문자 영역 조각들을 한 호출로 보냅니다(기본). 확대 조각은 그대로라 정확도는 같고, 호출 수와 지침 재전송이 절반 이하로 줍니다. 빠진 영역은 자동으로 낱개 호출합니다.
- **지침 캐시**: 호출마다 보내던 지침 전문(약 9천 토큰)을 Gemini 컨텍스트 캐시에 올려 참조합니다. 모델이 지원하지 않으면 자동으로 일반 호출로 돌아갑니다. 진행 기록 첫 줄에 "지침 캐시 사용/미사용"이 찍힙니다.
- **2차 판독 모델 `auto`(기본)**: 1차와 같은 세대의 flash 모델(lite 제외, 정식판 우선)을 자동으로 골라 2차 전사에 씁니다. 빠르고 싸며, 서로 다른 모델이 읽어 독립성이 오히려 커집니다. 두 판독이 다른 자리는 모두 표시되므로 안전합니다. 비우면 1차와 같은 모델을 씁니다.
- **2차 생각 줄이기(기본 켬)**: 2차는 확대 조각의 순수 전사라 깊은 생각이 필요 없습니다. 3.x 는 thinking_level LOW, 2.5 는 thinking_budget 512 로 보냅니다. 모델이 거부하면 자동으로 기본값으로 돌아갑니다. 1차(영역 분류)는 모델 기본 그대로 둡니다.
- **이전 판 설정**: 0.4.0 이하에서 저장한 설정(동시 3, 2차 모델 비움)은 처음 실행할 때 새 기본값(동시 6 자동 조절, 2차 `auto`)으로 올려 줍니다. 직접 바꾼 값은 그대로 둡니다.
- **짧은 JSON 키**: 모델이 돌려주는 JSON 의 키를 짧게(n, t, cols, paras…) 해 출력 토큰을 줄였습니다. 저장 파일(readings/*.json)은 읽기 쉬운 긴 이름 그대로입니다.

## 긴 PDF (수백 쪽)

- **중간 저장**: "중간 저장 N쪽마다"(기본 20) 판독이 진행될 때마다, 그리고 중지·오류로 멈출 때 `out\<PDF 이름>_진행중.hwpx` 를 다시 만듭니다. 최종 문서가 만들어지면 진행중 파일은 지웁니다.

- 쪽마다 기록이 남으므로 **중단·재개**가 됩니다. [■ 중지] 뒤 다시 [▶] 를 누르면 기록이 있는 쪽은 건너뛰고 이어서 합니다.
- 한 쪽이 일시 오류(응답 형식 불량 등)로 여러 번 실패하면 그 쪽만 건너뛰고 계속하며, 끝에 실패한 쪽 번호를 알려 줍니다. 다시 [③ 판독] 을 누르면 그 쪽들만 다시 시도합니다. 키·권한·모델·한도 0 같은 오류는 전체를 멈춥니다.
- 10쪽마다 쪽당 소요 시간과 남은 시간을 진행 기록에 적습니다. 700쪽이면 쪽당 30초~1분 기준 6~12시간입니다.
- 도판은 JPEG 로 넣어 수백 장이 들어가도 문서가 지나치게 커지지 않습니다. 권별로 나누려면 명령줄 `--split 200`(200쪽씩) 을 쓰십시오.
- [비용 미리 보기] 가 호출·토큰·금액을 어림합니다. 몇 쪽을 먼저 돌려 실측이 쌓이면 그 평균으로 더 정확해집니다.

## 알려진 한계

- 글자 정확도는 모델에 달려 있습니다. 153dpi 스캔의 작은 글자(쌍행소주, 나경도 안 글자)는 확대해도 한계가 있고, 나경도 안 글자는 지침대로 전사하지 않습니다. "최적화" PDF 는 쪽마다 해상도가 다를 수 있습니다(실측: 같은 책에서 300dpi 와 150dpi 쪽이 섞임). 300dpi 쪽 이미지가 따로 있으면 그 PDF 를 만들어 쓰는 편이 낫습니다.
- 入/人처럼 인쇄 자체가 오자인 자리는 모델이 자형대로 읽기도, 문맥대로 고쳐 읽기도 합니다. 3차 판별은 자형만 묻지만 최종 판단은 사람 몫입니다.
- 영역 좌표 보정은 1차 판독의 줄 수(열 수)와 영역 순서가 맞다는 전제 위에 섭니다. 글자층이 없고 1차가 줄 수를 잘못 세면 확신이 없어 고치지 않고 모델 좌표를 그대로 씁니다(진행 기록에 "좌표 보정" 줄이 없으면 그 경우).
- 읽기 방향·인쇄 쪽수 차이의 자동 판정은 PDF 글자층(기존 OCR)에 기댑니다. 글자층이 없는 PDF 는 세로쓰기로 보고 쪽수 차이는 검사하지 않으므로, 가로쓰기 한문인데 글자층이 없으면 읽기 방향을 직접 고르십시오. 한 번 판정한 값은 결과 폴더(state.json)에 남아 다음에도 쓰입니다.
- 모델이 주는 도판 좌표는 수 픽셀 어긋날 수 있어 외곽 먹 검사로 보정하고, 그래도 닿으면 "판독 확인 필요"에 올립니다.
- 손글씨 밑줄·동그라미는 글자로 옮기지 않도록 지시했지만 검수에서 확인이 필요합니다.
- HWPX 의 글꼴·문단 모양은 python-hwpx 기본 서식입니다.
