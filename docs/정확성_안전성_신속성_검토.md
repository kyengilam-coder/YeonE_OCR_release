# 정확성·안전성·신속성 검토 (0.6.7 기준) — 그리고 0.6.8 에서 고친 것

이 문서는 0.6.7 까지의 실행 기록(커밋 이력, 두 연구 문서, 실측 기록)과 코드를 **정확성·안전성·신속성** 세 갈래로 따로 검토한 결과입니다.
갈래마다 독립된 검토자가 코드를 읽고 실행해 결함을 찾았고, 겹친 결론과 상위 지적은 다시 코드로 확인하거나 재현했습니다.
이 환경에는 Gemini API 키가 없어 **모델 정확도는 재지 못했습니다.** 속도 수치는 합성 스캔(2480×3508, 4코어) 실측과 코드 기반 추정입니다.

## 0. 결론

- 코드 자체는 안정적입니다. 0.6.7 시험 211개는 tkinter 가 없는 환경의 GUI 시험 4개 말고 모두 통과했습니다.
- 그러나 실제 Gemini 로 확인한 것은 중의역대약론선 2쪽(130·131쪽)과 도판 1건뿐이고, **정답과 맞춰 본 정확도 수치가 없습니다.** 실제 책을 돌릴 때마다 새 결함 부류가 나왔습니다(좌표 밀림 → 하루 한도 재시도 낭비 → 도판 반쪽).
- 그래서 가장 큰 개선은 새 기능이 아니라 **측정 체계**와 **조용히 틀리는 경로를 막는 일**이었습니다.

## 1. 정확성

| 심각도 | 지적 | 위치(0.6.7) | 0.6.8 |
|---|---|---|---|
| 높음 | 1차가 〔疑: ○〕 를 단 글자 바로 곁에서 2차와 갈리면 갈림이 표시 없이 1차 글자로 들어감. 재현: 「能入〔疑: 肝〕經血分」 ↔ 「能人肝經血分」 → 入/人 표시 없음 | `merge.py` merge_passes·diff_mark | 고침: 표시는 두고 곁 글자만 따로 비교(`_merge_marked`) |
| 높음 | 책갈피 교정 기본 정책 "전부 자동"이 1:1 혼동 쌍(問/間·卯/卵·王/玉 …)을 자형 확인 없이 사람 원고에 덮어씀(시험이 이 동작을 의도로 고정) | `collate/collate.py` | 고침: 혼동 쌍은 B1 → 3차 자형 판별, 기본 정책 sure |
| 높음 | OCR 에만 있는 20자 이상 구간을 정책 all 에서 원고에 자동 삽입(1차만 읽은 구간·겹쳐 읽은 열·구획 자르기 오류가 섞일 수 있음) | `collate/collate.py` | 고침: 어느 정책에서도 삽입 제안만 |
| 유효 | 연구 문서의 네 빈틈: 1차=2차 상관 오류 미표시, 바탕 글이 저해상 1차, 〔疑〕·3자 이상·긴 구간은 3차로 안 감, CER 측정 없음 | `merge.py`, `adjudicate.py` | 측정은 `yeone-ocr eval` 로 해결. 1차=2차 상관 오류는 **합의 판독 의심**(글자층과 자형 혼동 쌍 한 글자 차이를 3차처럼 묻고 확인 항목만, 본문 불변)으로 일부 표시. 나머지는 측정 뒤 |
| 중간 | 같은 영역 안 2차 조각이 뒤바뀌면 못 잡음(영역 id 만 비교) | `cli._misassigned` | 고침: 묶음 응답의 조각 차례를 1차 글 안 위치로 검사, 갈린 조각은 낱개로 다시 읽어 가림(`cli._chunk_check`) |
| 중간 | NFC 가 U+FA0E~FAFF 호환 한자(塚·諸·者)를 표준 글자로 접어 이체자가 사라짐(지침 21) | `cli.nfc_reading`, `merge._norm` | 고침: 저장은 원형, 비교만 접음 |
| 중간 | 가로쓰기에서 1차 번체·2차 간체가 접혀 같아지면 1차 번체가 표시 없이 저장 | `merge.py` FOLD_ZH | 고침: 표기 차이 확인 항목 |
| 중간 | 좌표 보정이 되풀이되는 첫 줄에 걸려 빠진 영역까지 상자를 넓힘 | `refit.refit_by_layer` | 고침: 줄 수가 맞는 짝만, 아니면 손대지 않음 |
| 중간 | 글자층 증인이 B1 혼동 항목을 승격해 3차 자형 판별을 우회 | `collate/run.py` 순서 | 고침: 3차 먼저, 글자층 승격은 3차를 못 할 때만 |
| 낮음 | 3차 다시 적용이 앞뒤 글자 확인 없이 가장 가까운 같은 표시를 바꿈 | `adjudicate.apply_choice` | 고침: 앞뒤 글자 일치 요구, 못 찾으면 unmapped |

## 3. 신속성

쪽당 CPU 는 2~5초뿐이라 벽시계는 API 지연과 출력 토큰이 지배합니다. 300쪽 기준 추정입니다.

| 항목 | 절감 | 정확도 위험 | 0.6.8 |
|---|---|---|---|
| 준비 전부 선행 → 판독과 나란히 | 7~15분 | 없음 | 적용 |
| 동시 상한 6 → 8 | 40~75분 | 없음(429 자동 조절) | 적용 |
| 업로드 PNG 빠른 압축 | 5~10분 | 없음(무손실) | 적용 |
| Gemini 3 에서 1차 2배 확대 생략 | 2~5분 | 없음(토큰 예산 고정) | 적용 |
| 2차 묶음 고르게·실패 시 반분 | 한도 폭주일 5~20분 | 없음 | 적용 |
| 1차 생각 수준 LOW/MEDIUM | 25~60분, pro 출력비 약 40% | **있음** | 측정 뒤(`eval`) |
| 3차 flash 우선(`--adjudicate-model auto`) | 10~20분, pro 하루 한도 절약 | **있음** | 측정 뒤 |

연구 문서의 수치 두 곳을 정정합니다. 중간 저장이 판독을 막는 시간은 "몇 분~십여 분"이 아니라 실측상 300쪽 전체에서 1분 미만입니다(HWPX 조립 4.5ms/쪽). 글자층 대조의 O(n²) 우려도 실측 8ms(3,000자)로 없습니다.

## 4. 다음 순서

1. **잽니다.** 사람이 입력한 HWPX 가 있는 책에서 표본 20~40쪽을 `yeone-ocr eval` 로 재고, `diffs.html` 에서 차이 200건을 판정해 `labels.json` 으로 보정합니다.
2. 그 숫자로 정할 것: 1차 생각 수준, 3차 flash 우선, 2차·1차 `ultra_high`, 역할 교대(1차 flash·2차 pro). 같은 표본을 `--work` 만 바꿔 돌려 비교합니다(연구 문서 `docs/인식률_제고_방안.md` 의 채택 규약).
3. 그다음 합의 판독 의심·조각 차례 검사의 효과를 같은 표본으로 잽니다(확인 항목 정밀도, 추가 호출 수). 연구 문서 단계 3 의 나머지 신호(장부 편향 묶음, 글자층 대비 1~2자 삽입·삭제, 〔疑〕·3자 이상 갈림의 3차 회부)는 그 숫자를 보고 정합니다.

## 5. 0.6.8 개발 중 검토 기록

0.6.8 은 갈래별 구현 → 적대적 검토(지적마다 다른 검증자가 재현해 반박을 시도) → 고침을 두 번 되풀이했습니다.

| 회차 | 확인된 결함 | 대표 |
|---|---|---|
| 1차 검토(구현 직후) | 31건(반박 1건 제외) | 같은 표시가 한 줄에 두 번 나오면 병합이 글자를 지움(새로 생긴 결함, 무작위 입력 4만 건으로 다시 확인), 책갈피 교정의 긴 구간이 치환으로 묶여 자동 삽입, 2차 일부 실패 쪽이 '완료' |
| 2차 검토(두 번째 단계 뒤) | 26건 | 합의 의심 단계 오류 때 값 치른 3차 판정이 저장되지 않음, 책갈피 교정이 1차만 읽은 영역으로 사람 원고를 고침, 조각 차례를 1차 위치로 옮기면 1차 차례 오류가 숨음 |

모든 고침에는 고치기 전 코드에서 실패하는 회귀 시험을 붙였습니다. 시험은 0.6.7 의 211개에서 0.6.8 의 410개로 늘었고, tkinter 가 있는 환경(가상 화면)에서 창 시험까지 모두 통과합니다.
