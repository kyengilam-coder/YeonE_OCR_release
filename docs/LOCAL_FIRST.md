# 로컬 우선 인식과 선택 구간 AI 검증

현재 개발 소스의 **일반 OCR·이미지 OCR·`run` 기본 경로는 `local-first`**다. 설치된 로컬 엔진으로 먼저 읽고, 불일치하거나 어려운 구간에만 선택한 Gemini·OpenAI·Claude API를 사용한다. 기존 설치 파일에는 이 소스 변경이 반영되지 않았을 수 있다. 전체 쪽을 AI로 읽는 이전 경로는 `--ocr-strategy ai-full`로 명시한다.

## 처리 순서

1. 원본·쪽 범위·읽기 방향을 확인한다. 이미지 폴더·붙여넣기 묶음은 작업 폴더 `local-input`에 원본 지문으로 이름을 정한 PDF 사본을 만든다. 원본 이미지를 변경하거나 외부로 보내는 단계가 아니다.
2. 설치·언어·메모리 조건에 맞는 엔진을 **PP-OCRv6 → RapidOCR/v5 → EasyOCR → Tesseract** 순서로 하나씩 실행한다. 중국어는 네 엔진, 한글·한자 혼용은 Tesseract가 대상이다. 지원 엔진이 없으면 설치 오류로 기록하며 전체 쪽 AI 판독으로 자동 전환하지 않는다.
3. [자동 선택 정책](AUTOMATIC_OCR.md)으로 한 쪽의 로컬 결과 하나를 선택한다. v6 하나만 설치되어 있어도 진행할 수 있다. 원시 결과·직접 교정·사람의 기준 선택을 보존하며, API 호출 전에 로컬 판독을 저장한다.
4. 선택 결과와 호환되는 최신 엔진 결과에서 어려운 구간을 찾는다. 엔진 간 명시적 불일치, 낮거나 없는 confidence, `�`·`□`·`〔판독불명〕` 등 알 수 없는 글자, 좌표 누락, 글자는 검출하지 못했지만 먹이 있는 지역을 대상으로 삼는다.
5. 대상 구간의 원본 크롭과 제한된 앞뒤 문맥만 API로 검증한다. 깨끗한 높은 confidence 단일 엔진 결과나 위험 신호가 없는 일치 결과는 **API 0회**다. 좌표를 안전하게 연결할 수 없으면 검수 대기로 남긴다. 불일치가 많거나 좌표가 없다는 이유로 전체 쪽 이미지·문장 전체 검증으로 확대하지 않는다.
6. AI 응답은 수정 **제안**으로 저장한다. 비교·교정 창에서 채택·기각하기 전에는 본문을 덮어쓰지 않는다. HWPX·DOCX·검색 PDF·검수 화면·보고는 저장된 판독으로 만들며, 이 경로는 전체 쪽 AI 1·2차 판독·별도 3차 판별·문서 문맥 모델을 추가로 호출하지 않는다.

AI 검증 완료나 높은 confidence는 사람의 원본 대조 완료를 뜻하지 않는다. 서로 다른 엔진의 confidence를 비교하거나 정확도로 표시하지 않는다.

## 어려운 구간의 기준

confidence 경계는 API로 보낼 구간을 정하는 초기 휴리스틱이며 실측 인식률이 아니다. 선택한 기준 엔진의 자체 척도에서만 판단한다.

| 기준 엔진 | 낮은 confidence |
|---|---:|
| Tesseract | 70 미만, 자체 0–100 척도 |
| RapidOCR/v5 | 0.85 미만, 자체 0–1 척도 |
| PP-OCRv6 | 0.85 미만, 자체 0–1 척도 |
| EasyOCR | 0.55 미만, 자체 0–1 척도 |

confidence가 없는 구간도 검증 대상으로 본다. 일부 자형 보완 결과는 원래 모델 점수를 보존하고 최종 confidence를 `null`로 두므로 이 경로에 포함될 수 있다. 단순 검은 선·그림도 먹 검출에 잡힐 수 있다. 이미지 근거가 불명확하면 AI의 불확실 제안과 사람의 검수 상태를 확인해야 한다.

## 호출 상한과 이어 읽기

`--local-ai-max-calls` 기본값은 **이번 명령 전체 20회**다. 쪽별 20회가 아니며, `--max-calls`가 양수이면 두 상한 중 작은 값을 함께 적용한다. 완료한 요청은 원본·쪽·선택 기준·모델·정책·크롭 지문으로 재사용한다. **호출 상한만 바꾸거나 다음 실행의 남은 호출 수가 달라져도 완료한 검증을 다시 구매하지 않는다.** 원본·판독·모델·실제 검증 정책이 바뀌면 재검증 대상이 될 수 있다.

API 키가 없어도 로컬 인식·출력은 진행한다. AI 대상이 남거나 호출 상한·검증 실패로 검증을 마치지 못하면 종료 코드 `4`로 알리고 저장된 결과와 검증 계획을 보존한다. 깨끗해서 대상이 없으면 키가 없어도 성공이다. `--no-local-ai-review`로 로컬 전용을 명시하면 API를 호출하지 않고 로컬 결과를 만들며, 검수할 곳이 있다는 기록을 보존한다.

| 종료 코드 | 뜻 |
|---|---|
| `0` | 선택한 로컬·AI 작업과 출력 완료. 사람 검수 완료를 의미하지 않음 |
| `3` | 일부 쪽의 로컬 인식 실패. 완료된 쪽과 원시 결과는 보존 |
| `4` | 로컬 결과는 있으나 요청한 선택 구간 AI 검증이 대기·미완료 |
| `2` / `130` | 입력·설정 오류 / 사용자 중지 |

출력 생성 자체가 실패하면 해당 출력 오류 코드가 우선한다. 비교 프로젝트는 작업 폴더 `comparison`, 검증 계획은 `local-first-review`, 상태 집계는 `state.json`의 `local_first_last_run`에 남는다. 원문·AI 응답·제안·사람 채택 이력을 구분해 저장한다.

## 명령줄 예

프로젝트 가상환경의 Python으로 실행한다. API 제공사·모델·키 설정은 기존 설정을 사용한다. 키를 명령줄 인수에 넣지 않는다.

```powershell
# 번체 가로쓰기: 로컬 인식 → 어려운 구간만 API → HWPX
.\.venv\Scripts\python.exe -m yeone_ocr run "책.pdf" --local-profile traditional --mode horizontal_zh --work "work\책"

# 로컬 전용. 지원되는 엔진을 설치한 뒤 사용
.\.venv\Scripts\python.exe -m yeone_ocr run "책.pdf" --no-local-ai-review --local-engine-root "C:\OCR엔진"

# 한글·한자 혼용 세로쓰기, 검색 PDF, 이번 실행 최대 5회
.\.venv\Scripts\python.exe -m yeone_ocr run "혼용문헌.pdf" --local-profile mixed --mode vertical --pdf-only --local-ai-max-calls 5

# 이전 전체 쪽 AI 판독 경로를 명시적으로 사용
.\.venv\Scripts\python.exe -m yeone_ocr run "책.pdf" --ocr-strategy ai-full
```

엔진 설치·언어 범위는 [로컬 엔진 안내](LOCAL_OCR.md), 제안·개인 자료 저장 정책은 [AI 검증 안내](AI_REVIEW.md)를 함께 따른다.

## 속도: 상주 작업자와 엔진 병렬 실행

- **상주 작업자**: 로컬 우선 인식은 PP-OCRv6·RapidOCR·EasyOCR 작업자를 실행 동안 띄워 두고, 한 작업자로 최대 16쪽을 읽은 뒤 새로 띄웁니다(기존 세션 규약 그대로). 쪽마다 모델을 다시 올리고 모델 파일 해시를 다시 확인하지 않습니다. 가로쓰기 쪽만 해당하며, 세로쓰기 쪽과 Tesseract는 지금처럼 쪽마다 작업자를 띄웁니다(그 결과에 필요한 후처리가 그 경로에 있음). 끄려면 환경 변수 `YEONE_OCR_RESIDENT_WORKERS=0`.
- **엔진 병렬**: 한 쪽의 엔진들을 동시에 실행합니다. 동시 개수는 코어 4개당 엔진 1개, 빈 메모리(이미 떠 있는 작업자 제외)가 가장 무거운 엔진들의 예산을 넘지 않을 만큼입니다. 결과는 늘 엔진 순서대로 기록하므로 프로젝트·비교·선택 결과는 차례로 실행할 때와 같습니다. `--local-engine-parallel N`(0=자동, 1=차례로) 또는 `YEONE_OCR_ENGINE_PARALLEL`로 정합니다.
- **반복 작업 제거**: 한 쪽 렌더 결과를 엔진·미리보기·AI 조각이 함께 쓰고, 원본 해시는 크기·시각·inode가 그대로이고 2초 넘게 바뀌지 않은 파일에만 재사용합니다. 글꼴 해시는 파일마다 한 번, 프로젝트 중간 저장은 저장 자체가 느려지면 30초 간격으로 줄입니다(쪽 끝 저장은 늘 합니다).
- 실제 속도는 측정하지 않았습니다. 같은 표본에서 `ab_ocr/benchmark.py`로 전후를 재야 합니다.
