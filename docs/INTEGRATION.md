# 연어OCR 0.9.0 통합 기능

연어OCR의 기존 사용자 화면과 AI 판독 흐름에 AB_OCR 0.3.0의 로컬 인식·원본 대조 기반을 연결했다. 기존 세로 문헌 읽기, PDF 책갈피와 HWPX 구획 대조, 이미지·스크린샷 입력, HWPX·DOCX·검색 PDF 출력은 기존 경로를 유지한다. 새 비교 작업은 기존 AI 판독의 전역 설정·취소 상태를 사용하지 않는다.

## 사용 순서

상단 보조 도구줄의 **3엔진 비교·교정**을 누르면 현재 원본을 대상으로 별도 편집 창이 열린다. 일반 OCR에서는 현재 PDF, 책갈피 OCR에서는 해당 탭의 PDF, 이미지 OCR에서는 현재 이미지 또는 이미지 묶음을 사용한다. 원본을 고르지 않았다면 비교 창에서 열 수 있다. 같은 원본의 열린 편집 창이 있으면 그 창으로 돌아간다.

**엔진 폴더…**는 `tools`를 포함하는 상위 폴더를 선택한다. 선택 경로는 공통 설정에 기억하고 다음 비교 창에도 적용하며 **설치 확인**으로 언어·모델 상태를 확인한다. 자동 설치나 다운로드는 하지 않는다. 환경 변수로도 기본 경로를 지정할 수 있다. 자세한 설치·탐색 순서는 [LOCAL_OCR.md](LOCAL_OCR.md)에 있다.

문서 종류는 번체·한문, 간체·중문, 한글·한자 혼용 중에서 고르고 읽기 방향은 가로쓰기·세로쓰기를 명시한다. PDF 렌더링 DPI와 쪽 범위를 선택한 다음 현재 쪽 또는 지정 범위를 실행한다. 빈 쪽 범위는 전체이며 `1-5,8`처럼 범위를 지정할 수 있다. 잘못된 범위를 임의로 넓히지 않는다.

인식과 미리보기 렌더링은 작업 스레드에서 처리한다. 세 엔진은 각 쪽에서 차례로 실행하고 완료한 엔진마다 프로젝트·복구 사본을 저장한다. 중지하면 실행 중인 작업자를 종료하고 완료한 판독을 보존한다. 같은 원본·언어·방향·DPI·엔진 설치와 모델이 확인되면 완료한 엔진을 다시 호출하지 않는다. **완료한 엔진도 다시 읽기**를 선택하면 이전 원시 결과를 남기고 새 판독을 추가한다.

## 원본과 판독 비교

왼쪽 원본은 화면 맞춤·확대·이동을 지원한다. 오른쪽에는 엔진별 원시 판독 탭, 직접 수정하는 교정문, 불일치 후보 목록을 둔다. 후보를 선택하면 관련 문자열과 이미지 영역을 표시한다. 좌표는 인식 당시 렌더링 이미지의 픽셀 좌표이며 확대·표시 크기에 맞춰 변환한다. 검출 상자가 줄 단위인 엔진은 개별 글자 위치가 정확하다고 표시하지 않는다.

비교는 Unicode 코드 포인트를 그대로 사용한다. 간체·번체·호환한자·이체자 선택자·중문부호를 서로 같은 문자로 접지 않는다. 공백만 다른 항목은 별도로 분류하지만 원시 문자열을 바꾸지 않는다. 기본 기준 판독은 중문에서 EasyOCR, 혼용에서 Tesseract이며 사용자가 변경할 수 있다. 기준 선택은 이번 자료의 기존 비교 결과를 반영한 시작값이다. 문헌 전반에서 항상 우수하다는 뜻은 아니다.

후보는 자동 교정 결과가 아니다. **선택 판독 채택**, **기준 유지**, 직접 편집, 되돌리기로 사용자가 확정한다. 엔진 confidence는 정확도 측정치가 아니므로 세 엔진 사이의 투표 가중치로 사용하지 않는다. RapidOCR·EasyOCR의 한국어 모델은 한자를 지원하지 않고, 중국어 모델도 한글 혼용에 적합하지 않다. 지원하지 않는 글자를 포함하는 후보는 채택 가능한 판독 근거에서 제외한다.

세로 로컬 비교는 시험 기능이다. Tesseract에는 세로 중국어 언어팩과 PSM 5를 사용하고, 나머지 엔진의 글줄 순서는 원본과 확인해야 한다. AI 검증은 사용자가 선택한 제공사·모델·쪽 범위에 한해 이미지·문맥 재판독 후 번체자·중문부호 제안을 만든다. 각 제안은 사용자가 채택해야 교정문에 반영된다. 이 기능의 연결이 기존 세로 판독의 정확도 개선을 입증하지는 않는다. [AI 사용·저장 안내](AI_REVIEW.md)

## 저장과 이력

비교 프로젝트의 형식은 `yeone-ocr-comparison`, 버전은 `1`이며 JSON으로 저장한다. 기본 경로는 작업 폴더의 `comparison/<원본 SHA-256 앞부분>.yeone-compare.json`이다. 현재 원본의 경로·SHA-256·쪽 수를 기록하고 열기·인식·저장·출력 전에 검증한다. 원본이 변경됐으면 다른 내용에 기존 교정을 적용하지 않는다.

| 기록 | 저장 내용 |
|---|---|
| `runs` | 매번의 원시 OCR·엔진·언어·모델 해시·좌표·요청 조건·원시 기록 해시 |
| `baseline_run_id` | 현재 비교 기준으로 선택한 판독 |
| `corrected_text` / `edits` | 현재 교정문과 수정 전후·사유·시각·되돌리기 이력 |
| `suggestions` / `comparisons` | 현재 후보와 이전 비교의 원문·범위·좌표 근거 |
| `decisions` | 후보 채택·기준 유지·되돌리기 결정 |
| `review_history` | 사람이 부여한 검수 완료와 해제 기록 |
| `ai_reviews` | AI 요청의 지문·정책·이미지 영역, 제공사·모델, 응답 원문·제안·실패 상태 |
| `ai_decisions` | AI 제안에 대한 사람의 채택·기각·되돌리기 결정 |

원시 `runs`와 교정문은 별도로 보존하며 재판독으로 사람의 교정문을 덮지 않는다. 이력 창에서 이전 판독과 수정 내용을 확인할 수 있다. 기존 AB 프로젝트를 가져오면 최신 원시 결과뿐 아니라 이전 인식·교정 상태의 스냅샷도 보관한다.

저장은 같은 폴더의 임시 파일을 flush·fsync한 뒤 원자적으로 교체한다. 다른 창에서 프로젝트가 바뀌었거나 다른 프로젝트가 있는 경로에는 덮어쓰지 않는다. 이 경우 다른 이름으로 저장한다. 복구 사본은 `comparison-recovery`에 별도로 저장하며 **복구 사본…**으로 연다. 창을 닫을 때 진행 중인 인식을 중지하고 완료 기록을 저장한다.

검증기는 중복 JSON 필드, 유효하지 않은 숫자·문자열·좌표, 다른 원본의 기록, 교정 이력 불일치를 거부한다. 프로젝트 파일은 최대 256 MB, 문자열은 최대 2,000,000자, 쪽 수는 최대 1,000,000쪽이다. 이는 형식 검사 상한이며 모든 규모를 성능 검증했다는 뜻은 아니다.

프로젝트에는 원본 경로와 개인 문서의 판독·교정 내용이 들어간다. 원본·작업 폴더·복구본을 사용자 데이터로 취급한다. 소스·공개 테스트·배포 자료에 문서 본문, API 키, 실제 원본 경로를 포함하지 않는다.

## 기존 기록과 출력

기존 연어OCR 작업 폴더의 원본 지문이 일치하면 `readings`의 1차 판독과 병합 판독을 읽기 전용으로 가져온다. 원래 JSON 문자열과 구조, 파일 해시를 보관한다. 이전 버전이 이미 적용한 문자 정규화까지 되돌릴 수는 없으므로, 이를 변경되지 않은 API 응답이라고 표시하지 않는다. 기존 기록을 다시 쓰거나 새 비교 판독으로 기존 책갈피·AI 판독 기록을 갱신하지 않는다.

**기록 가져오기…**로 같은 원본의 AB 프로젝트를 가져올 수 있다. 원본 지문을 검증하고 원시 결과·기존 교정문·이전 상태를 보관한다. 현재 편집 중인 교정문과 선택 기준은 유지한다. 가져오기와 반복 실행의 중복은 기록 해시로 구별한다.

**내보내기…**는 지정 쪽의 현재 교정문을 TXT·HWPX·DOCX로 쓴다. 미처리 쪽이 포함되면 완료한 범위를 고르도록 안내한다. HWPX·DOCX는 새 임시 파일을 만든 뒤 다시 열어 문자가 일치하는지 검사하고 최종 파일을 교체한다. 출력 중 번체 변환·부호 정규화·제목 추론을 적용하지 않는다. 이 출력은 현재 교정문으로 만든 새 문서이며, 기존 책갈피 OCR의 원래 HWPX 서식을 유지하는 교정 사본과는 별도 기능이다.

## 명령줄

```powershell
python -m yeone_ocr compare-engines "D:\문헌\원본.pdf" --pages 1-3 --profile traditional --direction horizontal --work "D:\문헌\작업" --engine-root "D:\OCR엔진"
```

`--profile`은 `traditional`, `simplified`, `mixed`, `--direction`은 `horizontal`, `vertical`이다. `--project`로 비교 프로젝트 경로를 직접 지정하고 `--force`로 이력을 남기며 재판독할 수 있다. 생략한 `--pages`는 전체다. 종료 코드는 정상 `0`, 일부 엔진 실패 `3`, 작업 실패 `2`, 취소 `130`이다. 명령줄 비교도 외부 AI를 호출하지 않는다.

## 구현과 검증 경계

구현 모듈은 `comparison.py`(문서·비교·교정 이력), `comparison_editor.py`(편집 창), `comparison_bridge.py`(기존 기록·출력), `comparison_cli.py`(명령줄), `ab_ocr`(로컬 엔진·검증 기반)다. 엔진 환경과 공개 모델은 현재 PC의 기존 설치를 재사용하고, 연어OCR에 포함된 작업자 파일을 실행한다. 다른 PC에서도 소스 프로젝트 없이 설치할 수 있도록 설치 스크립트·잠금 기록과 설치판의 작업자 리소스 구성을 포함했다.

원시 문자 보존, 누락 후보 제외, 이력·되돌리기, 저장 충돌·원본 변경·복구, 중지·재실행, 기존 기록의 읽기 전용 가져오기, 출력 문자 재검사와 기존 세로·책갈피·이미지 흐름을 검증한다. AI 검증은 공급사 전송 형식·범위·원시 응답 보존·세대와 근거의 유효성·사람의 채택·기각·되돌리기를 포함한다. 실제 로컬 자료 인식과 모의 AI 응답 검증은 구분하며, 새 AI 정확도 벤치마크나 세로 문헌의 개선 근거로 확대하지 않는다. 상세 실행 결과는 [release-notes.md](release-notes.md)에 기록한다.

0.9.0 소스와 Windows 배포 구성을 포함한다. 배포 대상은 설치 파일·포터블·소스 ZIP·라이선스 ZIP·업데이트 manifest·SHA-256 목록이며, 배포 후 [v0.9.0 다운로드 주소](https://github.com/kyengilam-coder/YeonE_OCR_release/releases/tag/v0.9.0)에서 확인한다. 로컬 산출물은 `dist/0.9.0`, 빌드·자체 검사 보고서는 `work/windows-ai-0.9`에 둔다. 소스·설치용 실행 파일·포터블 자체 검사는 각각 26개 통과했고, 두 실행 파일의 앱 모듈 각각 75개와 리소스 17개·라이선스 참조 162개의 일치를 확인했다. 이전 0.8.0·0.7.x 기록과 파일은 별도로 보존한다.

통합 전 AB_OCR 0.3.0의 공개 소스 보존 위치는 `references/AB_OCR_0.3.0`이다. [보존 안내](../references/README.md)에 따라 소스 저장소·소스 ZIP에 포함하며, 이 사본을 실행하거나 런타임에 import하지 않는다. 현재 앱의 실행 코드는 `yeone_ocr`와 루트의 `ab_ocr`다.
