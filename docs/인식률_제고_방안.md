# 문자 인식률을 높이는 방안 — 세 갈래 탐색과 종합 (0.6.3 기준)

이 문서는 저장소 코드(0.6.3, `claude/eloquent-gates-jta68m`. 판독 경로는 0.6.2 와 같고 0.6.3 은 화면만 바뀜)를 읽고 쓴 연구 보고입니다. **제안이며 코드는 아직 바꾸지 않았습니다.** 문제를 세 갈래로 나눠 따로 탐색했습니다.

- **A 입력 신호**: 모델에 어떤 픽셀이 가는가
- **B 판독 전략**: 모델에게 어떻게 묻는가
- **C 증거 결합·측정**: 여러 판독을 어떻게 합치고 재는가

갈래마다 가지를 나눠 가지별로 하나를 골랐습니다. 각 제안은 코드와 대조하는 검토를 한 번 더 거쳤고, 그 과정에서 과장·틀린 인용·지침 충돌을 고치거나 뺐습니다.

이 환경에는 Gemini API 키가 없어 **모델 정확도는 하나도 재지 못했습니다.** 숫자는 두 종류뿐입니다. 공개 문서의 토큰 상한으로 계산한 값은 "어림"으로 적었습니다. 현재 코드를 합성 렌더(PyMuPDF 내장 CJK 글꼴)에 그대로 돌려 잰 값은 "합성 실측"으로 적었습니다. 그래서 첫 단계는 측정 체계입니다.

## 0. 결론 먼저

지금 구조에서 정확도를 깎는 곳은 넷입니다.

1. **두 판독이 같이 틀린 글자는 어디에도 표시되지 않습니다.** 3차는 〔a/b〕만 보고, 글자층과의 차이는 참고 목록에만 남습니다.
2. **본문의 기준 글이 가장 저해상인 판독에서 나옵니다.** 1차는 쪽 한 장을 글자당 약 2토큰(어림)으로 읽습니다. 병합은 이 1차 글을 바탕으로 하고, 긴 갈림에서는 1차를 따릅니다.
3. **본문을 바꾸는 유일한 자동 단계(3차)가 문맥을 받습니다.** 질문에 앞뒤 글자가 들어가고, 지시문에도 문맥 단서가 있습니다.
4. **정답과 맞춰 본 숫자가 없습니다.**

| 순위 | 방안 | 겨냥하는 오류 | 기대 효과 | 비용 | 위험 |
|---|---|---|---|---|---|
| 0 | **평가 체계**: 사람이 입력한 HWPX로 단계별 CER·표시 밖 오류율·3차 정밀도를 냄 | 전체(측정) | 모든 채택의 전제 | 1~2일, 호출 0, 사람 판정 약 200건(추정 1~2시간) | HWPX 자체 오탈 → 표본 판정으로 보정 |
| 1 | **합의 오류 재검**: 1차=2차인데 글자층·장부가 의심하는 글자를 3차 자형 질문으로. 표시만 | 같이 틀린 획 하나 차이(入/人·曰/日·于/干), 같이 빠뜨린 글자 | 중~상 | flash ⌈의심 자리/8⌉회, 2~3일 | 글자층이 나쁘면 표시 폭증 → 쪽당 상한 |
| 2 | **3차 눈가림**: 앞뒤 글자·문맥 단서 빼기, 순번·여백 눈금, 후보 섞기, 보고 나서 고르기 | 3차 문맥 오확정, 순서 편향 | 중~상 | 호출 그대로, 1일 | 미정 증가(의도한 보수성) |
| 3 | **센 판독에 픽셀**: 2차·1차 ultra_high, 역할 교대 실험 | 저해상 판독 | 상(어림, 측정 필요) | 코드 몇 줄, 이미지 토큰 증가 | 낮음(거부되면 자동으로 내림) |
| 4 | **3차로 안 가던 갈림 회부**: 〔疑〕, 3자 이상, 긴 구간 | 삽입·삭제, "1차를 따름" | 중(추정) | 자리 수만큼 flash | 처음엔 표시만 |
| 5 | **2차를 자형 전용 증인으로**, 조각은 글자 크기로 | 두 판독의 상관 오류, 작은 글자 | 중 | 반나절~2일 | 가짜 〔a/b〕 증가 |
| 6 | **해상도 진단·원본 대체·저해상 확정 거부** | 150dpi 쪽, 쌍행소주 | 해당 쪽 상 | 호출 0, 1일 | 판면 불일치 → 검사 후 거부 |
| 7 | **같은 책 견본**: 픽셀 대조 거부권 → 모델에 견본 보이기 실험 | 이 책 활자의 혼동 | 저~중 | 2~3일 | 라벨 오류 → 사람 확정분만 |
| 8 | 3차 다표, 온도 A/B | 3차 오확정, 반복 붕괴 | 저~중 | 3차 호출 최대 3배 | 기본은 지금대로 |
| 9 | 먹 문턱, 장부 되먹임, 다른 계열 증인, 용어 표시 | 책마다 다름 | 저 | 각 1~2일 | 효과 0일 수 있음 |

**가장 일관된 답**: 먼저 사람이 입력한 HWPX로 잽니다. 그다음 두 판독이 함께 틀린 글자를 표시로 끌어내고, 3차에서 문맥을 걷어 내고, 센 판독에 픽셀을 더 줍니다. 기존 OCR·투표·견본은 **의심을 올리는 데만** 쓰고, 글자는 자형과 사람이 정합니다.

유지할 것: 내장 스캔을 재압축 없이 PNG로 보내고, 조각은 원본에서 잘라 Lanczos로 키우는 지금 경로(`pdfio.page_image`, `layout.to_png_bytes`, `adjudicate.glyph_crop`)는 그대로 둡니다. 초해상·이진화·JPEG는 넣지 않습니다.

## 1. 인식률 관점에서 본 지금 구조

```
입력  pdfio.page_image   내장 비트맵 그대로(같은 책에 150/300dpi 섞임)
1차   cli.read_one → read_page  쪽 1장, media_resolution 없음(make_reader) → Gemini 3 기본 1,120토큰, 글자당 약 2(어림)
2차   cli._second_pass  split_bands 8열 → _zoom(세로 1600px) → flash, high 1,120, 약 5.6토큰/자(어림)
      ※ 1·2·3차 모두 같은 prompts.system_prompt = 지침 + OUTPUT_RULES + mode_note + CONFUSION_CARD
결합  merge.merge_passes  1차가 바탕. 1차≠2차만 〔a/b〕·〔疑〕. LONG_SEGMENT(12자) 이상은 확인 항목만
3차   adjudicate.find_sites  MARK_AB(1~2자 a/b)만 → ±2자 6배 조각 → adjudicate_many_prompt
참고  merge.compare_textlayer(쪽당 60항목에서 자름), ledger.build_ledger(되먹임 없음)
```

오류가 생기는 자리는 다음과 같습니다.

- **원본**
  - 10.5pt 글자가 150dpi에서 약 22px, 쌍행소주는 약 11px입니다(계산).
  - 쪽별 dpi는 기록되지 않습니다.
- **2차 조각**
  - 세로 조각 하나에 8열 × 열 전체(약 200자, 어림)가 들어갑니다.
  - 확대 배율은 300dpi에서 1.0배, 150dpi에서 1.4배입니다(합성 실측).
- **결합**
  - 1차=2차≠정답이면 흔적이 없습니다.
  - 〔疑〕, 3자 이상 갈림, 긴 구간은 3차로 가지 않습니다.
- **3차**
  - 앞뒤 글자를 글로 주므로, 조각이 엉뚱한 자리여도 그 글자를 옮겨 적으면 `window_ok`를 통과합니다.
  - 열 끝에서도 "가운데 글자"라고 묻습니다.
  - 후보는 [1차, 2차]로 고정입니다.
  - 답 차례가 c→e→w(`schema.GlyphChoice`)라서 고른 뒤에 근거를 씁니다.
- **조각 자르기**
  - 먹 문턱이 110으로 고정입니다(`layout._profile`·`page_bands`, `adjudicate.page_ink`).
  - 먹이 115 이상이면 띠를 0개 찾습니다(합성 실측).
- **측정**: 저장소에 CER 코드가 없습니다.

- B-3 Consensus Entropy → 원 논문은 의견이 갈리면 센 모델로 넘깁니다. 여기서는 사람에게 넘기도록 바꿔 썼습니다.
- B-4 arXiv 2405.09798 → many-shot 분류라 견본 2~3장의 근거로는 약합니다.
- B-5 "2차 약 11토큰/자" → ultra_high일 때 값입니다. 기본 high는 약 5.6입니다(어림).
- B-6 "README가 오류가 소주에 몰린다고 적었다" → 사실이 아니어서 뺐습니다.
- B-8 "자리 적중 98%" → 합성 렌더에서 목표가 창 안에 든 비율이지, 셈 정확도가 아닙니다.

## 4. 최종 제안과 실행 순서

**채택 규약**
- 같은 표본 쪽을 `--work` 폴더만 바꿔 돌립니다.
- 같은 설정을 두 번 돌린 차이(잡음 바닥)보다 커야 하고, 쪽 단위 부트스트랩 95% 구간이 개선 쪽에 있어야 채택합니다.
- 3차 비교는 같은 자리끼리 McNemar로 봅니다.
- **표시 밖 오류율이 늘면 CER이 줄어도 채택하지 않습니다.**

### 단계 0 — 측정 체계

새 `yeone_ocr/evaluate.py`와 `yeone-ocr eval <pdf> --hwpx <원본.hwpx> --pages <표본> [--configs A,B]`를 만듭니다. 읽기 전용이고 모델 호출이 없습니다.

- **재사용할 것**
  - `collate/run.py`: `index_both`, `trim_to_section`, `reading_text`
  - `collate/collate.py`: `hwpx_cells`, `ocr_cells`
  - `collate/zh.compare_key`
  - `run_section`은 쓰지 않습니다.
- **기준 파일**: 원본 HWPX로 고정합니다. `cmd_collate`는 `_교정.hwpx`(OCR이 이미 고친 파일)가 있으면 그것으로 바꿔 타므로, 그대로 쓰면 평가가 순환합니다.
- **단계별 글**: 글자층, 1차, 2차, 병합(표시는 첫 후보로), oracle(표시 안 후보 중 하나가 맞으면 정답), 3차 뒤.
- **지표**
  - CER_default, CER_oracle
  - **표시 밖 오류율**(표시 ±1자 밖 오류 ÷ 글자 수)
  - 표시 정밀도
  - 3차 확정 정밀도·결정률(모델·loc·dpi별)
  - 오류 상관비 P(2차 틀림|1차 틀림)/P(2차 틀림)
  - 공통 오류 수
  - 긴 구간 수
- **잡음 보정**: 차이 약 200건을 층화 추출해 `eval/diffs.html`에 띄웁니다. 사람이 "판독 틀림 / HWPX 틀림 / 인쇄 오자 / 이체자"로 판정하고, 결과는 `eval/labels.json`에 둡니다.
- **표본**: dpi·소주 비중·쓰기 방향으로 층화합니다. **개발용과 시험용을 미리 나눕니다.** 쪽 수는 파일럿 10쪽의 오류 수를 보고 정합니다.
- **시력표**(A-4): 다음 조건을 바꿔 가며 잽니다. 조각 모양별 토큰은 `count_tokens`로 먼저 잽니다(생성 호출 없음).
  - 글자 크기: 10~42px
  - 배치: 쪽·8열·3열·반높이
  - 해상도: high / ultra_high
  - 열화
- **지금 API 없이 할 수 있는 것**: 기존 `collate/*.json`에서 〔〕 없는 한 글자 차이를 세어 상한을 봅니다. 비교 글자 수 N은 저장되지 않으므로 하네스가 기록해야 합니다.

### 단계 1 — 즉시 손잡이 (코드 몇 줄, 설정 실험)

### 단계 2 — 3차 질문 다시 짜기

> **0.6.5 에서 구현됨.** 아래 계획 그대로이고, 구현에서 정한 것은 다음과 같습니다.
> - 판독기 함수는 앞뒤 글자를 받지 않습니다. `GlyphAsk`(섞은 후보·조각 안 순번·창 글자 수·실측 여부·눈금 여부)만 받으므로 프롬프트에 문맥이 새어 들어갈 길이 없습니다.
>   pre/post는 `window_ok`·`adjacent_seen` 검사(답을 받은 뒤 코드에서)에만 남았습니다.
> - 눈금은 조각 바깥에 덧댄 흰 띠에만 그립니다(글자 획을 가리지 않게). 실측이 아닌 자리는 "순번은 어림"이라고 알립니다.
>   렌더 시험에서 먹 셈은 획이 갈라지는 글자가 든 줄에서 맞지 않아 약 절반만 실측이 됩니다. 실측이라고 한 자리는 순번·대상 상자가 모두 맞았습니다.
> - 저해상 문턱은 잠정 16px(`--adjudicate-min-px`)입니다. 글자 크기는 글자층이면 글자 간격, 먹이면 줄 두께, 균등 분할이면 글자·줄 간격 가운데 작은 쪽으로 잽니다.
>   문턱에 걸린 자리는 묻지 않습니다(호출을 아낌).
> - 블라인드 단계(`--adjudicate-blind`)는 확정할 자리(후보 안 답, 창 검사 통과)만, 그 자리의 답을 낸 판독기에 묻습니다. 이체자 쌍·숫자·부호 후보는 접지 않고 글자 그대로 맞춰 봅니다. 재확인 호출이 실패해도 확정하지 않습니다.
> - 자형 전용 시스템 지시는 짧아서(약 1.3천 자) 컨텍스트 캐시를 만들지 않습니다(`CACHE_MIN_CHARS`).
> - 측정(정밀도·결정률·열 끝 적중률·앵무 시험)은 아직 하지 않았습니다. 기록에 `pos`·`asked`·`em_px`·`blind`가 남으니, 실측 때 위치 편향과 문턱을 이 기록으로 셀 수 있습니다.

- **`prompts.py`**
  - `glyph_system_prompt()`를 만듭니다. 지침 2·7·19·21·24장 요지와 `GLYPH_HINTS`만 넣습니다.
  - 다음은 넣지 않습니다: `CONFUSION_CARD`의 "장부 앞은 入이 흔하다", 가로 모드의 于 용법 목록, 쪽 JSON 규칙.
  - 판별 질문에서는 pre/post를 빼고 "조각 안 위→아래 n번째"로 가리킵니다.
- **`schema.py`**: 필드 차례를 w→e→c로 바꿉니다. 별칭은 그대로입니다.
- **`adjudicate.py`**
  - `glyph_window`가 창 안 순번을 돌려줍니다.
  - 눈금은 자리를 실측한 경우(loc=layer, 또는 먹 셈이 꼭 맞을 때)에만 여백에 그립니다.
  - 후보는 `hashlib` 고정 씨앗으로 섞습니다.
  - 후보 밖 답은 미정으로 둡니다(0.6.2 검토 반영에서 이미 했습니다).
- **블라인드 단계**(`--adjudicate-blind`): 후보 없이 받은 답과 객관식 답이 `compare_key`로 같을 때만 확정합니다. 쪽당 ⌈자리/8⌉회 flash가 더 듭니다.
- **저해상 확정 거부**: 원본 글자 높이가 문턱(16~20px 근처, 측정으로 정함)보다 작으면 확정하지 않습니다(지침 24).
- **같이 바꿀 곳**: `collate/run.adjudicate_items`, `GeminiReader(system=…)`.

**측정**: 같은 〔a/b〕 자리에서 확정 정밀도, 결정률, 열 끝 적중률을 봅니다. **앵무 시험**도 합니다. 확정 자리 50곳의 조각을 한 글자 밀어 다시 묻고, 앞뒤 글자를 줄 때와 숨길 때 `window_ok` 통과율을 비교합니다.

### 단계 3 — 표시되지 않는 오류 끌어내기

**공통 기반을 먼저 만듭니다.**
- 새 표시는 origin 태그가 붙은 〔疑: 합의글자〕와 확인 항목("합의 판독 X, 자형 판별 Y — 원본 확인")으로 넣습니다.
- 표시는 `rec['suspects']`에 저장합니다.
- `remerge_record`가 다시 붙이고, `find_sites`는 이 표시를 건너뜁니다.

**신호**
- ① **글자층 1:1 치환**: 글자층 plain으로 다시 계산합니다(저장본은 60항목에서 잘림). `compare_key`로 접은 뒤에도 다른 것만 씁니다(세로 모드 `_fold`는 이체자를 접지 않음). 일치율이 낮은 쪽은 뺍니다(지침 28).
- ② **장부 편향 묶음**: 쪽당 상한을 두고 빈도순으로 씁니다.
- ③ **글자층 대비 1~2자 삽입·삭제**: 그 열만 다시 판독합니다. 먹 셈은 글자층이 없을 때만, 셈 정확도를 잰 뒤에 씁니다.
- ④ **지금 3차로 안 가는 갈림**
  - 〔疑〕: "사이에 글자가 있는가"를 묻습니다.
  - 3~11자 갈림: 한 열 조각으로 세 번째 판독을 합니다.
  - 긴 구간: 고해상 판독을 확인 항목의 근거로 붙입니다(본문 불변).

**장부**: `ledger.build_ledger`가 `rec['adjudications']`도 세고, `max_sites`를 장부 순으로 자르게 합니다.

**바꿀 파일**: `adjudicate.py`(`find_suspects`), `merge.compare_textlayer`(위치), `cli.read_one`·`cmd_adjudicate`(`--suspects`, `--suspect-max`), `remerge_record`, `ledger.py`, `layout.py`(`count_glyphs`).

**측정**: 표시 밖 오류율 감소, 라우팅 정밀도, 1천 자당 표시 증가, 쪽당 추가 호출을 봅니다. 호출 없이 하네스 결과만으로 재현율 상한을 먼저 셉니다.

### 단계 4 — 2차를 독립 증인으로, 조각을 글자 크기로

- **2차 지시문**: `prompts.second_system_prompt()`를 만듭니다. 지침 발췌, 열 출력 규칙, 문맥 단서를 뺀 자형 카드로 구성하고 `--second-prompt full|glyph`로 고릅니다.
- **조각 나누기**: `cli._second_pass`에 `--chunk-glyphs`를 둡니다. 조각당 글자 면적으로 열 수를 정하고, 최소는 세로 2열·가로 3줄입니다. 글자층이 있으면 그 열 좌표 사이 공백을 경계로 씁니다.
- **먹 문턱·기울기**: `layout.ink_threshold`로 쪽별 문턱([60, 200])을 정해 투영 함수와 `page_ink`에 넘깁니다. 기울기는 2차 조각만 회전합니다. 둘 다 `cmd_inspect` 진단으로 해당 책인지 먼저 봅니다.

**측정**: 오류 상관비, 공통 오류 수, 〔a/b〕 수와 3차 호출, prompt_token_count, 글자층 열 수 일치율, loc=uniform 비율.

### 단계 5 — 실험 (남기거나 버림)

- **자형 대조 증인**
  - 견본은 HWPX나 사람이 확인한 글자만 씁니다. dpi와 글자 크기를 기록합니다.
  - 먼저 정규화 상호상관 대조를 거부권으로 씁니다. leave-one-out 정확도를 dpi별로 잽니다.
  - 그다음 모델에 견본(조각별 low)을 붙이는 조건과 비교합니다.
  - 이체자 쌍은 제외합니다.
- **3차 다표**: "1표 / 블라인드 일치 / 3표 만장일치 / 2표 이상이면서 pro가 다수 쪽" 가운데 측정으로 하나를 고르고, 겹쳐 쌓지 않습니다. 변형은 회색조 배율·반 글자 밀기·대비만 쓰고 이진화는 쓰지 않습니다.
- **1차 다중 시야**: B-2와 B-3이 모두 안 될 때만 시도합니다.
- **쌍행 하위 열**: 먼저 출력 규칙(오른쪽 하위 열 → 왼쪽 하위 열)을 OUTPUT_RULES와 지침 4·22장에 정합니다.
- **다른 계열 증인**: 글자층 없는 PDF의 표시 밖 오류가 클 때 Tesseract 세로 모델부터 씁니다.
- **책별 "다시 보라" 카드**: 2·3차에만 넣습니다.
- **용어·반복 구절**: PDF 책갈피로 만든 사전을 쓰고, 표시만 합니다.

**별도 점검**: 책갈피 탭의 기본 정책 `all`은 사람이 입력한 HWPX를 자동으로 고칩니다. 또 `witness_filter`가 글자층을 결정 증인처럼 씁니다. 하네스로 A·B2 자동 반영의 정밀도를 잴 때까지 기본값을 `sure`나 `memo`로 낮추는 것을 검토합니다.

## 5. 지침과의 관계

**불변식**(단위 검사로 고정)
1. 글자층·장부·증인·사전·투표는 본문 글자를 바꾸지 않습니다. 표시 추가, 3차 회부, 검수 순서에만 씁니다.
2. 표시를 지우고 확정하는 것은 3차 자형 판별과 사람만 합니다.
3. 이체자 쌍은 후보·견본에 넣지 않고, 후보 밖 답은 미정으로 둡니다.
4. 평가 수치는 전수 교감을 대신하지 않고 "원본 대조 완료(사람)"를 매기지 않습니다(지침 27·33).
