# 연어OCR 개발 인수인계

현재 소스 버전은 **0.9.0**이다. 연어OCR의 기존 작업 흐름에 AB_OCR 0.3.0의 로컬 세 엔진 비교·원본 대조 편집 기반을 통합하고 AI 이미지·문맥 재검증과 번체자·중문부호 교정 제안을 연결한다. 세로 읽기·책갈피 OCR·이미지 OCR을 유지하며 원시 판독, AI 응답·제안, 사람이 확정한 교정을 구분한다.

## 시작할 때 읽을 문서

1. `README.md`: 0.9.0 사용 흐름·다운로드 주소와 로컬 엔진 별도 설치.
2. `docs/INTEGRATION.md`: 구현 범위, 프로젝트 형식, 교정 이력, 기존 기록 가져오기·출력 정책.
3. `docs/LOCAL_OCR.md`: 엔진 폴더·설치·모델 언어 제한과 설치판 실행 방식.
4. `docs/release-notes.md`: 최종 테스트 결과와 배포 상태.
5. `yeone_ocr/지침.md`: 기존 문헌 판독·교정 규칙.
6. `docs/AI_REVIEW.md`: AI 전송 범위·두 단계 검증·정책·이력·재개.

## 실제 구현

| 구성 | 위치·책임 |
|---|---|
| 기존 앱 | `yeone_ocr/gui.py`, `cli.py`: 기존 일반·책갈피·이미지 탭과 AI 작업을 유지하고 상단 비교 편집 진입점·명령줄을 연결 |
| 비교 코어 | `yeone_ocr/comparison.py`: 쪽별 원시 판독 이력, 정확한 문자 비교, 모델 지원 범위, 교정·후보·검수 이력, 저장·복구·작업 실행 |
| 비교 편집 창 | `yeone_ocr/comparison_editor.py`: 원본 확대·후보와 좌표 표시·직접 교정·되돌리기·진행·취소·엔진 폴더 선택 |
| 기록·출력 연결 | `yeone_ocr/comparison_bridge.py`: 검증한 기존 연어·AB 기록을 읽기 전용으로 가져오고 TXT·HWPX·DOCX 출력 후 재검사 |
| 명령줄 | `yeone_ocr/comparison_cli.py`: `compare-engines`, 쪽 범위 검사, 엔진별 저장·중지·오류 종료 코드 |
| AI 재검증 | `yeone_ocr/comparison_ai.py`: 승인한 계획의 이미지·문맥 전송, 시각 재검증과 번체자·부호 제안, 공급사별 단일 요청·상한·취소·재개 |
| 로컬 엔진 | `ab_ocr/ocr.py`, `local_engines.py`, `runtime.py`, 두 작업자: 독립된 엔진 환경에서 Tesseract·RapidOCR·EasyOCR 실행 |
| 설치·배포 구성 | `scripts/install_*.py`, 잠금 JSON, `packaging/YeonE_OCR.spec`: 명시적 공개 모델 설치와 설치판 작업자 리소스 허용 목록 |

AB 코드의 원본 파일 해시는 `docs/AB_OCR_PROVENANCE.json`에 기록했다. 원래 AB_OCR 프로젝트는 수정하지 않는다. 연어OCR 코드는 다른 프로젝트의 Python 소스를 가져오지 않는다. 현재 개발 PC에서는 기존 AB 설치의 공개 모델·별도 실행 환경만 재사용한다. 설치판은 개발용 형제 프로젝트 탐색을 하지 않는다.

통합 전 AB_OCR 0.3.0의 공개 소스 52개와 파일 해시 목록은 `references/AB_OCR_0.3.0`에 보존한다. [보존 안내](../references/README.md)를 확인한다. `references`는 기록과 비교를 위한 비활성 소스 사본이며 런타임 import 경로가 아니다. 앱이 사용하는 통합 코드는 루트의 `ab_ocr`와 `yeone_ocr/comparison*.py`다. 보존 사본은 소스 ZIP에 포함하고 개인 문서·판독 기록·엔진 실행 환경·모델 가중치는 제외한다.

## 지켜야 할 데이터 정책

- 원본 PDF·이미지와 기존 연어 판독 기록을 새 비교 작업으로 덮어쓰지 않는다.
- 각 엔진의 원시 Unicode·부호·좌표와 모델 해시를 보존한다. 공백 차이 분류도 원문 수정으로 연결하지 않는다.
- 교정문, 수정 전후·시각·사유·되돌리기, 후보 결정, 사람이 확인한 검수 상태를 별도 이력으로 저장한다.
- 여러 엔진의 같은 결과를 자동으로 정답 처리하지 않는다. 한국어 모델의 한자 누락과 중국어 모델의 한글 미지원을 판단에서 제외한다.
- 기존 연어 기록은 과거 정규화가 적용됐을 수 있다. 원래 JSON과 가져오기 출처를 함께 남긴다. AB 이전 인식·교정 상태도 스냅샷으로 보존한다.
- 저장은 임시 파일·fsync·원자적 교체로 수행하고 원본 변경·다른 창의 저장 충돌을 확인한다. 완료한 쪽·엔진의 복구 사본을 유지한다.
- 개인 원본, 판독문, 스크린샷, API 키를 소스·로그·공개 테스트·배포물에 넣지 않는다. 실제 문서 검증 결과는 Git에서 제외한 `work` 아래에 둔다.

로컬 세 엔진 인식은 외부 전송 없이 실행한다. 별도 AI 검증 실행은 현재 설정의 제공사·모델과 선택한 문서·쪽 범위·번체자·중문부호 정책만 사용한다. 실제 전송 계획을 확인한 뒤 두 단계로 실행하고, AI 응답·제안은 `ai_reviews`, 사용자의 결정은 `ai_decisions`와 `edits`에 분리한다. 기존 AI 판독의 전역 취소·호출 상한·프롬프트를 변경하지 않는다. 공급사·모델 자동 대체나 사용자 확정 없는 교정문 덮어쓰기를 추가하지 않는다.

## 검증과 현재 상태

새 테스트는 `tests/test_comparison*.py`, `tests/test_local_runtime.py`에 있다. 원문·좌표·원본 변경·저장 충돌·복구·취소·이력·내보내기 문자 보존, 실제 SDK의 오프라인 HTTP 직렬화, AI 응답 형식·범위·세대·근거 계보와 사용자의 결정 보존을 확인한다. 기존 테스트는 세로 판독, 책갈피 대조, 이미지·캡처 처리, HWPX·검색 PDF와 설치판 실행 경계를 포함한다. 간체·번체·한글 한자 혼용의 실제 로컬 인식 검증과 AI 모의 응답 동작 검증은 구분한다. 전체 테스트 결과와 로컬 배포 상태는 `docs/release-notes.md`를 확인한다.

```powershell
python -B -X utf8 tools/check_regression.py
python -B -X utf8 -m yeone_ocr compare-engines "D:\문헌\원본.pdf" --pages 1 --profile traditional --direction horizontal --work "D:\문헌\작업" --engine-root "D:\OCR엔진"
```

0.9.0 기능 통합 기준 검증은 61개 모듈·고유 테스트 1,080개 통과이며, 공개 소스 정리와 추가 검사 뒤의 최종 결과는 [릴리스 기록](release-notes.md)에 이어 기록한다. Windows 배포판은 `tools/build_windows.ps1`로 만들며 소스·설치용 실행 파일·포터블에서 각각 오프라인 자체 검사 26개를 통과했다. 두 실행 파일의 앱 모듈 각각 75개, 리소스 17개, 라이선스 참조 162개의 일치를 확인했다. 문서·소스가 바뀌면 재빌드하고 이 검사를 다시 실행한다.

배포 파일은 `dist/0.9.0`, 빌드 보고서는 `work/windows-ai-0.9`에 둔다. 공개 소스 커밋에서 소스·라이선스 ZIP과 `update.json`·SHA-256 목록을 만들고, 배포 후 [v0.9.0 다운로드 주소](https://github.com/kyengilam-coder/YeonE_OCR_release/releases/tag/v0.9.0)에서 확인한다. 문서의 링크만으로 공개 완료를 판단하지 말고 실제 GitHub 릴리스와 자산·해시를 확인한다. 이전 0.8.0·0.7.x의 검증·배포 기록은 역사로 보존한다. 소스에서 실행하는 방법은 README를 따른다.

AI 연결의 동작 검증과 실제 인식 정확도 평가는 구분한다. 유료 제공사·모델·문서 범위가 별도로 선택되지 않은 개발 시험은 모의 응답을 사용한다. 실제 AI 판독 정확도와 세로·복잡한 표의 품질은 대표 원본과 독립 정답으로 추가 측정해야 한다. 교정 제안을 최종 정답으로 자동 확정하지 않는다.
