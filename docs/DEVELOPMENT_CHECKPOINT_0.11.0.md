# 0.11.0 개발·검증 정리 · 2026-10-24

PP-OCRv6 medium을 네 번째 로컬 엔진으로 추가하고, 중국어 인식 보완·자동 엔진 선택·Windows 설치 연결까지 구현한 시점의 기록이다. 이 커밋은 개발 저장소 저장이며 새 공개 릴리스 게시와 구분한다.

## 구현한 변경

- PP-OCRv6의 고정 실행 환경·모델 설치, 모델 SHA-256 검사, 별도 오프라인 작업자, 비교 편집기·CLI 연결을 추가했다.
- PP-OCRv6·PP-OCRv5·EasyOCR의 세로쓰기 열을 오른쪽→왼쪽으로 정렬했다. EasyOCR의 세로 글자 누락과 간체·번체 가로쓰기 혼동, PP-OCRv5·Tesseract의 자형 혼동을 보완했다. 기본 판독과 보완 근거를 별도로 남긴다.
- PP-OCRv6 번체 가로쓰기에는 원본 크롭·여백 재인식의 한자 합의와 줄 전체 자형 검증을 추가했다. 특정 글자 치환이나 테스트 정답을 실행 정책에 넣지 않는다. 설치된 글꼴과 입력에 민감한 기능이므로 임의 스캔의 정확도를 보장하지 않는다.
- 이전 엔진 폴더 설정이 있어도 내장 PP-OCRv6를 찾도록 했다. 자동 모드는 지원 언어·메모리 여유를 확인하고 후보를 순차 실행하여 쪽별 원문 하나와 선택 근거를 저장한다. 직접 교정과 사람이 정한 기준은 보존한다.
- 비교 파일 읽기는 제한 크기를 한꺼번에 할당하지 않고 청크로 읽는다. 설치·모델 묶음 검증, 설치 후 실행 확인 도구와 회귀 검사를 추가했다.

구체적인 정책·검증 경계는 [자동 선택](AUTOMATIC_OCR.md), [중국어 합성 시험](CHINESE_OCR_TEST.md), [설치판 검증](WINDOWS_0.11.0_VALIDATION.md)을 따른다.

## 완료한 검증

마지막 UI 수정 뒤 커밋 직전 전체 회귀 검사를 다시 실행해 **71개 모듈·1,193개 테스트 전부 통과**, 실패·오류·건너뜀·미완료 0개를 확인했다. 현재 소스·테스트 지문이 모든 검사 기록과 일치하며 소스 자체 검사 28개도 통과했다. 설치판의 고정 빌드 환경에서 실행한 결과는 [공개 집계 JSON](benchmarks/real-corpus-0.11.0-20261024.json)의 `commit_validation`에 기록했다. 최초 개발용 가상환경에는 `hanja`가 없어 검색 시험 1개 실패·2개 건너뜀이 발생했으며 그 실행을 중단하고 소스 변경 없이 고정 환경에서 전체를 재검사했다. 회귀 검사는 외부 연결을 차단하며 실제 문헌의 OCR 정확도 시험과 구분한다.

설치판·포터블·소스·설치본 자체 검사는 각각 28개를 통과했다. 0.10.0→0.11.0 업그레이드, 재설치·제거, 외부 사용자 자료 보존, 한글·공백 경로, 구형 엔진 폴더 설정에서 내장 모델 탐색을 확인했다. 설치본의 원래 3쪽과 추가 6조건, 합계 706자는 공백 제외 오류 0개였다. 이는 해당 합성 자료의 결과다.

로컬 설치 파일은 `dist/0.11.0/YeonE_OCR-0.11.0-Setup-x64.exe`이며 크기는 282,129,422바이트, SHA-256은 `63cb1cc5ead855dd4fdc94f1d7f4fc1377274eb04bc6b301a04b8382c4fc94d0`다. 설치 파일·모델·런타임은 Git 소스에 넣지 않는다.

## 실제 문헌의 개선 전 기준

HWPX를 원문, PDF를 OCR 입력으로 삼아 네 쌍의 대응 관계를 확인했다. PDF 텍스트층은 대응 감사에만 사용했고 OCR에는 PDF 렌더링 이미지가 들어갔다. 문서별·언어별 인식률, 처리 시간, 프로세스 트리 메모리를 실제 앱의 비교·자동 선택 경로에서 측정했다. 엔진·선택 정책은 이 시험 중 수정하지 않았다.

| 문서 | 전체 쪽 | 측정 완료 쪽 |
|---|---:|---:|
| 대조도감 | 5 | 5 |
| 의방집해 | 10 | 10 |
| 초신접기 | 5 | 5 |
| 초창결 원문2-200916 | 114 | 1–56 |
| 합계 | 134 | 76 |

사용자 요청으로 초창결 추가 측정을 중단했다. 나머지 58쪽과 중단 당시의 미완성 쪽은 점수·실패 건수에 포함하지 않았다. 완료된 엔진 판독은 287건, 실행 실패 0건, 측정 정답은 공백 제외 43,700자다. 혼용 프로필의 PP-OCRv6는 미지원으로 제외된다. 초신접기 5쪽은 실제 빈 쪽이며 올바른 빈 판독과 앱의 텍스트 없음 오류 1건을 구분했다.

자동 선택은 빈 쪽 제외 75쪽 중 45쪽에서 관측 최소 오류 엔진과 일치했다. 중국어만 보면 59쪽 중 33쪽이다. 최선 조합보다 추가 오류 1,314개가 있었다. 혼용 자동 모드는 Tesseract만 후보이므로 해당 쪽의 일치가 선택 능력을 입증하지 않는다.

의방집해는 2단의 글자를 줄마다 교차 배치하는 순서 문제가 주 점수를 크게 낮췄다. 좌표로 단을 다시 정렬한 수치는 원인 진단용 채점 결과이며 현재 앱 출력의 정확도가 아니다. 향후에는 다단 읽기 순서와 자동 선택을 우선 개선하고 같은 고정 기준과 비교한다.

현재 자료는 편집·출력한 가로쓰기 PDF다. 세로쓰기·낡은 스캔·촬영 문서의 대표 시험이 아니다. 주 지표 CER은 공백만 제거한 Unicode 편집거리로, 문자 형태뿐 아니라 읽기 순서·부호·이체자 차이를 포함한다. 시간은 단일 CPU 실행이고 쪽마다 모델을 새로 로드한다. 메모리는 계측기와 자식 프로세스 합산의 50ms 표본 최대치다. 지원 범위가 다르므로 전체 평균으로 엔진 순위를 정하지 않는다.

완료 판독을 묶은 네 문서의 앱 프로젝트는 저장→불러오기→재저장→재불러오기 검증을 통과했고 원시 판독·교정 미적용 상태를 보존했다. 초창결 프로젝트에는 측정한 56쪽만 있다. GUI 조작 성능·깨끗한 VM 설치 검증과 구분한다.

## 보관·재확인

Git에는 코드·테스트·합성 자료 생성기·문서·문헌 내용이 없는 [집계 JSON](benchmarks/real-corpus-0.11.0-20261024.json)을 보관한다. 기존 데이터 정책에 따라 실제 HWPX/PDF·정답·OCR 판독문·미리보기·사용자 설정·모델은 올리지 않는다.

전체 로컬 보고서는 `output/benchmarks/real-corpus-0.11.0-20261024/report.html`, 원시 시험 도구는 `work/real-corpus-baseline-0.11.0/`, 설치 검증 자료는 `work/windows-0.11/`에 있다. 다음 ZIP에는 입력 사본·고정 정답·수정 전 소스 스냅샷·엔진/모델 지문·측정값·판독·앱 프로젝트·재현 도구와 파일별 해시 목록을 보관했다.

- 파일: `YeonE_OCR-0.11.0-real-corpus-baseline-20261024.zip`
- 크기: 57,361,461바이트
- SHA-256: `ecadfabcd504edd5f5affc4687cd41177462fc2d52e95aff259cf3535466b7ea`
- 보관: 로컬 `output/benchmarks/` 및 원본이 있던 Z드라이브의 `+ OCR test +` 폴더. 복사본 해시와 ZIP CRC를 확인했다.

최종 감사 당시 초창결의 최초 원본 경로는 없어졌고 현재 같은 폴더의 짧은 이름 파일은 해시도 달랐다. 이 기준은 시작 시점에 보관한 기존 114쪽 원본 사본에 연결된다. 새 파일로 바꾸어 채점하지 않았다. 다른 세 쌍은 현재 원본과 사본 해시도 일치했다. 앱 소스·엔진 설치 정보·실제 사용 모델/실행 파일/글꼴 지문은 그대로임을 확인했다.
