# 0.11.0 자동 로컬 OCR 설치판 검증 · 2026-10-24

`dist/0.11.0/YeonE_OCR-0.11.0-Setup-x64.exe`는 PP-OCRv6 medium의 기존 고정 실행 환경·모델을 포함하고, 구형 엔진 폴더와 독립적인 내장 엔진 탐색 및 쪽별 자동 선택을 추가한다. 공개 GitHub 게시와는 별개의 로컬 빌드다.

- 전체 회귀 검사: 71개 모듈, 고유 테스트 1,193개 통과. 실패·오류·건너뜀·미완료 0개. 마지막 UI 표시 조정 후 관련 57개 테스트와 9개 subtest를 추가 통과했다.
- 소스·설치용 실행 파일·포터블·설치본의 오프라인 자체 검사: 각각 28개 통과. 자동 모드 기본 선택, 4엔진 합성 결과 비교·선택, 저장·재열기, 구형 폴더가 있어도 내장 모델을 찾는 검사를 포함한다.
- 이 PC의 한글·공백 포함 별도 경로에 0.10.0 설치 → 0.11.0 업그레이드 → 재설치 → 제거를 검증했다. 등록 버전·경로가 일치했고 외부 합성 사용자 자료가 보존됐다. 검증용 설치는 제거했다.
- 엔진 묶음 2,748개 파일의 크기·SHA-256을 재검증했다. 같은 고정 묶음의 네이티브 파일 98개에 대한 C++ 런타임 의존성 검사도 누락 0개다.
- 설치본 CLI에 모델이 없는 기존 엔진 폴더 경로를 계속 지정하고 `--engines`를 생략해 **기본 자동 모드**를 실행했다. 9개 조건 모두 PP-OCRv6를 자동 선택·적용했다. 실행 기록의 실제 모델 폴더는 새 설치 폴더였으며 구형 설정 사본은 바뀌지 않았다.
- 원래 PDF 3쪽(간체 가로·번체 가로·번체 세로)과 추가 6개 조건, 총 706자에서 공백만 제외한 문자 오류 0개. 추가 조건은 이전 환경에서 만든 이미지와 픽셀 단위로 같았고, 원시 모델의 기존 4개 오류가 개선 후 0개인 결과도 같았다.
- 기존 네 엔진의 저장 판독을 쪽별 선택기에 입력한 별도 평가에서도 세 쪽 모두 관측 최저 오류인 0개 결과를 선택했다. 이 평가는 저장 판독의 재평가이며 네 엔진을 다시 실행한 결과와 구분한다.
- 문서 누락·깨진 문자·부분 검출끼리의 일치·단일 엔진·실패 후 대체·중지·사람의 교정 및 기준 보존·손상 모델·메모리 여유 부족을 합성 회귀 검사에 포함했다.

Python 및 실제 로드된 C++ 런타임이 설치 폴더 안에 있음을 확인했다. 테스트 중 PATH는 Windows System32로 제한했고 작업자는 네트워크를 차단했다. 원래 PDF SHA-256은 `57863bf04cb406ad06e568974c5f57ec86f21da8fa8ddec885350756998a9db5`다.

선택 점수는 정답 없이 계산한 품질 추정이다. 모든 실제 문헌에서 항상 최고 정확도를 보장하지 않는다. 사용할 엔진이 한 개이거나 판독이 불일치하면 원본 대조 표시를 남긴다. 문서 종류와 읽기 방향은 사용자가 선택하며, 한글·한자 혼용에는 해당 Tesseract 모델이 필요하다. 자세한 정책은 [AUTOMATIC_OCR.md](AUTOMATIC_OCR.md)를 따른다.

최종 실행 파일과 해시는 `dist/0.11.0`에 보관한다. 원본 보고서는 `work/windows-0.11/regression/summary.json`, `installation-check/result.json`, `installation-check/ocr/result.json`, `installation-check/ocr/conditions-audit.json`, `saved-readings-selection.json`이다. 새 PC의 깨끗한 VM 검증과는 구분한다.
