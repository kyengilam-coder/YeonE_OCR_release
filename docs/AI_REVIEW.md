# AI 재검증과 교정 제안

## 원본 PDF 부호 보조 확인

`anchored-refinement-v3`의 제안과 ID는 유지하며, 별도 `refinement_source_checks`에 `refinement-pdf-punctuation-check-v1` 근거를 추가한다. 비교 편집기에서 PDF의 **교정 후보 생성**을 누르면 함께 실행하고, 기존 후보는 **PDF 부호 확인**으로 확인할 수 있다. 원본 PDF의 표시 문자 정보가 정확한 위치에서 변경 전 부호를 지지하면 해당 제안을 보류한다. 한자나 부호를 새로 생성하지 않는다. 보류는 후보 목록·채택·평가 초안·후속 AI에 전달할 로컬 후보에 공통으로 적용되며, 사용자의 기존 확정문은 그대로 보존한다.

이 기능은 문자 정보가 있는 디지털 PDF의 보조 근거다. 원본 PDF·입력 이미지 해시, 실제 렌더 픽셀, 앞뒤 네 내용 문자, 부호 순서·개수, 원시 OCR 영역과 표시 문자 좌표를 연결한다. 이미지에서 전각·반각을 추측하거나 PDF의 한자 본문을 OCR 대신 사용하지 않는다. 이미지 프로젝트를 원본 PDF에 연결하는 API는 쪽·DPI·자르기 좌표를 명시해야 하며 실제 RGB 픽셀이 같아야 한다.

숨은 문자·투명 문자·가림·불명확한 위치·지원하지 않는 회전이나 잘라낸 PDF는 근거 부족으로 기록한다. 문자 영역의 RGB 변화 검사는 균일한 배경색에 감춰진 글자를 제외하기 위한 검사이며, 이미지 문자인식의 증명은 아니다. 문자층이 없는 스캔 PDF에서도 기존 v3 검토 후보는 유지하며 자동 확정하지 않는다. 뒤의 근거 부족 기록은 앞서 확인한 보류를 해제하지 않는다.

원시 OCR, 로컬 후보, PDF 보조 확인, AI 응답·제안, 사람의 확정·되돌리기는 별도 이력이다. 저장 시 원시 좌표와 보존한 근거로 판정을 재현하고, 과거 AI 요청은 당시 확인 기록의 ID로 검증하므로 후속 확인으로 과거 내용을 바꾸지 않는다. AI 한자 보호 정책 `source-fidelity-v4`와 프롬프트는 변경하지 않았다.

연어OCR 0.11.0의 비교 편집기는 같은 조건으로 정상 완료한 로컬 OCR 세 개 이상의 결과를 원본 이미지·문맥과 함께 AI로 재검증한다. 원시 OCR, 로컬 후보·영역 재판독, AI 응답·제안, 사람이 확정한 교정은 각각 보존한다. AI가 반환한 문장을 교정문에 자동으로 덮어쓰지 않는다.

## 로컬 후보와 영역 재판독

**로컬 교정·영역** 탭의 **교정 후보 생성**은 `anchored-refinement-v3`를 사용한다. 공백·부호를 제외한 앞뒤 내용이 유일하게 대응하는 위치를 찾고, 실제 원시 문자열과 OCR 상자로 후보를 연결한다. 이 내용 투영은 주소 찾기에만 쓰며 원시 문자·공백·이체자를 정규화하지 않는다. EasyOCR의 부호를 한 글자씩 후보로 가져오되 부호 개수가 다른 구간이나 한쪽 괄호 폭만 바꿔 짝을 깨는 변경은 보류한다. 정확한 대응 위치는 문자가 맞다는 증명이 아니며 모든 후보는 미확정이다.

한자는 기준 엔진과 다른 독립 **세 계열 이상**, 한글은 **두 계열 이상**이 같은 수정 문자열을 읽고, 같은 위치를 확인할 수 있는 다른 판독이 반대하지 않아야 후보로 만든다. RapidOCR와 PaddleOCR는 한 계열로 계산한다. 기준이 GLM이어도 다른 엔진의 합의 후보를 찾는다. 이체자·간번체·호환 한자·변형 선택자 보호를 유지하며 이체자 사전을 사용할 수 없으면 한자 후보를 만들지 않는다. 과거 `anchored-refinement-v1`·`v2` 기록과 확정은 당시 구현으로 검증한다.

부호 종류 변경은 기준 외 독립 두 계열의 정확한 수정 문자 동의가 필요하다. 직접적인 Unicode 전각·반각 변경은 정확한 수정 문자 한 계열과 같은 부호 종류·순서·개수 두 계열 이상의 동의를 요구하며, 원래 폭을 읽은 계열이 수정 폭을 읽은 계열보다 많으면 보류한다. 어느 경로든 같은 위치의 다른 부호 종류·개수는 반대 근거로 보류한다. `guard_evidence`에 원시 문자·위치·해시·계열별 찬반을 저장하며, 이것을 AI 승인이나 이미지에서 문자 폭을 입증한 것으로 표시하지 않는다.

교정문에서 짧은 범위를 선택한 뒤 **선택 영역 재판독**을 실행하거나 **어려운 곳 2개**로 한글·한자 불일치 영역을 제안받을 수 있다. 사용할 로컬 엔진을 직접 선택한다. 양쪽 원문·좌표를 확인할 수 없거나 사람이 수정한 범위이면 추측해서 읽지 않는다. 여러 엔진이 같은 글자를 읽어도 자동 확정하지 않는다.

영역 재판독의 전체 원시 문자열·좌표·완료 여부는 `region_readings`에 보관하며, 전체 쪽의 `runs`를 바꾸지 않는다. 잘린 응답·취소·실패를 완료 판독으로 사용하지 않는다. `refinement_reviews`는 로컬·영역 교정 제안, `refinement_decisions`는 사람의 채택·거절·되돌리기다. 채택해야 교정문과 `edits`에 반영된다.

새 AI 계획은 유효한 미확정 로컬 후보와 영역 재판독 문맥을 포함하며, 겹치는 영역의 실제 원본 조각도 대상당 최대 두 개까지 보낼 수 있다. 계획에 이미지·호출 수를 표시하고 지문을 고정한다. AI는 이 근거를 정답으로 취급하지 않고 원본 이미지와 다시 대조한다. 요청·응답과 그때의 미확정 근거를 저장하므로 이후 사람이 채택하거나 거절해도 과거 요청을 재현할 수 있다. **쪽 전체 이미지 검증**을 선택하면 불일치만이 아니라 해당 쪽 전체 문장을 나누어 이미지로 확인한다.

로컬·영역 후보는 AI 요청의 원래 교정문에 아직 적용하지 않은 상태다. AI가 이미지로 확인한 변경은 로컬 후보와 같은 내용이어도 원래 문자의 정확한 위치로 다시 제안해야 한다. AI가 변경을 제안하지 않았다는 이유로 로컬 후보를 승인한 것으로 취급하지 않는다. 모든 단계는 사람이 채택하기 전까지 별도 제안이다.

간체 문서의 기본 번체 변환은 꺼져 있다. 번체 변환은 명시적으로 선택할 때만 제안하며, 원문 부호를 단순한 편집 양식에 맞춰 전각·반각으로 일괄 바꾸도록 지시하지 않는다. 실제 정확도 비교에서도 원문 간체·번체·이체자·부호를 구분한다.

## 원본 한자 보호

이미지 판독 단계에서 원본의 이체자·간체·번체를 다른 표기로 바꾸는 AI 제안은 원문 보호 대상으로 보류한다. 문자 관계 사전은 변경 종류를 판별하는 데만 사용하며 원시 OCR이나 비교용 정답을 정규화하지 않는다. 사용자가 별도로 선택한 번체 편집 제안은 이미지 판독과 구분한다.

그 밖의 한자 변경도 AI의 확신만으로 채택 가능한 제안이 되지 않는다. 기준 엔진 외에 서로 다른 두 로컬 OCR 계열이 정확한 해당 위치의 수정 문자를 뒷받침해야 한다. RapidOCR 모바일과 PaddleOCR 서버형은 같은 계열로 센다. 지원하지 않는 언어, 잘린 판독, 모호한 위치는 동의 근거가 아니다. 근거가 부족한 제안은 사유와 함께 보존하며 원본을 보고 직접 교정할 수 있다. 이 보수적인 기준은 올바른 AI 교정도 일부 보류할 수 있다.

AI가 반환한 원래 제안과 프로그램의 보호 판정은 별도 기록이다. 보류해도 AI 응답의 수정 전후 문자나 불확실성 값을 고쳐 쓰지 않는다. 과거에 사람이 확정한 수정 이력은 소급 변경하지 않으며, 아직 결정하지 않은 제안에는 현재 보호 검사를 적용한다. 저장된 응답을 새 보호 검사로 재평가한 시험과 새 API 응답을 받은 시험도 구분해서 보고한다.

`source-fidelity-v4`는 v3의 부호 검증과 v2의 한자 보호를 유지한다. 주변 공백·부호 차이 때문에 정확한 위치 동의를 찾지 못한 경우 양쪽 네 글자의 내용 문맥이 원문과 각 OCR에서 유일한 위치를 가리켜야 하며, 바꿀 글자 자체는 원시 문자열과 완전히 같아야 한다. 이 추가 경로에서는 같은 위치를 확인할 수 있는 다른 OCR 하나라도 원래 글자나 제3의 글자를 읽으면 보류한다. 간번체·이체자·호환 한자·변형 선택자는 이 위치 찾기에서도 같은 글자로 접지 않는다.

문장부호의 종류와 정확한 전각·반각 표기는 별개로 검사한다. Unicode의 일대일 전각·반각 관계에 해당하는 **부호만** 폭이 다른 경우, 기준 외 한 OCR 계열이 정확한 수정 문자를 읽고 서로 다른 두 계열 이상이 같은 종류·순서·개수의 부호를 읽어야 한다. 같은 위치의 다른 부호 종류나 개수는 반대 근거로 보류한다. 이 완화는 해당 범위를 원본 이미지에 연결한 AI 요청에만 사용하며, 이미지가 제공됐다는 사실 자체가 판독 정답을 보장하지는 않는다. 부호 종류 변경·삽입·삭제에는 기존 두 계열의 정확한 수정 문자 동의를 유지하고 다른 부호 종류를 읽은 근거가 있으면 추가 보류한다.

일반 NFKC나 한자 정규화는 사용하지 않는다. 부호 종류 비교용 키와 실제 수정 문자열은 구분해서 기록하며 원시 OCR·AI 제안·정답의 전각·반각을 고쳐 쓰지 않는다. 제안이 공백을 바꾸지 않을 때만 대상 밖 공백 차이를 위치 찾기에서 제외하고, 수정 대상은 원시 문자열과 정확히 비교한다. 공백 변경에는 전체 구간의 정확한 근거가 필요하다. 주변의 바뀌지 않은 글자를 포함한 넓은 제안은 유일한 최소 부호 변경 위치를 확인할 수 있을 때만 그 부분의 근거를 별도 계산한다. 반복 부호의 어느 위치인지 모호하거나 한자·변형 선택자까지 실제로 바꾸는 혼합 제안에는 이 완화를 사용하지 않는다.

v4는 기준 OCR 문장에서 정확한 폭으로 짝이 맞던 괄호의 한쪽만 바꾸어 짝을 깨는 부호 폭 교정을 추가 보류한다. 실제 변경만 검사하므로 바뀌지 않은 공백·부호·문자를 포함한 넓은 제안이나 다른 부호의 동시 폭 변경으로 검사를 우회하지 못한다. 같은 제안에서 두 끝을 함께 바꾸어 짝이 유지되는 경우에는 이 추가 사유로 보류하지 않는다. 원래 짝이 모호하거나 이미 폭이 섞인 경우에는 짝을 추측하지 않는다. 이는 기준문 구조를 보존하는 검사이며 원본 이미지의 코드포인트를 증명하지 않는다. 원본에 실제로 혼합 폭 괄호가 있다면 올바른 수정도 보류할 수 있으므로 직접 원본을 대조해야 한다.

신규 요청은 `comparison-ai-v12`를 사용한다. 문서 양식이나 모델의 확신뿐 아니라 주변 공백·자간·양끝 맞춤·넓은 빈 공간도 원본 부호의 Unicode 전각·반각 코드를 증명하지 못함을 명시한다. 이미지로 두 표기를 구별할 수 없으면 원래 폭을 유지하거나 불확실로 표시한다. v11의 주변 간격을 살피라는 지시와 폭을 추측하지 말라는 지시 사이의 모순을 제거했다. 한자 보호와 부호의 독립 엔진 근거를 요구하는 `source-fidelity-v4`는 유지한다. 과거 v11 기록도 같은 v4 정책으로 검증하며 v11·v12 근거를 더 약한 v3 정책으로 바꾸어 채택할 수 없다. 픽셀 간격 측정 시제품은 원문 코드포인트를 안정적으로 판별하지 못해 자동 판정에 넣지 않았다.

이전 v1·v2·v3의 저장 판정과 확정 이력은 고정한 당시 규칙으로 재검증한다. 미확정 제안을 새 v4 근거로 사람이 채택하면 기존 AI 기록을 수정하지 않고, 그때의 근거·정책·원문 지문·정확한 채택 위치를 새 결정에 별도로 연결한다. 저장 후 재열기와 되돌리기에서도 이 연결을 검증하며 신규 v4 응답의 채택 근거를 더 약한 과거 정책으로 바꿔치기하지 못하게 한다. 이전 v3에서 확정한 수정이 현재 괄호 보호에 걸리더라도 과거 확정은 유지하며, 되돌린 뒤 미확정으로 검토할 때 현재 보호 검사를 적용한다.

## 작업 흐름

1. 기존 설정에서 Gemini·OpenAI·Anthropic 중 사용할 제공사와 이미지 입력을 지원하는 모델·API 키를 선택한다. 비교 창은 현재 선택한 제공사만 사용한다.
2. 원본을 선택하고 **3엔진 비교·교정**을 연다. 대상 쪽의 로컬 세 엔진 판독을 완료한다.
3. AI 검증에서 현재 쪽 또는 지정 범위와 번체자·중문부호 교정 정책을 선택한다. 요청 전에 실제 제공사·모델·문서·쪽 범위·요청 수·이미지 전송 범위를 확인한다.
4. AI는 엔진 불일치를 이미지로 재판독하고, 이어서 선택한 쪽의 교정문에서 번체자·중문부호 제안을 만든다. 앞 단계의 AI 결과는 잠정 근거로 구분하며 사람이 확정한 결과로 취급하지 않는다.
5. AI 제안 목록에서 수정 전후·사유·단계·불확실 여부를 원본과 대조하고 채택하거나 기각한다. 채택해야 현재 교정문과 사람의 수정 이력에 반영된다. 되돌리기는 확정 이력을 추가하며 원시 판독과 AI 응답은 그대로 둔다.

AI 호출은 실행 버튼으로 지정한 작업에만 적용한다. 문서를 열거나 설정을 바꾸는 것만으로 전송하지 않는다. API 이용료는 제공사별로 별도이며 이미지·문맥과 출력 길이에 따라 달라진다. 프로그램은 요청 수를 제한하며 다른 모델이나 제공사를 자동으로 시험하지 않는다.

OpenAI 연결은 Responses의 텍스트·이미지 입력과 JSON Schema 출력 형식을 사용한다. 이미지와 문맥을 같은 요청으로 보내고, 응답은 저장 전에 별도로 검사한다. API 형식 근거는 [공식 이미지 입력 안내](https://developers.openai.com/api/docs/guides/images-vision)와 [구조화 출력 안내](https://developers.openai.com/api/docs/guides/structured-outputs)다.

## 원본과 언어 정책

시각 재검증은 엔진 불일치 위치와 주변 문맥을 사용한다. 위치를 신뢰할 수 있으면 원본의 확대 영역을 보내고, 위치를 안전하게 대응하지 못하면 선택한 원본 쪽의 이미지를 사용한다. 불일치가 많은 쪽은 해당 쪽의 문장을 묶어 검증하고 이 범위를 전송 계획에 표시한다. 범위를 일부만 몰래 잘라서 보내지 않는다.

**현재 쪽·지정 범위**의 번체자·부호 검증은 해당 쪽의 텍스트 전체를 나누어 처리하므로 세 엔진이 같은 간체자로 인식한 부분도 대상이 된다. **선택한 불일치**는 선택한 위치와 주변 문맥에 한해 두 단계를 실행한다. 범위 밖의 쪽이나 편집용 DOCX·HWPX 정답은 전송하지 않는다.

번체자·중문부호 정책은 화면과 요청 기록에 명시한다. 이체자·호환 한자·변형 선택자를 임의로 정규화하지 않는다. 문맥으로 보이지 않는 글자를 지어내거나 한국어·숫자·원래 의미를 재작성하도록 지시하지 않는다. 판독이 불확실한 제안은 확정 가능한 제안과 구분한다.

AI 응답은 엄격한 형식·문자 범위·수정 전 문자열 검사를 통과해야 제안으로 사용할 수 있다. 모델이 JSON 형식을 지켰다는 사실은 판독 정확도를 뜻하지 않는다. 같은 자리를 서로 다르게 고친 제안, 사람이 이미 수정한 자리, 이전 원시 판독에 기반한 제안은 현재 문장에 무조건 적용하지 않는다.

## 응답 잘림 예방과 위치 복원

0.9.1의 기본값은 문장 범위 최대 480자, 요청당 대상 1개, 출력 상한 8,192토큰이다. Gemini 3 계열에서는 낮은 사고량을 명시한다. 시각 재검증과 번체·부호 검증은 단계별 응답 형식을 사용한다. 실제 요청 수와 출력 예산은 전송 계획에 표시하며, 누락한 범위를 완료로 표시하거나 잘린 응답을 임의로 이어 붙이지 않는다. 자동 추가 호출·다른 모델 대체·키 회전은 하지 않는다. Gemini 설정은 [공식 사고 수준 안내](https://ai.google.dev/gemini-api/docs/generate-content/thinking?hl=en)와 [구조화 출력 안내](https://ai.google.dev/gemini-api/docs/structured-output)를 기준으로 한다.

같은 승인 대상의 OCR 문자열에 글자별 Unicode 코드포인트 위치표를 붙여 모델이 숫자 위치를 직접 셈하지 않고 참조하도록 한다. 위치표에는 이미 전송 대상인 OCR 문장만 포함하며 원본 HWPX·DOCX나 정답 자료를 추가하지 않는다.

AI가 반환한 수정 전 인용문이 보고한 숫자 위치와 다르면, 같은 승인 대상 안에서 그 문자열이 **정확히 한 번** 나타나는지 확인한다. 이 조건을 만족할 때만 검증용 위치를 복원한다. 공백·한자·부호 정규화, 유사 문자열 검색, 가장 가까운 위치 선택은 사용하지 않는다. 반복 인용·찾을 수 없는 인용·빈 문자열 삽입의 잘못된 위치·불완전 응답은 복원하지 않는다. 복원한 응답도 기존 범위·겹침·문자 정책 검사를 모두 통과해야 한다.

원래 AI 응답은 그대로 보존하며 위치 복원의 보고값과 검증값은 별도 근거로 남긴다. 복원은 AI 제안을 검토할 수 있게 하는 절차다. 사람의 채택으로 기록하거나 현재 교정문에 자동 적용하지 않는다.

2026-10-18의 잔여 부호 16건 시험은 `punctuation-region-recheck-v1` 전용 프롬프트로 Gemini `gemini-3.1-pro-preview`를 실제 16회 호출했다. 원본 PDF의 600dpi 문맥·확대 이미지 두 장과 대상 부호를 가린 OCR 문맥, 순서를 섞은 두 후보만 전송했다. HWPX·DOCX 정답, 기존 AI 사유, 후보의 원문/교정안 역할은 전송하지 않았다. 16건 모두 완전한 응답을 받았으며 자동 재시도·키 회전은 없었다.

이 시험의 원시 제공사 응답, 응답 텍스트, 기계 판정과 평가용 적용 여부는 `work/ocr-punctuation-live-v1`에 별도 보존한다. 기존 프로젝트의 `runs`·`ai_reviews`·`ai_decisions`·`edits`를 고쳐 쓰거나 사람의 확정으로 기록하지 않는다. 평가에서는 기존에 선택된 541건 중 대상 16건만 보류 가능하며, 보류 자리에 다른 미선택 제안을 승격시키지 않는다. 실패·잘림·형식 오류는 기존 결과를 유지하여 통신 실패 때문에 정확도가 좋아진 것처럼 계산하지 않는다. 이는 전용 실험 경로이며 일반 편집기의 자동 적용 정책이나 설치판을 변경한 것은 아니다.

- `runs`: 로컬 엔진의 원시 판독·좌표·모델·해시. AI 검증으로 변경하지 않는다.
- `ai_reviews`: AI 요청의 원본·텍스트·판독 근거 지문, 제공사·모델·정책·이미지 영역 정보, 응답 원문과 교정 제안. 원본 한자 보호의 기계 판정은 원래 응답과 구분하여 기록한다. 실패 응답도 성공한 교정으로 표시하지 않는다.
- `ai_decisions`: 사람이 AI 제안을 채택·기각·되돌린 이력. 새 채택의 `source_fidelity_acceptance`는 당시 보호 판정과 원래 AI 기록·원문·위치를 연결하며, 대응하는 `edits`의 지문으로 다시 확인한다.
- `edits` / `review_history`: 현재 교정문에 반영한 수정과 사람이 부여한 원본 대조 완료 상태.

API 키와 이미지의 Base64 본문은 프로젝트에 저장하지 않는다. AI 응답과 교정문은 개인 문서 내용이므로 원본·복구 사본과 함께 사용자 작업 폴더에만 보관한다. 배포물·소스·공개 테스트에 넣지 않는다.

정확도 평가용 문장도 사람의 확정 이력으로 저장하지 않는다. 같은 120개 영역의 주력 원시 → 로컬 후보 → 영역 후보 → AI 제안을 별도로 비교한다. 단계가 모두 완료되지 않은 평가 단위는 이전에 완료한 단계의 문장을 유지한다. AI 단계가 완료되면 명시적으로 검증한 AI 제안만 원래 기준문에 적용해 평가하며, AI가 재제안하지 않은 로컬·영역 후보를 몰래 이어 붙이지 않는다. 전체 120개 분모와 완료·미완료 범위, 순 오류 감소와 원래 맞던 글자의 오교정을 각각 보고한다.

완료한 요청마다 프로젝트와 복구 사본을 저장한다. 중지하면 완료한 응답을 보존하고 다음 요청을 보내지 않는다. 이미 시작한 제공사 요청은 응답 또는 제한 시간까지 기다릴 수 있다. 원본·현재 교정문·판독 근거가 바뀌면 기존 전송 계획을 중단하고 새 계획을 만든다. 재개는 동일한 조건으로 완료한 요청을 재사용하며 강제 실행은 이전 AI 이력을 보존하고 새 요청을 만든다.

이전 0.8.0 프로젝트도 열 수 있다. AI 기록이 없는 프로젝트는 빈 AI 이력으로 취급하며 원시 OCR·기존 교정 이력을 유지한다.
# 이미지 OCR 근거 재검사와 연속 한자 오류 (2026-10-18)

편집기의 **이미지 OCR 근거 재검사**는 저장된 이미지 OCR의 원시 판독으로 미확정 로컬·영역·AI 제안을 다시 확인한다. 원본 PDF 문자 정보나 HWPX·DOCX 정답은 사용하지 않으며 새 OCR·API 호출도 하지 않는다. **교정 후보 생성**은 기존 v3 후보와 별도의 v4 한자 후보를 만들고 이 검사를 함께 기록한다. PDF 문자 정보는 별도의 **PDF 부호 확인**에서만 선택적으로 확인한다.

과거 제안도 현재 화면과 직접 채택 경로에서 한자 이체·간번체·호환 문자·변형 선택자 보호를 거친다. 부호 폭만 다른 제안은 기존 기준을 유지한다. 부호 종류 변경이나 삭제는 기준 엔진을 제외한 독립 두 계열이 유일한 원문 주소의 원래 부호 전체에 동의하면 추가 보류한다. RapidOCR와 Paddle 서버는 한 계열이다. 새로운 허용 권한을 주는 검사가 아니며 이전 보호·완료·위치 검사를 우회하지 않는다.

사용자가 명시적으로 선택한 번체 편집은 저장된 요청의 편집 단계·제안 종류·사용자 옵션을 인증한 경우에만 이 추가 이체 관계 보류에서 제외한다. 기존 AI 원본 보호 검사는 계속 적용하며, 호환 한자·변형 선택자 검사는 생략하지 않는다. 보류된 후보를 직접 채택하려는 시도는 교정문과 기록을 변경하지 않는다. 허용된 후보의 새 채택 시에만 당시 검사 근거와 사람의 결정을 함께 연결한다.

`image_only_checks`는 원시 판독, `refinement_reviews`, `ai_reviews`, 사람의 `edits`·결정 이력과 분리한 추가 기록이다. 저장·재열기에서 보존된 부모 원시와 대상 제안으로 판정을 재현한다. 과거 사람이 확정한 교정은 소급 변경하지 않으며 새 채택에는 당시 검사 근거를 연결한다. 후속 AI에는 보류된 로컬 후보를 전달하지 않고, 이전 AI 요청이 캡처한 근거는 이후 검사와 구분해 검증한다.

v4 한자 후보는 고유한 양쪽 내용 문자 4자, 최대 8자의 동일 길이 불일치 구간으로 원문 위치를 찾는다. 한 번에 한 글자만 제안하며 기준 엔진 외 독립 세 계열 각각의 실제 OCR 영역과 일치가 필요하다. 원시 문자·공백을 정규화하지 않는다. 기존 이체자 보호에 고정된 Unicode 17.0.0 Unihan 관계와 발음 자료를 추가한다. 같은 발음은 이체자라는 증명이 아니라 새 후보를 보류할 주의 신호로만 사용하며, 이 추가 기준을 기존 v3 후보에 소급 적용하지 않는다. 누락 구절의 자동 삽입은 이번에 추가하지 않았다.

## 2026-10-18 잔여 한자·과잉 보류 후속 검증

`work/ocr-image-recall-v2`에서는 신규 한자 9건 전부를 원본에서 직접 렌더링한 600/1200dpi 이미지로 실제 재검증했다. 이전 300dpi 페이지와 픽셀 동일성을 확인했고, 두 후보 역할과 이전 AI 응답을 숨겼다. 후보별 구별 획·반대 근거·위치·불확실성을 분리하지만 자연어 획 설명의 진실을 자동 증명하지는 않는다. 같은 OCR 계열의 판독 충돌은 추가 보류한다. 원래 蒌를 유지하게 되어 같은 120영역에서 오류 5,926자·한자 510자·오교정 0건, 기존 올바른 1,106건과 1,865건 집합 모두 유지다.

올바른 보류 41건 중 40건은 부호 폭, 1건은 한자 재검증의 원래 후보 선택 때문이다. 독립 OCR의 정확한 수정 문자 다수결로 폭 14건을 다시 허용한 시험은 14건 전부 오교정이어서 기본 정책에 채택하지 않았다. 올바른 41건은 이번에도 복원하지 못했다. 실패한 재허용 시험·추천 단계의 사후 선택·소폭의 전체 오류 감소를 함께 보고한다.

새 읽기전용 `evaluate_incremental_candidate` API는 원래 후보와 실제 OCR 지문·주소·기존 보호를 다시 검사한다. 기본값은 폭 변경 보류이며 표수는 진단 근거로만 반환한다. `diagnostic_width_consensus=True`는 명시적 개발 비교이고 사용자의 확정이 아니다. 기존 v1 검사·채택 재현, UI 자동 적용 정책과 설치판은 변경하지 않았다. 원시/AI 응답/제안은 불변이고 새 기계 판단은 별도 검토 자료다.
