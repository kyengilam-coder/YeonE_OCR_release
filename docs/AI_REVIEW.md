# AI 재검증과 교정 제안

연어OCR 0.9.0의 비교 편집기는 세 로컬 OCR 결과를 원본 이미지·문맥과 함께 AI로 재검증한다. 원시 OCR, AI 응답·제안, 사람이 확정한 교정은 각각 보존한다. AI가 반환한 문장을 교정문에 자동으로 덮어쓰지 않는다.

## 작업 흐름

1. 기존 설정에서 Gemini·OpenAI·Anthropic 중 사용할 제공사와 이미지 입력을 지원하는 모델·API 키를 선택한다. 비교 창은 현재 선택한 제공사만 사용한다.
2. 원본을 선택하고 **3엔진 비교·교정**을 연다. 대상 쪽의 로컬 세 엔진 판독을 완료한다.
3. AI 검증에서 현재 쪽 또는 지정 범위와 번체자·중문부호 교정 정책을 선택한다. 요청 전에 실제 제공사·모델·문서·쪽 범위·요청 수·이미지 전송 범위를 확인한다.
4. AI는 엔진 불일치를 이미지로 재판독하고, 이어서 선택한 쪽의 교정문에서 번체자·중문부호 제안을 만든다. 앞 단계의 AI 결과는 잠정 근거로 구분하며 사람이 확정한 결과로 취급하지 않는다.
5. AI 제안 목록에서 수정 전후·사유·단계·불확실 여부를 원본과 대조하고 채택하거나 기각한다. 채택해야 현재 교정문과 사람의 수정 이력에 반영된다. 되돌리기는 확정 이력을 추가하며 원시 판독과 AI 응답은 그대로 둔다.

AI 호출은 실행 버튼으로 지정한 작업에만 적용한다. 문서를 열거나 설정을 바꾸는 것만으로 전송하지 않는다. API 이용료는 제공사별로 별도이며 이미지·문맥과 출력 길이에 따라 달라진다. 프로그램은 요청 수를 제한하며 다른 모델이나 제공사를 자동으로 시험하지 않는다.

OpenAI 연결은 Responses의 텍스트·이미지 입력과 JSON Schema 출력 형식을 사용한다. 이미지와 문맥을 같은 요청으로 보내고, 응답은 저장 전에 별도로 검사한다. API 형식 근거는 [공식 이미지 입력 안내](https://developers.openai.com/api/docs/guides/images-vision)와 [구조화 출력 안내](https://developers.openai.com/api/docs/guides/structured-outputs)다.

## 원본과 언어 정책

시각 재검증은 엔진 불일치 위치와 주변 문맥을 사용한다. 위치를 신뢰할 수 있으면 원본의 확대 영역을 보내고, 위치를 안전하게 대응하지 못하면 선택한 원본 쪽의 이미지를 사용한다. 불일치가 많은 쪽은 해당 쪽의 문장을 묶어 검증하고 이 범위를 전송 계획에 표시한다. 범위를 일부만 몰래 잘라서 보내지 않는다.

**현재 쪽·지정 범위**의 번체자·부호 검증은 해당 쪽의 텍스트 전체를 나누어 처리하므로 세 엔진이 같은 간체자로 인식한 부분도 대상이 된다. **선택한 불일치**는 선택한 위치와 주변 문맥에 한해 두 단계를 실행한다. 범위 밖의 쪽이나 편집용 DOCX·HWPX 정답은 전송하지 않는다.

번체자·중문부호 정책은 화면과 요청 기록에 명시한다. 이체자·호환 한자·변형 선택자를 임의로 정규화하지 않는다. 문맥으로 보이지 않는 글자를 지어내거나 한국어·숫자·원래 의미를 재작성하도록 지시하지 않는다. 판독이 불확실한 제안은 확정 가능한 제안과 구분한다.

AI 응답은 엄격한 형식·문자 범위·수정 전 문자열 검사를 통과해야 제안으로 사용할 수 있다. 모델이 JSON 형식을 지켰다는 사실은 판독 정확도를 뜻하지 않는다. 같은 자리를 서로 다르게 고친 제안, 사람이 이미 수정한 자리, 이전 원시 판독에 기반한 제안은 현재 문장에 무조건 적용하지 않는다.

## 기록과 복구

- `runs`: 로컬 엔진의 원시 판독·좌표·모델·해시. AI 검증으로 변경하지 않는다.
- `ai_reviews`: AI 요청의 원본·텍스트·판독 근거 지문, 제공사·모델·정책·이미지 영역 정보, 응답 원문과 교정 제안. 실패 응답도 성공한 교정으로 표시하지 않는다.
- `ai_decisions`: 사람이 AI 제안을 채택·기각·되돌린 이력.
- `edits` / `review_history`: 현재 교정문에 반영한 수정과 사람이 부여한 원본 대조 완료 상태.

API 키와 이미지의 Base64 본문은 프로젝트에 저장하지 않는다. AI 응답과 교정문은 개인 문서 내용이므로 원본·복구 사본과 함께 사용자 작업 폴더에만 보관한다. 배포물·소스·공개 테스트에 넣지 않는다.

완료한 요청마다 프로젝트와 복구 사본을 저장한다. 중지하면 완료한 응답을 보존하고 다음 요청을 보내지 않는다. 이미 시작한 제공사 요청은 응답 또는 제한 시간까지 기다릴 수 있다. 원본·현재 교정문·판독 근거가 바뀌면 기존 전송 계획을 중단하고 새 계획을 만든다. 재개는 동일한 조건으로 완료한 요청을 재사용하며 강제 실행은 이전 AI 이력을 보존하고 새 요청을 만든다.

이전 0.8.0 프로젝트도 열 수 있다. AI 기록이 없는 프로젝트는 빈 AI 이력으로 취급하며 원시 OCR·기존 교정 이력을 유지한다.
