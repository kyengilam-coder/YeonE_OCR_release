# 로컬 OCR 실행 환경

연어OCR 0.10.0 설치 파일은 PP-OCRv6 medium의 독립 Python 실행 환경과 검출·인식 모델을 포함합니다. 설치 후 별도 Python 설치나 모델 다운로드 없이 간체·번체 가로쓰기와 세로쓰기를 실행합니다. 비교 창은 포함된 PP-OCRv6를 기본 선택합니다. PP-OCRv5·EasyOCR·Tesseract는 아래 절차로 별도 설치합니다. 사용자 문서는 배포물에 포함하지 않습니다. 재사용한 소스의 원래 SHA-256은 `AB_OCR_PROVENANCE.json`에 기록했습니다. 로컬 인식 뒤 실행하는 별도 AI 검증은 [AI_REVIEW.md](AI_REVIEW.md)를 따릅니다.

0.11.0부터 설치판의 PP-OCRv6는 이전에 저장한 엔진 폴더와 관계없이 `프로그램 폴더/tools/ppocrv6/runtime/python.exe`와 `models/*.onnx`를 자동으로 찾습니다. 기존 폴더 설정은 다른 엔진에 계속 적용하며 바꾸지 않습니다. 포터블 단일 실행 파일에는 이 대용량 환경이 포함되지 않습니다. 한국어는 지원하지 않으므로 한글·한자 혼용 프로필에는 Tesseract의 해당 언어 모델이 필요합니다.

**자동 로컬 OCR·비교**의 기본값은 자동 엔진 선택입니다. 문서 종류·읽기 방향에 맞고 설치된 엔진을 하나씩 실행해 쪽마다 결과를 선택합니다. 누락·깨진 문자·지원 문자·엔진 간 일치도를 근거로 추정하며, 서로 다른 엔진의 confidence를 정확도처럼 비교하지 않습니다. 원문과 선택 근거를 보관하고 직접 교정·사람의 기준 선택은 유지합니다. 메모리 할당 여유가 적으면 무거운 엔진을 제외합니다. [자동 선택 정책](AUTOMATIC_OCR.md)

Tesseract, RapidOCR, EasyOCR는 서로 다른 원시 판독을 반환합니다. 로컬 인식 중 API를 호출하거나 모델을 다운로드하지 않습니다. RapidOCR·EasyOCR는 별도 Python 환경의 작업자를 실행하며, 작업자의 네트워크 연결을 차단합니다. 모델 파일이 없거나 해시가 달라지면 해당 엔진을 오류로 표시합니다. EasyOCR 번체 세로쓰기는 아래에 설명한 두 중국어 인식 모델을 함께 사용합니다.

## 엔진 폴더 선택

엔진 폴더는 다음 구조입니다. 설정에서 고르는 경로는 `tools`를 포함하는 **상위 폴더**입니다.

```text
선택한 폴더/
  tools/tesseract/tesseract.exe
  tools/tesseract/tessdata/*.traineddata
  tools/tesseract/installation.json
  tools/rapidocr/venv/Scripts/python.exe
  tools/rapidocr/models/*.onnx
  tools/rapidocr/installation.json
  tools/easyocr/venv/Scripts/python.exe
  tools/easyocr/models/*.pth
  tools/easyocr/installation.json
```

탐색 순서는 화면에서 선택·저장한 폴더 또는 호출에 명시한 폴더 → `YEONE_OCR_ENGINE_ROOT` 환경 변수 → 호환용 `AB_OCR_ENGINE_ROOT` 환경 변수 → 연어OCR 프로그램 폴더의 설치 → 사용자 설치 폴더입니다. 소스 개발 환경에서는 마지막으로 같은 상위 폴더의 기존 `AB_OCR` 설치도 탐색합니다. 설치판은 이 개발용 탐색을 하지 않습니다. 화면에서 폴더를 선택하면 기존 환경 변수보다 우선하며, 명시한 폴더가 준비되지 않았을 때는 다른 폴더로 넘어가지 않습니다.

연어OCR에서 [엔진 폴더…]로 고른 위치는 공통 설정에 기억하며 다음 비교 창에도 적용합니다. 엔진 폴더를 선택하거나 설치 상태를 확인하는 동작은 모델 다운로드를 실행하지 않습니다.

기존 AB_OCR 설치를 선택해도 Python 코드는 연어OCR에 포함된 작업자를 실행합니다. 기존 설치의 실행 환경·공개 모델만 읽으며, 다른 프로젝트 소스나 사용자 문서를 가져오지 않습니다. 대용량 가중치를 복사할 필요가 없습니다. 실행마다 선택 경로를 함수에 전달하므로 병렬 작업이 전역 환경 변수를 바꾸지 않습니다.

기본 사용자 설치 폴더는 `%LOCALAPPDATA%\YeonE_OCR\local-engines`입니다. 새 PC에는 아래 설치 작업이 필요합니다. 일반 연어OCR의 AI 판독·책갈피·이미지 입력은 로컬 엔진 설치와 독립적으로 사용할 수 있습니다.

## 새 PC에 설치

설치 스크립트는 사용자가 실행할 때 공개 패키지·모델만 다운로드합니다. 모델의 SHA-256, 실제 패키지 버전, 내려받은 패키지의 URL·해시를 설치 폴더에 기록합니다. Windows x64 Python 3.14.5에서 검증했으며, 신경망 엔진의 고정 의존성은 별도 환경에 설치합니다. Tesseract 배포 압축을 풀 때는 기존 Bandizip 또는 7-Zip이 필요합니다.

소스 폴더에서 PowerShell로 실행합니다. 설치판에도 `scripts`와 이 문서를 허용 목록으로 포함하며, 설치 스크립트 실행에는 별도 Python이 필요합니다.

```powershell
$ocrRoot = Join-Path $env:LOCALAPPDATA 'YeonE_OCR\local-engines'
py -3.14 scripts/install_tesseract.py --root $ocrRoot
py -3.14 scripts/install_rapidocr.py --root $ocrRoot
py -3.14 scripts/install_easyocr.py --root $ocrRoot
```

`--root`는 소스 프로젝트일 필요가 없습니다. Tesseract는 레지스트리·PATH를 변경하거나 관리자 설치 프로그램을 실행하지 않고, 검증한 배포 파일을 전용 폴더에 풉니다. RapidOCR와 EasyOCR는 `venv`에 설치합니다. 설치 중 다운로드에는 인터넷이 필요합니다. 인식 중에는 인터넷이 필요하지 않습니다.

런타임 점검 예:

```python
from ab_ocr.ocr import doctor
from ab_ocr.runtime import default_engine_root

root = default_engine_root()
for engine in ('tesseract', 'rapidocr', 'easyocr'):
    status = doctor(engine=engine, engine_root=root)
    print(engine, status['available'], status['languages'])
```

## 언어·판독 결과 보존

### PP-OCRv6 medium 추가

PP-OCRv6 medium은 선택형 네 번째 엔진(`ppocrv6`)입니다. 기존 RapidOCR 3.9.2 / PP-OCRv5를 교체하지 않고 `tools/ppocrv6`의 독립된 RapidOCR 3.10.0 / ONNX Runtime 1.25.1 환경에서 CPU로 실행합니다. 검출·인식 모두 medium 모델이며, Apache-2.0 모델의 공식 SHA-256과 패키지 버전을 `scripts/ppocrv6-lock.json`에 고정합니다. 설치 기록에는 실제 패키지와 배포 URL·해시를 남깁니다.

```powershell
py scripts/install_ppocrv6.py --root $ocrRoot
```

비교 창의 **로컬 엔진 비교·교정 → 설치 확인**에서 `ppocrv6`가 사용 가능한지 확인한 뒤 **PP-OCRv6 medium** 체크박스를 켜고 **현재 쪽 · 선택 엔진 인식**을 누릅니다. 기존 세 엔진이 기본 선택되며 v6는 사용자가 추가로 선택합니다. v6 원문은 별도 탭에 표시되고 기준 판독 선택·불일치 후보 채택·교정·저장·이어 읽기에 참여합니다. 모델 미설치·해시 불일치로 v6가 실패해도 완료한 기존 엔진 결과는 보존합니다.

`chi_sim`, `chi_tra`와 각각의 `+eng`만 지원합니다. 간체·번체는 같은 medium 인식 모델을 사용하고 출력 문자열을 간번체 변환하지 않습니다. 번체 가로쓰기는 아래의 원본 줄 재인식 검증을 사용하며 기본 판독도 보존합니다. 한글·한자 혼용 프로필에서는 v6를 명시적으로 제외하며, 이전 중국어 판독을 혼용 판독의 합의 근거로 사용하지 않습니다. 분류기는 사용하지 않으므로 뒤집힌 스캔은 먼저 방향을 맞추십시오.

명령줄에서 네 엔진을 비교하려면:

```powershell
python -m yeone_ocr compare-engines "책.pdf" --pages 1-3 --profile traditional --engine-root $ocrRoot --engines tesseract rapidocr easyocr ppocrv6
```

`--engines`를 생략하면 기존 세 엔진만 실행하여 기존 호출 동작을 유지합니다. [테스트 PDF 생성·오류율 비교](CHINESE_OCR_TEST.md)를 참고하십시오. v6 설치는 Windows x64 Python 3.13.15에서 실제 검증했습니다.

- Tesseract: 한글·중문·영문 조합을 지원합니다. 언어팩 목록을 실제 설치에서 확인합니다. PSM은 이 엔진 전용입니다. 비교 창의 간체·번체 단일 언어 프로필은 아래의 로컬 자형 검증을 사용하고 기본 TXT·TSV도 보존합니다.
- RapidOCR 3.9.2 / ONNX Runtime 1.25.1: PP-OCRv5 server 검출 모델과 mobile 인식 모델을 기본으로 사용합니다. `chi_sim`과 `chi_tra`는 같은 중국어 모델을 쓰며, 간체·번체 변환은 적용하지 않습니다. 중국어 가로·세로쓰기는 아래의 로컬 자형 보완을 함께 사용하고 기본 신경망 판독도 보존합니다. 한국어 모델은 별도이며 자형 보완을 적용하지 않습니다.
- EasyOCR 1.7.2 / PyTorch 2.10.0+cpu: `chi_sim`, `chi_tra`, `kor`를 각각 지원합니다. CPU로 실행하고 다운로드 옵션을 끕니다.

두 신경망 엔진의 한국어 모델은 한자를 지원하지 않습니다. 한글·한자 혼용에서 두 모델의 같은 누락을 정답 근거로 삼으면 안 됩니다. 세로 문헌도 가로 문헌과 별도로 품질을 검증해야 합니다. 엔진의 confidence 수치는 실측 정확도가 아니며 서로 직접 비교할 수 없습니다.

### PP-OCRv6 번체 가로쓰기 재인식 검증

**PP-OCRv6 medium + 재인식 검증(번체 가로)**은 기본 medium 모델의 검출·인식을 유지하고, 거의 수평인 번체 가로 줄만 원본 해상도에서 다시 자릅니다. 회전·기울기가 큰 영역과 과도한 크기는 보류합니다. 잘라낸 원본과 흰 여백을 추가한 입력을 같은 PP-OCRv6 인식기로 읽습니다. 두 결과가 완전히 같고 기본 판독과 코드 포인트 수가 같을 때 후보로 삼습니다. 원래와 같은 후보는 점수·좌표까지 그대로 유지합니다.

여백 입력에서 한자는 개선되지만 문장부호가 누락되면, 여백을 1픽셀 늘린 입력을 같은 모델로 한 번 더 읽습니다. 서로 다른 두 여백 입력의 한자 순서·개수가 정확히 같고 기본 한자 개수와도 같아야 후보를 만듭니다. 두 입력의 부호는 기본 부호의 순서를 유지한 부분 목록이어야 합니다. 한자는 합의된 모델 판독을 사용하고 부호 위치는 기본 판독을 유지합니다. 숫자·영문·공백·결합 문자·이체자 선택자가 섞인 줄과 한자 개수가 다른 줄에는 이 경로를 사용하지 않습니다. 부호 추가·순서 변경이나 한자 누락을 추측해 메우지 않습니다.

달라진 후보는 기존 로컬 글꼴 자형 검증으로 줄 전체의 재렌더링까지 확인해야 채택합니다. 첫 글자도 틀렸을 수 있으므로 검증 앵커는 합의된 모델 후보에서 가져옵니다. 모든 글자와 부호의 자형·폭·위치를 확인한 전체 줄이 후보와 정확히 같아야 하며, 글꼴 단계만 제시한 다른 문자열은 사용하지 않습니다. 유지한 부호 역시 이미지로 검증돼야 합니다. 합의가 없거나 글꼴이 없거나 시각적 증거가 부족하면 기본 결과를 유지합니다. 정답 사전·특정 글자 치환·간번체 변환·다른 OCR 엔진은 사용하지 않습니다.

`engine_metadata.model_result`에 기본 문자열·좌표·점수를 보존하고, `horizontal_preprocessing.regions`에 원래 사각형·인덱스, 잘라낸 이미지와 여백 입력의 SHA-256, 재인식 문자열·점수, 후보의 출처·완성 문자열, 자형 근거, 적용·보류 이유를 남깁니다. 추가 여백 입력은 `punctuation_retry`에 별도로 기록합니다. 채택한 영역의 최종 confidence는 `null`로 두고 기본·재인식 점수를 따로 보존합니다. `duration_seconds`는 보완 시간도 포함합니다. 설치 글꼴을 사용하는 검증은 깨끗한 일치 글꼴에 유리하며 임의의 고서·스캔에서 같은 개선을 보장하지 않습니다.

`chi_tra`와 `chi_tra+eng`의 가로쓰기에서만 실행합니다. 간체와 세로쓰기는 기본 medium 인식을 유지합니다. 호스트는 `--direction`을 작업자에 전달하며, 캐시에는 번체 가로 프로필에만 정책 `ppocrv6-traditional-original-crop-verified-v2`와 설치 글꼴 지문을 추가합니다. 이에 따라 이전 v1 번체 가로 v6 결과만 재실행하고 다른 결과·이력을 유지합니다.

### Tesseract 간체·번체 자형 보완

비교 창과 `compare-engines`의 중국어 단일 언어 프로필은 **Tesseract + 자형 보완(중국어)**으로 실행합니다. 가로는 `chi_sim`/`chi_tra`와 PSM 6, 세로는 해당 `_vert` 언어팩과 PSM 5를 유지합니다. 기본 Tesseract 실행 파일·모델·사전은 바꾸지 않습니다. 설치된 언어팩의 출력 문자 목록에 없는 이체자·중문부호는 설정 변경만으로 복원되지 않으므로 별도의 이미지 검증을 사용합니다.

중국어 TSV의 단어 좌표는 겹치거나 글자의 일부만 포함할 수 있습니다. 따라서 level 4의 줄·열 영역에 여백을 더해 한 번만 검증합니다. 독립적으로 출력된 TXT의 비어 있지 않은 줄과 TSV 줄의 순서·문자열이 공백을 제외하고 모두 대응해야 이 단계를 시작합니다. 대응이 불확실하거나 단어 좌표가 남으면 원래 판독을 유지합니다. 가로는 공통 자형 검증의 전체 줄 재렌더링, 세로는 빈 공간 분할과 모든 글자의 높은 자형 일치도·후보 간 차이를 요구합니다. 열 순서는 Tesseract의 오른쪽→왼쪽 출력을 유지합니다.

검증된 줄만 대체하고, 나머지는 원래 TXT 공백·줄바꿈과 단어 좌표·점수를 그대로 둡니다. 빈 문단과 마지막 줄바꿈도 유지합니다. 기본 TXT·단어 목록·원시 TSV는 `engine_metadata.model_result`에 저장하며 `glyph_verification`에 TXT 줄 대응, 원래 인덱스, 이미지 지문, 후보, 적용·보류 근거를 기록합니다. 보완 영역의 confidence는 `null`입니다. 정책 `tesseract-chinese-line-glyph-verified-v1`과 설치 글꼴 SHA-256으로 캐시를 갱신합니다.

`ab_ocr.ocr.recognize_file`의 기본 호출은 순수 Tesseract 출력을 유지합니다. 위 동작을 직접 사용할 때는 `verify_chinese_glyphs=True`를 명시하며 `chi_sim`, `chi_tra`, `chi_sim_vert`, `chi_tra_vert` 중 단일 언어만 지원합니다. 한글·혼용 프로필은 이 보완을 사용하지 않습니다. 설치 글꼴이 없거나 근거가 부족하면 원래 판독을 반환합니다. 정답 파일이나 다른 OCR 판독을 사용하지 않으며 외부 API·다운로드는 없습니다. 설치 글꼴과 일치하는 깨끗한 인쇄체에 유리한 보조 인식이며, 임의의 스캔·고서 정확도를 보장하지 않습니다. 후보 은행에 약 226MB의 추가 배열 메모리와 처리 시간이 필요할 수 있습니다.

### 세로쓰기 열 순서와 원시 결과 보존

**세로쓰기**를 선택하면 PP-OCRv5(RapidOCR), PP-OCRv6, EasyOCR 모두 검출한 좌표로 열을 오른쪽부터 왼쪽으로 정렬하고, 같은 열의 조각은 위에서 아래로 읽습니다. 글자·이체자·부호 자체는 바꾸지 않으며 인식하지 못한 문자를 채우지 않습니다. 정렬 전 문자열과 좌표는 `engine_metadata.raw_engine_result`에 보존하고, `source_line_indices`에는 정렬 전 영역 배열의 인덱스(0부터 시작)를 기록합니다. 빈 문자열인 검출 영역도 기록에 남깁니다.

정렬 정책 버전을 캐시에 포함하므로 정렬을 적용하지 않은 세로 판독은 다음 인식에서 갱신되고 이전 판독 이력도 남습니다. 이미 같은 정렬 정책을 사용한 v6 결과는 재사용할 수 있습니다. 가로쓰기에는 이 정렬을 적용하지 않으며 Tesseract는 기존 세로 언어팩·PSM 5를 사용합니다. 단일 영역의 곧은 세로 열을 대상으로 하며, 주석·가로 제목이 섞인 복잡한 문헌은 순서를 별도로 확인해야 합니다.

### PP-OCRv5 간체·번체 자형 보완

기존 mobile 인식 모델과 설정은 유지합니다. 작업자는 중국어 경로(`chi_sim`, `chi_tra`, 각각 `+eng` 포함)의 기본 문자열·좌표·confidence를 `engine_metadata.model_result`에 먼저 보존합니다. 화면은 **PP-OCRv5 mobile + 자형 보완**으로 표시합니다. 이는 신경망의 학습 가중치나 간번체 변환을 바꾼 결과가 아니라, 설치된 중국어 글꼴을 이용한 별도의 로컬 이미지 대조를 포함한 결과입니다. 후보 은행·글꼴은 다운로드하거나 재배포하지 않습니다.

가로쓰기는 아래 EasyOCR와 같은 공통 자형 인식을 사용합니다. 인접한 같은 줄의 검출 영역만 모아 글꼴·크기·시작점을 확인하고, 글자의 모양과 폭·부호 위치를 대조합니다. 각 글자의 유사도 0.98 이상·차순위와 차이 0.03 이상을 요구하며 줄 전체를 재렌더링해 원본과 0.98 이상 일치할 때만 보완합니다. 검증하지 못한 줄은 기본 검출 조각과 판독을 유지합니다. 기록은 `horizontal_preprocessing.regions`에 저장합니다.

세로쓰기는 같은 열의 가까운 조각을 모으되, 조각 사이 빈 간격이 글자 영역 폭의 1.8배보다 크면 나눠 처리합니다. 겹친 검출 영역의 합집합을 한 번만 빈 공간 기준으로 분할해 이웃 글자의 일부가 중복 조각이 되는 것을 피합니다. 글자 조각 수와 판독 코드 포인트 수가 일치하고 **변경하지 않은 글자까지 모두** 높은 자형 일치도·후보 차이를 충족해야 보완하고 한 열로 이어 붙입니다. 어느 글자라도 불확실하면 해당 묶음의 기본 판독·조각 사이 줄바꿈·confidence를 유지합니다. 최종 열 순서는 기존의 오른쪽→왼쪽, 열 안 위→아래 정책을 사용합니다. `vertical_preprocessing.regions`에 원래 조각 인덱스·좌표·문자열, 새 글자 조각 좌표, 자형 후보와 적용·보류 이유를 기록합니다.

보완 영역의 최종 confidence는 `null`이며 기본 점수는 `model_result`에 남습니다. `recognition_pipeline`, `glyph_verification_policy`, `glyph_font_sources`로 방식과 설치 글꼴 지문을 명시합니다. `ppocrv5-local-glyph-verified-v1`과 글꼴 지문을 캐시 요청에 포함하므로 이전 v5 캐시나 글꼴 변경 시 갱신하고 과거 기록은 보존합니다. 지원 글꼴이 없거나 이미지 근거가 부족하면 보완을 보류합니다. 설치 글꼴과 유사한 깨끗한 인쇄체에 유리한 시험 기능이며 실제 고서·필사체·복잡한 배치는 별도 검수가 필요합니다.

### EasyOCR 세로쓰기 전처리

EasyOCR는 세로쓰기에서 `readtext`의 가로 열 병합을 사용하지 않습니다. CRAFT 검출 영역을 분리한 뒤 같은 세로 열을 모으고, 긴 영역은 글자 사이 빈 공간을 기준으로 자릅니다. 원본 글자 조각의 픽셀을 회전·확대·축소하지 않고 위에서 아래 순서대로 가로 띠에 이어 붙여 기존 인식 모델에 전달합니다. 정답 파일이나 다른 OCR 엔진의 판독은 사용하지 않습니다. 간체·번체 가로쓰기는 기본 `readtext` 뒤 아래의 줄 전체 검증을 적용합니다.

이 처리는 여러 세로 열을 하나의 가로 상자로 합치는 문제와 긴 세로 열 전체가 인식기 높이로 축소되는 문제를 피합니다. 인식 뒤 좌표는 가상 띠가 아니라 원본 열의 범위로 돌려놓습니다. `engine_metadata.vertical_preprocessing`에 검출 다각형, 원본 조각→가로 띠 좌표 대응, 띠 크기·픽셀 SHA-256을 저장합니다. 출력 좌표는 인식된 글자 하나하나의 확정 위치가 아니라 원본 조각을 포함하는 영역입니다.

번체 세로쓰기에서는 `chinese.pth`의 불확실한 낱글자를 같은 EasyOCR의 `zh_sim_g2.pth`로 재확인합니다. 둘 다 기본 EasyOCR 설치에 포함된 로컬 모델입니다. 글자 조각 수와 출력 코드 포인트 수가 일치하고, 열 판독과 낱글자 판독이 같은 한자를 반환하며 낱글자 confidence가 0.8 미만일 때만 보조 모델을 확인합니다. 보조 모델이 원본 조각과 10% 흰 여백을 추가한 조각에서 같은 한자를 각각 0.9 이상으로 반환해야 후보를 적용합니다. 이는 실험적 판단 기준이며 두 모델 점수를 서로 비교하거나 정확도 확률로 해석하지 않습니다. 기준 문자열, 특정 글자 치환표, 간번체 변환은 사용하지 않습니다. 글자 수가 맞지 않거나 이체자 선택자·부호·미분리 영역이 있는 위치는 추측해 대응시키지 않습니다.

`vertical_preprocessing.regions[].recognition_refinement`에는 보조 인식 전 열 문자열·confidence, 확인한 낱글자의 원본 좌표, 두 모델의 출력·점수, 적용한 변경을 저장합니다. 변경된 열의 최종 confidence는 단일 모델의 점수를 붙이지 않고 `null`로 둡니다. 모델별 근거 점수는 0~1 척도로 보존합니다. `vertical_refinement`에는 적용 조건을 기록합니다. `朮`, `爲`처럼 두 모델 모두 출력할 수 없는 글자나 높은 confidence로 잘못 읽는 글자는 이 단계만으로 해결되지 않을 수 있습니다.

그 다음 **로컬 자형 대조**를 적용합니다. Windows에 설치된 SimSun·Microsoft JhengHei에서 CJK 통합 한자와 확장 A 전체(U+3400~4DBF, U+4E00~9FFF)를 렌더링해 후보를 검색하고, 원본 크기의 글꼴 렌더링으로 다시 비교합니다. 글꼴의 미지원 글리프 상자는 제외합니다. 후보는 세 글자나 문헌 정답으로 제한하지 않습니다. 크기와 작은 위치 이동만 맞추며 획을 임의로 늘이거나 이체자를 변환하지 않습니다. 정규화 상관 유사도 0.98 이상이고 다른 코드 포인트의 차순위 후보보다 0.03 이상 높을 때만 보완합니다. 점수는 이미지 유사도이며 인식 정확도 확률이 아닙니다. 이 보조 인식은 EasyOCR 신경망 가중치와 별개이므로 화면에 **EasyOCR + 자형 보완**으로 표시합니다.

기본 판독은 `recognition_refinement.primary_text`, 두 EasyOCR 모델을 거친 판독은 `glyph_refinement.input_text`, 자형 후보·유사도·변경·원본 조각 지문은 `glyph_refinement`에 보존합니다. `recognition_pipeline`, `glyph_verification_policy`, `glyph_font_sources`로 보완 방식과 설치 글꼴 지문을 명시합니다. 글꼴이나 후보 은행은 내려받거나 배포하지 않으며 매 작업자에서 로컬 글꼴로 생성합니다. 첫 생성에는 시간과 약 226MB의 추가 배열 메모리가 들 수 있습니다. 지원 글꼴이 없는 PC에서는 이 단계를 끄고 그 상태를 기록합니다. 글꼴이 다르거나 손상·기울임·잡음이 있으면 보완을 보류할 수 있으므로 실제 고서 전반의 정확도를 보장하지 않습니다.

정책 `easyocr-vertical-dual-chinese-local-glyph-v3`를 `recognition_policy`에 기록하므로 이전 EasyOCR 세로 캐시는 다시 인식합니다. 보조 모델과 설치 글꼴 지문도 캐시 검사에 포함하며 과거 판독 이력은 남습니다. 번체 세로쓰기에 필요한 보조 모델이 없거나 손상됐으면 설치 오류를 표시합니다. 밝은 배경의 곧은 세로 글줄과 명확한 글자 간격을 대상으로 하며, 붙은 글자·기울어진 글줄·복잡한 주석 배치는 별도 검수가 필요합니다. 빈 공간으로 나눌 수 없는 긴 영역은 글자 수를 추정해 강제로 자르지 않고 별도로 인식하며 `unresolved_tall_regions`에 개수를 기록합니다.

### EasyOCR 간체·번체 가로쓰기 보완

기본 `readtext`의 문자열·좌표·confidence를 `horizontal_preprocessing.raw_engine_result`에 보존합니다. 연속된 검출 조각 중 높이가 절반 이상 겹치고, 높이 비가 1.8 미만이며 조각 사이 간격이 작은 쪽 높이보다 짧을 때만 한 줄 후보로 모읍니다. 큰 단 간격, 겹친 상자, 다른 행을 임의로 합치지 않습니다.

줄 앞의 한자를 이미지와 대조해 설치 글꼴·크기·쓰기 시작점을 확인합니다. 전체 CJK 후보에 ASCII(U+0021~007E), 일반 문장부호(U+2010~2027), CJK 부호(U+3001~303F), 전각 문자(U+FF01~FF60)를 더하고, 글자의 잉크 모양과 실제 글꼴 advance(다음 글자까지의 폭)를 함께 검증합니다. 전각 콜론과 ASCII 콜론처럼 비슷한 부호도 폭·위치로 구분하며 코드 포인트를 일괄 변환하지 않습니다. 한자·숫자·영문이 섞인 줄에서도 판독 후 전체 문자열을 다시 렌더링해 원본 영역과 대조합니다.

각 글자가 유사도 0.98 이상·차순위와 차이 0.03 이상이고 줄 전체 유사도도 0.98 이상일 때만 그 줄을 보완합니다. 앞부분 잉크를 버리거나 뒤의 글자를 읽지 않은 결과는 채택하지 않습니다. 글꼴·시작점이 불확실하거나 실제 공백·애매한 글자가 있으면 그 줄의 원래 검출 조각·문자열·confidence를 유지합니다. 모든 공백이나 부호가 포함된 줄을 복원할 수 있다는 의미는 아닙니다. 한글 가로쓰기에는 이 처리를 적용하지 않습니다.

`horizontal_preprocessing.regions`에는 원래 조각 인덱스, 원본 줄 좌표, 보완 전 문자열, 후보 순위, 글자 폭·위치, 글꼴·크기·시작점, 원본·재렌더링 이미지 SHA-256과 줄 유사도, 채택·보류 이유를 기록합니다. 확인한 줄의 출력 confidence는 `null`이며 기본 EasyOCR 점수는 별도로 보존합니다. `easyocr-horizontal-font-layout-verified-v1`과 설치 글꼴 지문을 캐시 요청에 넣으므로 이전 가로 판독·글꼴 변경 시 해당 EasyOCR 결과만 갱신됩니다. 세로쓰기 정책과 기존 판독 이력은 보존합니다. 이 방법은 설치 글꼴과 유사한 깨끗한 인쇄체에 유리하며 실제 문헌에서 별도 검수가 필요합니다.

원시 문자열은 엔진의 Unicode와 부호를 보존합니다. 결과에는 엔진·모델 해시, 언어, 렌더링 크기·DPI, 좌표와 전처리 정책을 기록합니다. 교정·번체 변환·부호 편집은 별도 기록에서 수행해야 합니다. 원본이 실행 중 바뀌거나 좌표가 유효하지 않으면 적용을 중단합니다. 취소·시간 초과 시 작업자 프로세스를 종료합니다.

세 엔진은 한 쪽 안에서 순서대로 실행합니다. Tesseract의 OpenMP 스레드는 자식 프로세스에서 최대 8개로 제한하고, 사용자가 더 낮게 설정했으면 그 값을 따릅니다. RapidOCR는 내부 실행 스레드 최대 8개, EasyOCR는 2개를 사용합니다. 프로그램 전체 환경 변수는 바꾸지 않습니다.
