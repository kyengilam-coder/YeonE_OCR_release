# 연어OCR 0.9.0 · AI 이미지·문맥 재검증

세 엔진 비교 편집기에 선택한 AI 제공사의 이미지·문맥 재검증을 연결했습니다. 로컬 OCR 뒤 AI가 불일치를 재판독하고 번체자·중문부호 교정 제안을 만듭니다. AI 응답을 최종 교정으로 자동 확정하지 않으며 사람이 채택·기각·되돌리기를 결정합니다.

0.9.0 다운로드 주소는 [v0.9.0 릴리스](https://github.com/kyengilam-coder/YeonE_OCR_release/releases/tag/v0.9.0)입니다. 배포 완료 후 `YeonE_OCR-0.9.0-Setup-x64.exe`, 포터블 `YeonE_OCR-Windows-x64.exe`, 같은 버전의 소스·라이선스 ZIP, `update.json`과 `SHA256SUMS.txt`를 이 주소에서 받습니다. 앱 실행 환경은 포함하며 로컬 OCR 엔진·모델은 [별도로 설치](LOCAL_OCR.md)합니다.

## AI 검증 흐름

기존 **설정**에서 Gemini·OpenAI·Claude 중 제공사·이미지 입력 모델·API 키를 선택합니다. 원본의 세 로컬 엔진 판독을 완료하고 **3엔진 비교·교정 → AI 검증**을 실행합니다. 대상 쪽·번체자·부호 정책과 요청 상한을 지정하고, 실제 전송 계획의 제공사·모델·원본·쪽·이미지·호출 수를 확인합니다. 범위를 준비하거나 설정 창을 여는 동작은 API를 호출하지 않습니다.

첫 단계는 불일치 위치를 원본 이미지와 엔진별 판독·문맥으로 검증합니다. 다음 단계는 선택한 문장 범위의 번체자·중문부호를 검사하며, 일반 쪽 범위에서는 세 엔진이 같은 글자로 읽은 부분도 검사합니다. 앞 단계의 판독은 잠정 AI 근거로 구분합니다. 세부 범위는 전송 계획에 표시합니다. [AI 검증 사용·저장 정책](AI_REVIEW.md)

원시 OCR은 `runs`, AI 요청·응답·제안은 `ai_reviews`, 사람의 채택·기각·되돌리기는 `ai_decisions`와 `edits`에 구분해 보존합니다. 원본 변경·이미지 좌표·수정 전 문자열·원시 판독 지문을 확인하고, 오래되거나 불확실한 제안을 현재 교정문에 적용하지 않습니다. 이체자·호환 한자·변형 선택자를 임의로 정규화하지 않습니다.

각 요청이 완료될 때 저장·복구 사본을 만들고 동일한 조건의 완료 기록은 재사용합니다. 호출 실패·거절·잘못된 응답은 성공한 교정으로 처리하지 않습니다. SDK 자동 재시도·다른 제공사나 모델 시험·환경 키 자동 선택을 사용하지 않고 승인한 작업의 호출 상한을 적용합니다. API 키와 이미지 Base64 본문은 프로젝트나 배포물에 넣지 않습니다.

개발 검증에는 사용자 API 키나 문서를 외부에 보내지 않습니다. 모의 공급사 응답으로 동작을 검증하며 실제 유료 AI의 인식 정확도와 구분합니다. 세 제공사의 실제 SDK 직렬화와 OpenAI의 거절 응답 보존도 네트워크를 차단한 메모리 HTTP 전송으로 검사했고, 개발 환경과 배포용 격리 환경에서 각각 4개 검사를 통과했습니다. 새 배포 파일은 `dist/0.9.0`, 빌드·검증 기록은 `work/windows-ai-0.9`에 둡니다. 이전 0.8.0 파일은 보존합니다.

- 0.9.0 기능 통합 기준으로 **61개 모듈·고유 테스트 1,080개 통과**, 실패·오류·건너뜀·미완료 0개입니다. 모든 모듈을 네트워크 차단·독립 프로세스에서 실행하고 해당 검증 소스·테스트의 지문을 확인했습니다. 결과는 `work/ai-regression-0.9-release/summary.json`입니다. 공개 소스 정리와 추가 검사 뒤의 최종 결과는 이 기준 결과와 구분해 기록합니다.
- 공개 소스 구성과 배포 검사를 보완한 최종 회귀 검증은 **61개 모듈·고유 테스트 1,087개 통과**, 실패·오류·건너뜀·미완료 0개입니다. 결과는 `work/publication-regression/summary.json`입니다. 별도 실행한 AB_OCR 원본 보존 사본의 **134개 검사도 통과**했으며, 보존한 52개 파일의 Git 바이트가 원본과 해시 목록에 일치합니다. 최종 공개 빌드는 `work/windows-public-0.9`에서 다시 생성·검증합니다.

- 소스·설치용 실행 파일·포터블에서 **오프라인 자체 검사 각각 26개 통과**했습니다. 모의 이미지 재검증 → 번체·부호 제안 → 사람의 세 제안 채택·되돌리기 → 재열기 → 완료 요청 재사용 검사를 포함합니다. 결과는 `work/windows-ai-0.9/smoke/{source,onedir,portable}.json`입니다.
- 설치용 실행 파일과 포터블의 **앱 모듈 각각 75개**, 명시적 리소스 **17개**, 라이선스 참조 **162개**가 소스와 일치했습니다. `work/windows-ai-0.9/verify-build.json`에 기록했으며 문서·소스 수정 뒤에는 다시 빌드해 검증합니다.

공개 소스·소스 ZIP에는 통합 전 AB_OCR 0.3.0의 공개 소스 52개와 해시 목록을 `references/AB_OCR_0.3.0`에 보존합니다. 이 사본은 실행하거나 런타임에 import하지 않습니다. 앱은 루트 `ab_ocr`와 `yeone_ocr`의 통합 코드를 사용합니다. [AB 원본 소스 보존 안내](../references/README.md)

배포물에는 개인 원본·API 키·설정·판독 기록·모델 가중치를 넣지 않습니다. 이번 개발 검증에서 사용자의 기존 프로그램을 설치·교체·제거하지 않았습니다. 공개 완료 여부와 파일 해시는 위 릴리스 주소의 실제 자산으로 확인합니다. 실제 유료 AI의 인증·문헌 정확도는 이번 오프라인 검증 범위에 포함되지 않으며, 사용자가 선택한 제공사·모델·문서 범위로 별도 측정해야 합니다.

# 연어OCR 0.8.0 · 로컬 세 엔진 비교·교정 통합

연어OCR의 세로 읽기·책갈피 OCR·이미지 OCR을 유지하면서 AB_OCR의 Tesseract·RapidOCR·EasyOCR 실행과 원본 대조 편집을 통합했습니다. 기존 공개 0.7.4와 별도의 로컬 개발판입니다.

## 사용과 저장

원본을 고른 뒤 **[3엔진 비교·교정]**을 누르십시오. **[엔진 폴더…]**에서 기존 엔진 설치의 상위 폴더를 선택하고 **[설치 확인]**을 누릅니다. 선택 위치는 저장됩니다. 번체·간체·한글 한자 혼용과 쪽 범위를 고른 뒤 실행하며, 원본 확대·엔진별 원문·불일치 후보·교정문을 나란히 확인합니다.

- 매 인식의 원시 문자열·좌표·모델 해시는 추가 기록으로 남고, 사람의 수정·후보 선택·되돌리기·검수 이력은 분리해 보존합니다. 재인식과 과거 기록 가져오기가 현재 교정문을 덮지 않습니다.
- 완료한 엔진마다 저장·복구 사본을 만들며 중지·재시작을 지원합니다. 원본 변경과 다른 창의 저장 충돌을 감지합니다.
- 기존 연어 판독과 AB 프로젝트는 원본 지문을 검증하여 읽기 전용으로 가져옵니다. 과거 기록에 이미 있던 정규화는 출처와 함께 보존합니다.
- 교정문은 TXT·HWPX·DOCX로 내보내고 다시 열어 문자 보존을 확인합니다. 원본·원시 기록을 덮어쓰지 않습니다.
- 한글 모델의 한자 미지원 등 언어 범위를 비교 근거에 반영합니다. 간체·번체·이체자·중문부호를 자동으로 변환하지 않으며, 후보 채택은 사용자가 결정합니다.

## 검증

- 기존 기능과 새 통합 기능을 포함한 **58개 모듈, 고유 테스트 1,007개 통과**, 실패·오류·건너뜀·미완료 0개입니다. `tools/check_regression.py`는 API 연결을 차단하고 모듈마다 새 프로세스에서 실행합니다. Windows Tcl 출력 캡처와 임시 경로 이름에 영향을 받은 두 모듈은 실행 환경을 고쳐 모듈 전체를 다시 검증했습니다. 최초 결과와 재검증 결과를 모두 `work/integration-regression-verified.json`에 보존했습니다.
- 간체·번체·한글 한자 혼용 실제 자료를 각각 세 엔진으로 실행하여 **9회 모두 완료**했습니다. 이것은 통합 동작 확인이며 새 정확도 측정은 아닙니다.
- 실제 연어OCR 창의 버튼으로 실제 자료를 열고, 별도 QA 사본에서 수정·되돌리기·재열기·HWPX·DOCX 출력을 확인했습니다. 원본과 세 엔진 원시 기록의 해시는 유지됐습니다. 1440×930·1080×720 화면도 확인했습니다. 결과는 Git에서 제외한 `work/private-integration/gui-verification.json`에 있습니다.
- 전체 런타임의 Ruff `E9,F63,F7,F82` 검사와 새 모듈의 `E9,F` 검사를 통과했습니다.
- 마지막 소스 배포 허용 목록 검사에서 엔진 잠금 파일·출처 기록·기본 양식 누락을 수정하고, 모델·개인 문서·작업 폴더가 소스 압축에 들어가지 않도록 제한했습니다. 해당 모듈 전체 **11개 통과**이며, 기존 7개 외에 추가한 검사는 **4개**입니다. 따라서 검증한 고유 테스트는 총 **1,011개**입니다. 상세 통합 보고서는 `work/integration-regression-verified-final.json`에 있습니다.

## 로컬 Windows 배포

Windows x64 빌드를 완료했습니다. 설치 파일은 `dist/0.8.0/YeonE_OCR-0.8.0-Setup-x64.exe`(약 90 MB), 포터블은 `dist/0.8.0/YeonE_OCR-Windows-x64.exe`(약 121 MB)입니다. 같은 폴더의 `SHA256SUMS.txt`에 파일 해시를 기록했습니다. 두 파일의 제품 버전은 `0.8.0`입니다. 사용자에게 설치·제거를 실행하거나 인터넷에 게시하지 않았습니다.

- 소스·설치용 실행 파일·포터블에서 **오프라인 자체 검사 각각 25개 통과**했습니다. 실제 편집 창의 원본 표시·수정·되돌리기·닫기와 원시 결과·교정 이력 저장·복구가 포함됩니다.
- 설치용 실행 파일과 포터블에서 공개 합성 이미지를 **각각 세 엔진으로 실제 인식하여 6회 모두 완료**했습니다. 배포된 작업자 파일·모델 해시·원본 해시·원시 판독 해시를 확인했습니다. 검증 중 사용자 설정·API 키·외부 AI는 사용하지 않았습니다. 결과는 `work/frozen-runtime-probe/onedir/report.json`, `portable/report.json`에 있습니다.
- 두 실행 파일에 포함된 **앱 모듈 각각 74개**가 현재 소스와 일치하고, 명시적으로 포함한 리소스 15개와 라이선스 참조 162개도 원본과 일치했습니다. 검증 결과는 `work/windows-integration-0.8/verify-build.json`입니다.

빌드 경로는 `work/windows-integration-0.8`입니다. 공개 저장소 게시와 기존 프로그램 설치·교체는 이 개발 작업과 별개입니다.

모델과 엔진의 큰 실행 환경은 배포물에 넣지 않습니다. 현재 PC는 기존 AB 설치의 공개 모델·별도 환경을 재사용할 수 있으며, 새 PC는 [로컬 엔진 안내](LOCAL_OCR.md)의 설치 스크립트를 사용합니다. 개인 문서·API 키·설정·판독 기록은 소스 및 배포물에 포함하지 않습니다.

새 비교 창은 로컬 처리만 수행합니다. 기존 유료 AI 판독 코드는 유지했으며 이번 검증에서 실제 유료 API를 호출하지 않았습니다. 세 엔진 결과를 이미지와 함께 AI에 자동 전송하는 검증, 자동 번체·부호 교정은 이번 통합에 연결하지 않았습니다. 로컬 세로 비교는 시험 기능이며 기존 세로 읽기의 정확도 개선이나 ABBYY 동급 성능을 입증한 것은 아닙니다.

# 연어OCR 0.7.4 · Windows

Windows 10/11 x64에서 Python 설치 없이 실행할 수 있는 설치판입니다.

## 이미지 입력을 비우고 다시 시작

세 번째 **[이미지(스크린샷) OCR]** 탭에 **[입력 비우기]**를 추가했습니다. 누르면 선택한 원본·쪽 범위·인쇄 쪽수 보정·강제 재판독과 저장 위치·진행 표시를 초기화하고 새 이미지 입력을 기다립니다. 이어서 **[이미지 고르기…]**로 PNG·JPG 등을 선택하거나 **[스크린샷 붙여넣기]** 또는 `Ctrl+Shift+V`로 새 캡처를 불러오십시오.

입력을 비워도 디스크의 원본 이미지·판독 기록·완성 HWPX와 화면의 진행 기록 이력은 남습니다. 다른 탭의 원본 선택과 API·모델·문서 설정도 유지합니다. 입력을 비우거나 붙여넣는 것만으로 API를 호출하지 않습니다.

## 이미지의 가로·세로 방향 자동 판정

이미지의 읽기 방향은 **자동 판정이 기본**이며 실제 그림의 글줄을 분석해 가로쓰기·세로쓰기를 결정합니다. 일반 OCR·책갈피 OCR의 방향과 이미지용 방향을 각각 기억하므로 PDF 작업에서 고른 방향이 새 이미지에 그대로 적용되지 않습니다.

기존 글자층을 먼저 활용하고, 없거나 부족하면 내 PC에서 이미지의 글줄 간격·배치를 분석합니다. 방향 판정에 추가 API 호출이나 요금은 없습니다. 빈 화면·그림 위주·가로와 세로 근거가 비슷한 경우에는 불확실한 이유를 알리고 세로쓰기 기본값을 사용합니다.

직접 방향을 지정하려면 이미지 탭의 **[설정 바꾸기]**를 눌러 **[읽기 방향]**을 고릅니다. 설정 화면은 현재 작업에 해당하는 방향을 바꾸며, **[설정 저장]·[OCR로 돌아가기]**로 저장하고 작업을 이어갑니다.

판정 근거가 없는 구버전의 세로쓰기 저장값은 이미지 근거가 확실할 때 다시 평가합니다. 완료·부분 판독 기록은 보존하고 자동으로 강제 재판독하지 않으며, 처리 내용은 진행 기록에 안내합니다. 직접 고른 읽기 방향은 유지합니다.

## 기존 작업과 결과 열기

**[일반 OCR]·[책갈피 OCR]·[이미지(스크린샷) OCR]·[설정]**의 네 탭, 원본 선택의 독립성, 공통 API·모델·문서 설정을 유지합니다. **[원본 보기]**로 확인한 뒤 **[한 번에 인식]**을 실행하고, 끝나면 **[HWPX 바로 열기]** 또는 **[저장 폴더]**로 결과를 확인합니다.

캡처의 기본 결과 경로는 `%LOCALAPPDATA%\YeonE_OCR\screenshots\screenshot-<hash>_png_YeonE_OCR\out\screenshot-<hash>.hwpx`입니다. `<hash>`는 캡처마다 달라집니다. 기존 저장 위치와 같은 캡처의 판독 기록을 유지하며, **[HWPX 저장]** 줄에서 실제 전체 경로를 확인할 수 있습니다.

Gemini·ChatGPT(OpenAI)·Claude(Anthropic) 선택, 제공사를 바꿔 중단 작업 이어 읽기, 최종 HWPX·DOCX의 번체·MSR·云/雲 문맥 교정도 유지합니다. 각 제공사의 API 키와 이용 권한이 필요하며 API 이용료는 별도입니다. ChatGPT·Claude 웹 구독과 API는 별개입니다.

## 다운로드와 업데이트

- **설치 권장:** `YeonE_OCR-0.7.4-Setup-x64.exe`를 실행합니다. 현재 사용자 계정에 설치하며 시작 메뉴에 연어OCR을 등록합니다.
- **단일 실행파일 사용자:** `YeonE_OCR-Windows-x64.exe`를 사용합니다. 기존 자동 업데이트용 파일명과 `update.json` 형식을 유지합니다.
- OCR 작업을 마치거나 [중지]로 기록을 저장한 뒤 업데이트하십시오. API 키·설정, 원본 옆 결과 폴더와 저장한 스크린샷은 유지합니다.
