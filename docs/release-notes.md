# 연어OCR 1.0.5 · 띄어쓰기 변경 뒤 수동 교정 보호 오류 수정

대조 편집에서 저장한 문단의 일반 공백만 나중에 달라졌을 때, 수동 수정 기록과 본문이 다르다는 오류로 교정 실행·대조 편집을 막던 문제를 수정합니다.

- 문단 수·위치·수정 기록을 검증하고, 기록된 본문과 현재 본문이 일반 공백(U+0020)만 다른 경우에는 현재 문단을 사람이 고친 문단으로 계속 보호합니다.
- 현재 파일의 띄어쓰기·글자·교정 색상을 그대로 사용합니다. 기록을 지우거나 예전 본문으로 되돌리지 않습니다.
- 실제 글자·문장부호·제어 문자나 문단 구조가 달라진 경우에는 기존 덮어쓰기 방지를 유지합니다. 확인할 수 없는 기록을 무시하지 않습니다.
- 파일 밖에서 바뀐 공백을 새로운 학습 정답으로 자동 등록하지 않습니다. 이후 대조 편집에서 저장한 수정은 기존 방식대로 기록합니다.

합성 문서의 교정 재실행·편집 재열기·저장·보호 동작과 실행 파일 자체 검사, 1.0.4에서의 업데이트 설치를 확인합니다. 개인 문헌과 수정 기록은 공개 자료에 포함하지 않습니다.

# 연어OCR 1.0.4 · 일반·이미지 OCR 대조 편집과 교정 색상 일치

**일반 OCR**과 **이미지(스크린샷) OCR**에서도 완성된 HWPX 결과를 **나란히 대조 편집**으로 엽니다. 왼쪽 원본 PDF·이미지를 보면서 오른쪽 교정문을 수정하고, 결과 폴더의 `_교정.hwpx`에 이어서 저장합니다. 기존 OCR 결과는 원본으로 보존합니다.

- 쪽을 선택하면 해당 쪽의 교정문을 함께 표시합니다. 긴 문서를 한꺼번에 띄우지 않으며, 쪽을 옮기기 전 미저장 수정의 처리 방법을 확인합니다.
- 책갈피 OCR의 찾기·바꾸기, 전체 복사, 본문 내보내기, 수정 기록과 저장 전 사본을 함께 사용합니다. 편집창을 여는 데 새 OCR 판독이나 모델 호출은 필요하지 않습니다.
- 이미지 파일·스크린샷·이미지 폴더를 원본으로 표시합니다. 저장된 판독 위치가 있으면 해당 영역을 안내하며, 글자 위치를 확인할 수 없을 때는 정확한 커서 위치로 표시하지 않습니다.
- 교정 HWPX에 저장된 글자 색·배경색·굵게·밑줄을 읽어 대조 편집창에 표시합니다. 글자가 원본과 같아도 확인 표시는 유지합니다.
- 원본과 달라진 글자만 파랗게 표시해 빨강·노랑 확인 대상이 빠지고 사람 수정도 다시 표시되던 오류를 수정합니다.
- 미저장 수정으로 위치가 바뀌어도 남아 있는 표시를 해당 글자에 대응합니다. 사람이 직접 바꾼 글자는 교정 색을 다시 칠하지 않으며, 저장·다시 불러오기 후에도 파일과 화면의 표시를 맞춥니다.
- 교정 표시의 의미를 범례로 안내하고, 실제로 편집하는 교정본의 전체 경로를 확인할 수 있게 합니다.
- 기존 저장 오류 수정, 구획 전체 복사, 본문 내보내기, 수동 수정 기록과 원본 보존을 유지합니다.

전체 회귀 검사와 빌드·설치 검증은 병렬 실행하고, 검증한 동일 실행 파일을 게시합니다. 실제 문헌은 읽기 전용 또는 작업 사본으로 확인하며 개인 문헌·설정·수정 기록은 공개 소스에 포함하지 않습니다.

# 연어OCR 1.0.3 · 여러 서식에 걸친 수정 저장·배포 시간 개선

대조 편집에서 OCR 색상이나 글자 서식이 다른 부분을 함께 고칠 때, 글자 수가 달라지면 저장하지 못하던 문제를 수정합니다.

- 여러 서식에 걸친 글자 추가·삭제·바꾸기를 기존 교정본에 저장합니다. 수정하지 않은 글자와 원래 문서 구조를 보존합니다.
- 직접 수정한 글자의 OCR 교정 표시는 제거하고 원래 글자 서식을 이어받습니다. 저장 전 사본·외부 변경 감지·수동 수정 기록을 유지합니다.
- **구획 전체 복사**로 여러 문단의 현재 교정문을 한꺼번에 복사합니다. 아직 저장하지 않은 수정도 포함하며, 문단별 입력칸을 넘겨 드래그할 필요가 없습니다.
- **본문 내보내기**에서 현재 구획 전체 또는 교정본 문서 전체를 선택해 UTF-8 텍스트 파일로 보관합니다. 수정 전 내용이나 비교 설명을 섞지 않고, 수정하지 않은 문단과 아직 저장하지 않은 수정을 포함한 현재 본문을 담습니다. 변경 확인창에서도 같은 내보내기를 사용합니다.
- 전체 회귀 검사와 실행 파일 빌드·설치 검증을 동시에 진행합니다. 두 작업이 모두 성공한 동일 소스의 파일만 게시합니다.
- 검토한 비화면 검사만 모듈별 프로세스로 병렬 실행합니다. 화면·포커스·클립보드 검사는 단독 실행하며, 실패하면 대기 중인 검사를 중단하고 미실행 목록을 기록합니다.
- 수정 단계에서는 관련 검사를 먼저 실행하고, 최종 전체 검사는 공개 서버에서 수행합니다. 공개 서버가 만든 파일을 로컬 확인에도 사용해 별도의 배포 빌드를 반복하지 않습니다.

검증은 여러 서식에 걸친 수정·저장·재열기, 본문·색상·메모·수정 기록 보존, 전체 회귀 검사, 실행 파일 자체 검사와 1.0.2에서의 업데이트·재설치·제거로 구성합니다. 실제 소요 시간과 최종 결과는 공개 CI 기록과 배포 검증 기록에서 확인합니다.

# 연어OCR 1.0.2 · 대조 편집 PDF 패널·글자 크기 복구

책갈피 대조 편집창의 초기 표시가 늦어지면 원본 PDF 패널이 사라지고 교정문 글자가 매우 작아지는 문제를 수정합니다.

- 창이 표시되기 전 임시 폭을 기준으로 좌우 분할을 확정하지 않습니다. 실제 표시 크기를 확인한 뒤 PDF와 교정문을 배치합니다.
- 다시 표시·창 크기 변경·교정본 다시 불러오기 때 양쪽 패널의 폭을 확인하고, 한쪽이 접힌 상태를 복구합니다.
- 창 위쪽의 **좌우 균등** 버튼으로 언제든 두 패널을 같은 폭으로 되돌릴 수 있습니다.
- 숨겨지거나 폭이 확정되지 않은 PDF 패널을 기준으로 축소 이미지를 만들거나 교정문 글자 크기를 맞추지 않습니다.
- 숨긴 동안 미뤄진 PDF 표시는 창을 다시 열면 재개합니다. 최초 PDF가 비어 있거나 이전 쪽·확대율이 남지 않도록 현재 상태로 다시 그립니다.
- 기존 미저장 수정, 커서 연동, 수동 글자 크기, 찾기·바꾸기, 복사와 기존 교정본 저장을 유지합니다. 화면 배치 복구는 문서 내용을 바꾸지 않습니다.

검증은 첫 표시 지연·숨김 후 다시 표시·창 크기 변경·다시 불러오기·패널 폭과 글자 크기 확인, 기존 기능 회귀 검사, 실행 파일 자체 검사와 1.0.1에서의 업데이트 설치로 구성합니다. 최종 결과는 공개 릴리스 검증 기록에 남깁니다.

# 연어OCR 1.0.1 · 대조 편집 저장·복사와 찾기·바꾸기

책갈피 대조 편집에서 줄바꿈·탭 때문에 저장이 막히는 상황을 바로잡고, **찾기·바꾸기(Ctrl+H)**를 추가합니다. 예를 들어 `皰`를 찾아 `疱`로 한 번에 바꿀 수 있습니다.

- 현재 문단·현재 구획·문서 전체에서 바꿀 범위를 선택합니다. 변경 건수와 수정 전후를 확인하고 적용한 다음 **변경 확인·저장**으로 기존 교정본에 저장합니다.
- 제목·책갈피·필드 등 편집할 수 없는 문단은 제외하고 건수를 알립니다. 현재 창에서 이미 수정한 내용도 함께 보존하며, 미리보기나 적용만으로 파일을 덮어쓰지 않습니다.
- 문단 편집 중 실수로 줄바꿈·탭이 들어가지 않도록 입력을 처리합니다. 붙여넣기나 기존 입력에 줄바꿈·탭이 있으면 내용을 확인하고 공백으로 정리할 수 있습니다. 임의로 본문 글자를 삭제하지 않습니다.
- 저장할 수 없는 입력은 해당 문단과 위치를 안내합니다. 저장 실패 때 입력 내용이 창에 남으며, 기존 교정본과 수동 교정 기록은 유지됩니다.
- 오른쪽 교정문에서 선택한 글자는 **Ctrl+C** 또는 **마우스 오른쪽 버튼 → 복사**로 복사합니다. 저장 전 수정한 내용도 복사하며, 복사 작업은 본문과 저장 상태를 바꾸지 않습니다.
- 직접 고친 글자의 교정 표시 제거, 수정 사례 기록, 저장 전 사본, 외부 변경 확인을 유지합니다.

검증은 문단 입력·붙여넣기·찾기·일괄 바꾸기·수정 취소와 저장·재열기, 본문·서식·수동 수정 기록 보존 검사, 실행 파일 자체 검사, 1.0.0에서의 업그레이드·재설치·제거 확인으로 구성합니다. 최종 결과는 공개 릴리스 검증 기록에 남깁니다.

# 연어OCR 1.0.0 · 사람이 고친 글자의 교정 표시 정리

앱·설치판·포터블의 버전을 **1.0.0**으로 맞춥니다. 책갈피 대조 편집에서 직접 고친 글자를 저장하면 해당 글자의 OCR 교정 색상·배경색·밑줄 등을 제거하고 원래 문서의 글자 서식으로 되돌립니다.

- 한 문단에 글꼴·크기·강조 등 여러 서식이 섞여 있어도 사람이 수정한 글자의 표시를 정리합니다. 아직 수정하지 않은 글자의 OCR 표시는 유지합니다.
- 원래 문서에 있던 글꼴·크기·색상·강조는 보존합니다. 원래 서식을 안전하게 확인할 수 없는 경우에는 저장을 중단하고 서식별로 나눠 수정하도록 안내합니다.
- 수정 내용은 기존 `_교정.hwpx`에 저장하고, 저장 전 사본·외부 변경 확인·수동 수정 문단 보호와 `.manual.json` 수정 사례 기록을 유지합니다.
- 색상만 교정 표시, 기존 앱 메모 정리, 원본 PDF 커서 따라가기·글자 크기 맞춤 기능을 이어서 제공합니다.

이번 버전에서 저장하는 수정부터 적용합니다. 기존 파일에 남아 있는 표시를 버전 업데이트만으로 일괄 제거하지는 않습니다.

검증은 여러 서식이 섞인 문서의 수정·저장·재열기와 원문 및 수정 기록 보존 검사, 실행 파일 자체 검사, 0.12.5에서의 업그레이드·재설치·제거 확인으로 구성합니다. 최종 결과는 공개 릴리스 검증 기록에 남깁니다.

# 연어OCR 0.12.5 · 색상만 교정 표시와 기존 앱 메모 정리

책갈피 OCR의 기본 표시를 **색상만 표시**로 바꿉니다. 메모나 본문 설명을 새로 넣지 않고 초록(3차 자형 판별 근거)·파랑(자동 교정, 확인 권장)·빨강/노랑(원본 확인 필요)으로 구분합니다. 원래 글자·삽입 제안·근거 전체는 보고서에 남깁니다.

- 삭제 자리와 폭 없는 삽입 제안은 가까운 실제 글자에 표시합니다. 표시할 글자가 없는 항목은 보고서에 남기며, 표시를 위해 본문 글자를 추가하지 않습니다.
- **기존 앱 메모 정리** 버튼으로 기존 교정본의 앱 교정 메모를 한 번에 정리합니다. OCR 호출 없이 동작하며 정리 전 `.bak.hwpx` 사본을 만듭니다.
- 본문·서식·색상·책갈피·사용자 메모·일반 OCR 메모와 사람이 수정한 문단의 보호·수정 사례 기록을 보존합니다. 손상되거나 소유권이 불확실한 메모는 남기고 알립니다.
- 기존 기본 메모/글 속 설명 설정은 한 번만 새 기본값으로 옮깁니다. 명시적으로 선택했던 모든 메모 방식과 이후 사용자가 다시 고른 방식은 유지합니다. 일반 OCR 설정은 바꾸지 않습니다.
- 과거에 본문 글자로 넣은 `〔…〕` 설명은 메모 정리 버튼으로 지우지 않습니다. 기존 메모 방식도 설정에서 다시 선택할 수 있습니다.

검증은 합성 문서의 색상 표시·메모 정리·원문 및 사람 수정 기록 보존 검사, 실행 파일 자체 검사, 0.12.4 업그레이드·재설치·제거 확인으로 구성합니다. 최종 결과는 공개 릴리스 검증 기록에 남깁니다.

# 연어OCR 0.12.4 · 사람 수정 사례 기록과 다음 판독 참고

책갈피 대조 편집에서 사람이 글자를 고치고 저장하면 수정 전후 본문·문단·구획·시각을 교정본 옆 `.manual.json`에 함께 보관합니다. **수정 기록 보기**에서 저장된 이력을 확인할 수 있습니다.

- 같은 PDF의 다음 새 1차 판독에 최근에 저장한 유효한 짧은 수정 사례부터 최대 24개와 문맥을 전달합니다. 한자를 한글로 오인식한 뒤 사람이 바로잡은 경우도 기록합니다. 실제 글자는 원본 이미지로 확인하도록 안내하며 2차·3차 판독은 사례를 전달하지 않고 독립적으로 진행합니다.
- 되돌린 교정, 저장 실패로 문서에 반영되지 않은 내용, 상충하는 사례와 다른 PDF의 사례는 참고에서 제외합니다. 삽입·삭제·긴 수정도 이력에는 남기지만 짧은 글자 치환 사례만 판독에 보냅니다.
- 기존 완료 판독은 그대로 재사용합니다. 사례가 추가되었다고 자동으로 유료 재판독하지 않습니다. 새 쪽 판독이나 명시적 재판독부터 참고하며, 부분 재개에서는 실제 1차 판독에 사용했던 사례의 출처를 유지합니다.
- 이전 버전의 해시 기반 문단 보호는 유지합니다. 그 기록만으로는 실제 수정 전후를 알 수 없어 사례를 소급 생성하지 않습니다. 이 버전에서 저장하는 수정부터 전후 기록이 쌓입니다.
- 원본 보존·저장 전 사본·외부 변경 확인·수동 교정 문단 보호를 유지합니다. 사례는 교정본 옆에 저장되며, OCR 실행 시 선정된 짧은 사례만 선택한 판독기로 전달됩니다.
- 대조 편집 창을 처음 열 때 Windows 테마의 분리선 두께를 반영해 좌우 패널 너비를 균등하게 맞춥니다. 사용자가 이후 조절한 분할 비율은 유지합니다.

이 기능은 저장한 수정 사례를 판독에 참고시키는 방식이며 모델 가중치를 재학습하지 않습니다. 실제 인식률 개선 수치는 별도 평가가 필요합니다. 배포 검증은 수정 기록·재개·기존 교정 보존 회귀 검사, 실행 파일 자체 검사, 0.12.3 업그레이드·재설치·제거 확인으로 구성합니다.

# 연어OCR 0.12.3 · 대조 편집 커서 연동과 글자 크기 맞춤

책갈피 OCR 대조 편집에서 오른쪽 커서의 위치를 왼쪽 원본 PDF에 표시합니다. PDF의 화면상 글자 폭에 맞춰 교정문 글자 크기를 조절하고 대응 글자를 양쪽 화면의 비슷한 높이에 배치합니다.

- **커서 따라가기**가 기본으로 켜집니다. 클릭·방향키·입력으로 커서를 옮기면 대응 PDF 쪽과 줄을 찾습니다. 노란색은 대응 줄, 테두리는 확인된 글자 위치입니다.
- **PDF 글자 크기 맞춤**이 기본으로 켜집니다. PDF 확대·축소와 창 너비 변경에 맞춰 오른쪽 글자 크기도 바뀝니다. **가− / 가+**로 직접 조절하면 자동 맞춤이 꺼지며, 체크하면 다시 맞춥니다.
- 커서가 있는 줄의 화면 높이를 맞추고 오른쪽 스크롤을 따라갑니다. PDF와 HWPX는 줄바꿈·문단 구조가 달라 가로 위치와 전체 지면 배치까지 같아지는 것은 아닙니다.
- 반복 문장은 구획 문맥으로 확인합니다. 새로 입력한 글자 등 대응이 없는 위치는 주변 문맥만 표시하며, 모호하거나 글자층이 없는 PDF에는 임의의 정확한 글자 표시를 하지 않습니다. PDF 글자층은 위치 안내용이며 자동 교정 근거로 추가 사용하지 않습니다.
- 직접 PDF 쪽을 바꾸면 자동 이동을 멈추고, 오른쪽 커서를 다시 움직일 때 따라갑니다. **커서 따라가기**를 꺼서 자유롭게 탐색할 수 있습니다.
- 위치 표시·크기 맞춤은 문서나 서식을 바꾸지 않습니다. 기존 교정본 저장, 저장 전 사본, 외부 변경 확인과 사람 수정 보호는 유지됩니다. 추가 OCR 호출 없이 동작합니다.

배포 검증은 오프라인 회귀 검사, 소스·설치용 실행 파일·포터블의 커서 연동 자체 검사, 깨끗한 Windows에서 0.12.2 업그레이드·재설치·제거 확인으로 구성합니다. 최종 검사 결과는 공개 릴리스 검증 기록에 남깁니다.

# 연어OCR 0.12.2 · 책갈피 OCR 나란히 대조·편집

책갈피 OCR에서 선택한 구획의 원본 PDF와 현재 교정문을 한 창에 나란히 표시합니다. 오른쪽 문단을 직접 수정하고 변경 내용을 확인한 뒤 기존 누적 교정본에 저장할 수 있습니다.

- **나란히 대조·편집** 버튼과 구획 더블클릭으로 엽니다. 왼쪽은 PDF 쪽 이동·확대·축소, 오른쪽은 문단 편집·원문 차이 표시와 선택 문단 비교를 제공합니다.
- **변경 확인·저장** 또는 `Ctrl+S`로 수정 전후를 확인합니다. 기존 `_교정.hwpx`를 갱신하며, 교정본이 없으면 처음 저장할 때 만듭니다. 수정 전 사본을 보관하고 원본 PDF/HWPX는 유지합니다.
- 저장 전 문서 위치와 파일 변경 여부를 확인합니다. 외부 변경·저장 실패 때 입력한 수정문을 유지하고 덮어쓰지 않습니다. 미저장 내용이 있으면 닫기·다시 불러오기 때 확인합니다.
- 사람이 수정한 문단은 교정본 옆의 `.manual.json` 기록으로 보호합니다. 이후 자동 교정은 해당 문단을 바꾸지 않고 차이를 보고에만 남깁니다. 이 기록은 교정본과 함께 보관해야 합니다.
- 제목·필드 등 수정 위치를 안전하게 확인할 수 없는 문단은 읽기 전용입니다. PDF 쪽과 HWPX 문단은 각각 탐색하며, 문단 추가·삭제나 한글 전체 서식 편집은 지원하지 않습니다. 과거 OCR 보고와 메모는 작성 당시 기록으로 남습니다.

배포 검증은 오프라인 회귀 검사, 소스·설치용 실행 파일·포터블의 자체 검사, 깨끗한 Windows에서 0.12.1 업그레이드·재설치·제거 확인으로 구성합니다. 실제 검사 결과는 공개 릴리스 검증 기록에 남깁니다. 이번 기능은 문서 대조·수동 편집이며 OCR 모델의 정확도 향상을 의미하지 않습니다.

# 연어OCR 0.12.1 · 책갈피 구획 선택과 결과 확인 개선

책갈피 OCR에서 같은 위치의 책갈피·제목이 두 번 나타나거나, PDF 본문의 앞선 언급을 구획 시작으로 잘못 찾던 문제를 수정합니다. 선택한 구획의 교정 실행과 결과 확인을 구분합니다.

- 같은 문단의 책갈피와 제목 스타일을 한 구획으로 합치고 제목 계층을 유지합니다. 전체 교정에서 같은 위치를 중복 처리하지 않습니다.
- PDF 책갈피가 없는 구획은 본문 제목과 주변 범위를 확인합니다. 첫 문자열 등장만으로 엉뚱한 구획을 자동 선택하지 않으며 확인할 수 없으면 쪽 범위를 직접 지정하도록 안내합니다.
- 선택 구획의 이름·PDF 범위·HWPX 내용을 확인할 수 있고, 행 더블클릭은 결과 확인/미리보기로 동작합니다. 교정 재실행은 별도 실행 버튼으로 구분합니다.
- 구획 결과는 원본 문서와 구획 위치에 연결합니다. 가장 최근에 수정된 다른 구획의 보고를 열거나 같은 이름의 보고를 덮어쓰지 않습니다. 확인 가능한 기존 보고도 조회할 수 있습니다.
- 파일·제목 스타일·색인 기준이 바뀌면 기존 선택을 갱신해야 합니다. 실행 전 구획 이름과 시작 문단을 다시 확인합니다.
- 전체 교정본 열기와 선택 위치의 보기 사본 열기를 구분합니다. 위치 이동을 지원하는 문서는 보기 사본의 시작 위치만 바꾸며 원본·누적 교정본을 변경하지 않습니다.

기존 판독 기록·사람 교정 보존 정책을 유지합니다. 이번 수정은 구획 선택과 결과 확인에 대한 것이며 OCR 모델의 일반적인 정확도 향상을 의미하지 않습니다. 배포 검증은 오프라인 회귀 검사, 소스·설치용 실행 파일·포터블 자체 검사, 깨끗한 Windows CI의 0.12.0에서 업그레이드·재설치·제거 확인으로 구성합니다. 실제 검사 결과와 한계는 릴리스 검증 기록에 남깁니다. [설치·검증 안내](windows-release.md)

# 연어OCR 0.12.0 · 원문·교정 보존 강화와 소주 검수

일반 OCR의 문자 보존과 위치 확인을 강화하고, 세로 쌍행·가로 다중행 소주를 원본과 대조하는 선택 검수 기능을 추가했습니다. 기존 판독 기록과 사람이 확정한 교정을 유지합니다.

- 새 1차·2차 판독은 호환 한자·이체자 선택자·한글 자모를 임의로 정규화하지 않고 저장합니다. 과거 기록은 당시 정책으로 재현하고, 재병합·실패 영역 재시도에서는 기존 교정문을 보존합니다.
- 새 3차 판별은 원본 글자 위치와 앞뒤 연결을 확인하지 못하면 확정을 보류합니다. 기존 확정 판별을 소급 변경하지 않습니다.
- **소주 검수**에서 세로 두 소열·가로 다중행 후보를 검출하고, 선택한 행을 재판독할 수 있습니다. 완료 응답은 재사용하며 기존 본문은 바꾸지 않습니다. 원본과 삽입 위치를 확인한 사람이 명시적으로 삽입할 때만 반영하고, 변경 전 기록과 이력을 보존합니다.
- 평가에 Unicode 정규화·이체자 접기를 하지 않는 **CER(원문 코드)**를 추가했습니다. 최종 문서의 번체·부호 변환은 출력 설정을 따르며 `--no-normalize`로 생략할 수 있습니다.
- Windows 실행 파일의 명령줄 출력을 파일로 저장할 때 한국어·문장부호·희귀 한자 때문에 중단되지 않도록 로그 출력을 UTF-8로 설정합니다.
- 공개 0.9.0 이후의 여섯 로컬 엔진 선택, 교정 후보·어려운 영역 재판독, GPU 대기열·작업자 재사용, 원문 한자와 부호의 오교정 보류를 함께 포함합니다. 엔진 실행 환경·모델은 별도 설치하며 원시 OCR·AI 제안·사람 확정을 구분합니다.

소주 검수는 원본 대조용 제안입니다. 실제 표본에서 기존 판독에도 소주가 모두 있었으므로 누락 회복을 입증하지 못했고, 가로 표본의 새 후보 오류율은 기존보다 높았습니다. 자동 삽입·쌍행 서식 복원·일반적인 정확도 향상을 제공한다고 표시하지 않습니다. Document AI는 연동하지 않았습니다.

이 기능 묶음의 직전 소스 검증은 103개 모듈·1,695개 테스트를 통과했습니다. 0.12.0 배포 검증에서는 최신 소스 회귀 검사와 소스·설치용 실행 파일·포터블의 오프라인 자체 검사, 설치·재설치·제거 및 사용자 데이터 보존을 별도로 확인합니다. 실제 유료 OCR을 재호출하지 않는 배포 검증과 문헌 정확도 실측을 구분합니다. [설치·검증 안내](windows-release.md) · [개발·실측 기록](HANDOFF.md)

# 연어OCR 0.11.0 · 교정 후보와 영역 재판독·GPU 작업 관리

원본 대조 편집기의 **로컬 교정·영역** 탭에서 GLM의 한자 차이와 EasyOCR의 부호 차이를 교정 후보로 만들고, 선택한 범위 또는 어려운 한글·한자 영역 두 개를 다시 읽는다. 실제 OCR 좌표와 양쪽의 유일한 원문을 확인할 수 있을 때만 대응하며, 사람이 수정한 자리를 덮어쓰거나 GLM에 글자 좌표를 만들어 넣지 않는다. 기존 세로 읽기·책갈피·이미지 OCR과 여섯 엔진 비교·기존 기준 판독은 유지한다.

영역 계획은 원본·렌더링·잘라낸 이미지·부모 판독·모델 설치·실행 환경·장치를 고정한다. `runs`, `region_readings`, `refinement_reviews`, `ai_reviews`, 사람의 결정과 `edits`를 구분한다. 완료·미완료·실패 원시를 보존하고 사용자가 채택해야 교정문이 바뀐다. 과거 요청의 미확정 근거도 저장·재열기에서 검증한다.

GPU 작업은 Windows 공통 FIFO에서 취소 가능하게 기다린다. 모델별 연속 쪽·영역 처리는 GLM·Surya·Paddle 전용 작업자·서버를 재사용하고, 기본 8회 뒤 임대를 반납한다. 페이지 사이에 대화 문맥을 넘기지 않으며 원시마다 요청·세션·작업자 정보와 고정 조건을 남긴다. 명시 CPU·CUDA가 다른 캐시는 같은 실행으로 재사용하지 않는다. 취소·시간 초과·종료 때 해당 작업이 만든 프로세스만 정리한다.

AI는 미확정 로컬 후보와 영역 원시·확대 이미지를 원본·문맥으로 다시 검증한다. 쪽 전체의 시각 검증을 선택할 수 있고, 간체의 번체 변환 기본값은 꺼져 있다. 이체자·원문 부호를 보존하며 일괄 전각화 같은 편집 양식 교정을 정답으로 강제하지 않는다. 동일 Gemini 모델·기존 120개 평가 범위만 사용한 실제 검증은 개인 작업 폴더 `work/refinement-validation`에 보관하고, HWPX·DOCX 정답은 추론·외부 전송에서 제외한다. 조합·AI 제안을 적용한 평가용 문장과 사람의 확정 이력을 구분하며 정확도 개선과 오교정을 별도로 계산한다.

개인 문헌·정답·원시 측정·실행 실패/복구 증거는 Git에서 제외한 `work/new-engine-comparison`에 둔다. 최종 비교는 기존 고정 원시 360건과 신규 모델 최종 원시 360건이며, 초기 설치 진단과 혼합하지 않는다. 이번 비교는 외부 AI 호출을 하지 않는다. 모델 가중치·실행 환경·개인 문서는 소스나 배포물에 포함하지 않는다. 로컬 빌드는 `work/windows-multi-engine-0.10.0`, 설치 파일·포터블은 `dist/0.10.0`이며 GitHub 공개 배포 상태와 구분한다.

첫 단계는 불일치 위치를 원본 이미지와 엔진별 판독·문맥으로 검증합니다. 다음 단계는 선택한 문장 범위의 번체자·중문부호를 검사하며, 일반 쪽 범위에서는 세 엔진이 같은 글자로 읽은 부분도 검사합니다. 앞 단계의 판독은 잠정 AI 근거로 구분합니다. 세부 범위는 전송 계획에 표시합니다. [AI 검증 사용·저장 정책](AI_REVIEW.md)

원시 OCR은 `runs`, AI 요청·응답·제안은 `ai_reviews`, 사람의 채택·기각·되돌리기는 `ai_decisions`와 `edits`에 구분해 보존합니다. 원본 변경·이미지 좌표·수정 전 문자열·원시 판독 지문을 확인하고, 오래되거나 불확실한 제안을 현재 교정문에 적용하지 않습니다. 이체자·호환 한자·변형 선택자를 임의로 정규화하지 않습니다.

원본을 고른 뒤 **[3엔진 비교·교정]**을 누르십시오. **[엔진 폴더…]**에서 기존 엔진 설치의 상위 폴더를 선택하고 **[설치 확인]**을 누릅니다. 선택 위치는 저장됩니다. 번체·간체·한글 한자 혼용과 쪽 범위를 고른 뒤 실행하며, 원본 확대·엔진별 원문·불일치 후보·교정문을 나란히 확인합니다.

- 매 인식의 원시 문자열·좌표·모델 해시는 추가 기록으로 남고, 사람의 수정·후보 선택·되돌리기·검수 이력은 분리해 보존합니다. 재인식과 과거 기록 가져오기가 현재 교정문을 덮지 않습니다.
- 완료한 엔진마다 저장·복구 사본을 만들며 중지·재시작을 지원합니다. 원본 변경과 다른 창의 저장 충돌을 감지합니다.
- 기존 연어 판독과 AB 프로젝트는 원본 지문을 검증하여 읽기 전용으로 가져옵니다. 과거 기록에 이미 있던 정규화는 출처와 함께 보존합니다.
- 교정문은 TXT·HWPX·DOCX로 내보내고 다시 열어 문자 보존을 확인합니다. 원본·원시 기록을 덮어쓰지 않습니다.
- 한글 모델의 한자 미지원 등 언어 범위를 비교 근거에 반영합니다. 간체·번체·이체자·중문부호를 자동으로 변환하지 않으며, 후보 채택은 사용자가 결정합니다.

# 연어OCR 0.7.4 · Windows

Windows 10/11 x64에서 Python 설치 없이 실행할 수 있는 설치판입니다.

## 이미지 입력을 비우고 다시 시작

세 번째 **[이미지(스크린샷) OCR]** 탭에 **[입력 비우기]**를 추가했습니다. 누르면 선택한 원본·쪽 범위·인쇄 쪽수 보정·강제 재판독과 저장 위치·진행 표시를 초기화하고 새 이미지 입력을 기다립니다. 이어서 **[이미지 고르기…]**로 PNG·JPG 등을 선택하거나 **[스크린샷 붙여넣기]** 또는 `Ctrl+Shift+V`로 새 캡처를 불러오십시오.

입력을 비워도 디스크의 원본 이미지·판독 기록·완성 HWPX와 화면의 진행 기록 이력은 남습니다. 다른 탭의 원본 선택과 API·모델·문서 설정도 유지합니다. 입력을 비우거나 붙여넣는 것만으로 API를 호출하지 않습니다.

## 이미지의 가로·세로 방향 자동 판정

이미지의 읽기 방향은 **자동 판정이 기본**이며 실제 그림의 글줄을 분석해 가로쓰기·세로쓰기를 결정합니다. 일반 OCR·책갈피 OCR의 방향과 이미지용 방향을 각각 기억하므로 PDF 작업에서 고른 방향이 새 이미지에 그대로 적용되지 않습니다.

기존 글자층을 먼저 활용하고, 없거나 부족하면 내 PC에서 이미지의 글줄 간격·배치를 분석합니다. 방향 판정에 추가 API 호출이나 요금은 없습니다. 빈 화면·그림 위주·가로와 세로 근거가 비슷한 경우에는 불확실한 이유를 알리고 세로쓰기 기본값을 사용합니다.

직접 방향을 지정하려면 이미지 탭의 **[설정 바꾸기]**를 눌러 **[읽기 방향]**을 고릅니다. 설정 화면은 현재 작업에 해당하는 방향을 바꾸며, **[설정 저장]·[OCR로 돌아가기]**로 저장하고 작업을 이어갑니다.

판정 근거가 없는 구버전의 세로쓰기 저장값은 이미지 근거가 확실할 때 다시 평가합니다. 완료·부분 판독 기록은 보존하고 자동으로 강제 재판독하지 않으며, 처리 내용은 진행 기록에 안내합니다. 직접 고른 읽기 방향은 유지합니다.

## 기존 작업과 결과 열기

**[일반 OCR]·[책갈피 OCR]·[이미지(스크린샷) OCR]·[설정]**의 네 탭, 원본 선택의 독립성, 공통 API·모델·문서 설정을 유지합니다. **[원본 보기]**로 확인한 뒤 **[한 번에 인식]**을 실행하고, 끝나면 **[HWPX 바로 열기]** 또는 **[저장 폴더]**로 결과를 확인합니다.

캡처의 기본 결과 경로는 `%LOCALAPPDATA%\YeonE_OCR\screenshots\screenshot-<hash>_png_YeonE_OCR\out\screenshot-<hash>.hwpx`입니다. `<hash>`는 캡처마다 달라집니다. 기존 저장 위치와 같은 캡처의 판독 기록을 유지하며, **[HWPX 저장]** 줄에서 실제 전체 경로를 확인할 수 있습니다.

Gemini·ChatGPT(OpenAI)·Claude(Anthropic) 선택, 제공사를 바꿔 중단 작업 이어 읽기, 최종 HWPX·DOCX의 번체·MSR·云/雲 문맥 교정도 유지합니다. 각 제공사의 API 키와 이용 권한이 필요하며 API 이용료는 별도입니다. ChatGPT·Claude 웹 구독과 API는 별개입니다.

## 다운로드와 업데이트

- **설치 권장:** `YeonE_OCR-0.7.4-Setup-x64.exe`를 실행합니다. 현재 사용자 계정에 설치하며 시작 메뉴에 연어OCR을 등록합니다.
- **단일 실행파일 사용자:** `YeonE_OCR-Windows-x64.exe`를 사용합니다. 기존 자동 업데이트용 파일명과 `update.json` 형식을 유지합니다.
- OCR 작업을 마치거나 [중지]로 기록을 저장한 뒤 업데이트하십시오. API 키·설정, 원본 옆 결과 폴더와 저장한 스크린샷은 유지합니다.
