# 구독 계정으로 AI 판독·검증: Claude · ChatGPT · Gemini

로컬 우선 인식에서 AI가 하는 두 가지 일 — **쪽 판독**(`--local-ai-page`)과 **의심 구간 검증** — 을 API 키 없이
자기 구독 계정으로 할 수 있다. 세 회사 모두 **공식 명령줄 프로그램에 자기 계정으로 로그인**하는 방식이다.

| 구독 | 실행하는 공식 프로그램 | 설치 (PowerShell) | 로그인 |
| --- | --- | --- | --- |
| Claude (Pro/Max) | Claude Code `claude -p` | `irm https://claude.ai/install.ps1 \| iex` | `claude auth login` |
| ChatGPT (Plus/Pro/Business/Edu/Enterprise) | OpenAI Codex CLI `codex exec` | `npm install -g @openai/codex` | `codex login` → **Sign in with ChatGPT** |
| Gemini (Google 계정: 무료, Google AI Pro/Ultra, Code Assist) | Gemini CLI `gemini -p` | `npm install -g @google/gemini-cli` | `gemini` 실행 → **Login with Google** → `/quit` |

Codex CLI와 Gemini CLI는 Node.js(20 이상)가 필요하다. 로그인 상태는 `yeone-ocr plans`로 확인한다
(상태 명령만 실행하며 모델은 부르지 않는다).

## 고르기

- 설정 탭 「구독 계정 판독」: 체크(기본 켬)와 계정 선택 — 자동 / Claude / ChatGPT / Gemini.
- 명령줄: `--local-ai-plan auto|claude|chatgpt|gemini`, 환경 변수 `YEONE_OCR_AI_PLAN`.
- **자동**은 로그인된 것 중 Claude → ChatGPT → Gemini 순으로 고른다. Claude가 먼저인 까닭은 2026-11의 기본 설정
  (쪽 판독 prefer, 4구간씩 1024화소 조각, 확신한 제안 반영)을 Claude로 쟀기 때문이다. ChatGPT·Gemini에서도 같은
  설정을 쓰지만 정확도는 아직 재지 않았다.
- 계정을 고르면 그 계정부터 쓰고, 쓸 수 없으면 나머지를 위 순서대로 쓴다.
- 끄기: 체크 해제, 또는 `--local-ai-page off --local-ai-auth api`.

## 사용량 한도에 닿으면: 다른 구독 → API 키, 한도가 풀리면 다시

실행 중에 쓰던 구독 계정이 사용량 한도(5시간·주간·일일)에 닿거나 로그인이 풀리거나 프로그램을 실행할 수 없으면,
**같은 요청을 로그인된 다음 구독 계정으로 다시 보낸다**(Claude → ChatGPT → Gemini 순, 지금 쉬는 계정은 건너뜀).
쪽 판독과 의심 구간 검증이 한 연결을 같이 쓰므로, 한쪽에서 넘어가면 다른 쪽도 넘어간 계정을 쓴다.

계정이 빠지는 기간은 까닭에 따라 다르다.

| 까닭 | 하는 일 |
| --- | --- |
| 사용량 한도 | 그 프로그램이 말한 초기화 시각("resets 12:10am", "try again in 3 hours")까지 쉬고 **다시 쓴다**. 시각을 말하지 않으면 30분 뒤 다시 확인(계속 한도면 60분, 120분 …). |
| 일시 오류(서버 혼잡·네트워크·알 수 없는 실패) | 같은 계정에 3초·10초 뒤 **다시 보낸다**. 그래도 실패하면 그 계정을 10분 쉬게 하고(되풀이되면 20분, 40분 …) 다음 계정으로 보낸다. 같은 요청이 다른 계정에서도 실패하면 요청 탓으로 보고 그 요청만 실패로 남긴다(계정은 그대로). |
| 로그인 만료 · 프로그램 없음 · 요금제에 없는 모델 | 이번 실행에서 다시 쓰지 않는다. |
| 요청 거부(검증 스키마·입력) | 계정은 그대로, 그 요청만 실패. |

쉬는 시간이 지나면 연결은 처음 맡았던 계정으로 돌아간다([다음 구독으로 넘기기]로 직접 넘긴 연결은 돌아가지 않는다).
진행 카드의 **AI 연결** 줄에 지금 쓰는 연결 모두와 쉬는 계정(몇 분 뒤 다시)이 나오고, 마우스를 올리면 그 프로그램이 말한 이유가 나온다.

**쓸 수 있는 구독 계정이 하나도 남지 않으면 바로 API 키로 넘어간다.** 설정 탭에서 고른 제공사와 모델, 그 API 키를 쓰며,
이번 실행의 API 호출은 설정 「AI 판독기」 ③의 「로컬 뒤 AI 검증」 호출 수(`--local-ai-max-calls`, 기본 20)까지다 — 쪽 판독과 검증을 합해 센다.
처음부터 로그인된 구독 계정이 없을 때도 API 키가 있으면 그것으로 검증한다(쪽 판독은 이때 기본으로 끈다).
API 키도 없거나 호출 상한에 닿으면 AI 판독·검증을 멈추고 결과와 검증 대상을 저장한다(쉬던 계정이 돌아오면 그 뒤 쪽부터 다시 검증). 넘어갈 때마다 진행 기록에 적는다.

API 요금을 쓰지 않으려면 `--no-local-ai-api-fallback`.

## 실행 중에 직접 넘기기: [다음 구독으로 넘기기]

구독 계정으로 연결된 실행 중에는 진행 카드 아래에 **AI 연결** 줄이 나온다: 지금 연결(예: Claude 구독) · **넘길 곳** · **[다음 구독으로 넘기기]**.

- **넘길 곳을 고르고 누르면**: 지금 쓰는 구독을 멈추고 고른 계정에 연결한다. 답을 기다리던 요청이 있으면 그 프로그램을
  끄고(자식 프로그램까지) 같은 요청을 새 계정으로 다시 보낸다. 고른 계정이 로그인되어 있지 않으면 정해진 순서로 고른다.
- **고르지 않고(자동) 누르면**: 정해진 순서(Claude → ChatGPT → Gemini, 이번 실행에서 넘긴·실패한 계정은 건너뜀)의
  다음 계정에 연결하고, 남은 구독이 없으면 API 키로 간다. 줄의 '자동(다음: …)'이 갈 곳을 미리 보여 준다.
- 직접 넘긴 계정은 이번 실행에서 저절로 돌아오지 않는다. 넘길 곳에서 직접 고르면 다시 쓴다. 쪽 나눠 보내기에서 같은 계정을 쓰던 다른 연결도 함께 넘어간다.
- 넘길 곳이 하나도 없으면 지금 연결을 그대로 쓴다. 넘길 때마다 진행 기록에 적는다.
- 검증만 자동(`--local-ai-auth auto`)에 두고 그 제공사의 API 키가 없으면, 그 제공사의 구독을 먼저 찾는다.

모델: Claude는 `opus`(`YEONE_OCR_CLAUDE_MODEL`). ChatGPT와 Gemini는 각 프로그램이 요금제에 맞춰 고르는 기본 모델을
쓰고(기록에는 `codex-default`, `gemini-cli-auto`로 남는다), 바꾸려면 `YEONE_OCR_CHATGPT_MODEL`,
`YEONE_OCR_GEMINI_MODEL`. 그 밖의 환경 변수는 각 모듈 머리글(`yeone_ocr/chatgpt_subscription.py`,
`yeone_ocr/gemini_subscription.py`, `yeone_ocr/claude_subscription.py`)에 있다.

## 이 프로그램이 하는 일과 하지 않는 일

- 하는 일: 요청마다 공식 프로그램을 한 번 실행한다. 새 빈 폴더에 그 요청의 그림·지시문·검증 스키마만 두고,
  도구·MCP 서버·확장·사용자 설정·세션 기록을 끈다(Codex: `--ephemeral --ignore-user-config --ignore-rules`,
  읽기 전용 샌드박스, 승인 없음, 웹 검색 끔 / Gemini: `--approval-mode plan -e none --allowed-mcp-server-names none`,
  `GEMINI_SYSTEM_MD`로 지시문 교체). 환경 변수의 API 키(`OPENAI_API_KEY`, `CODEX_API_KEY`, `GEMINI_API_KEY`,
  `GOOGLE_API_KEY`, `ANTHROPIC_API_KEY` 등)는 자식 프로그램에 넘기지 않는다 — 넘기면 구독 대신 API 요금이 나간다.
- 하지 않는 일: 로그인 토큰(`~/.codex/auth.json`, `~/.gemini/oauth_creds.json`, Claude 자격 증명)을 읽거나
  저장하거나 다른 곳으로 보내지 않는다. Gemini는 어느 로그인 방식을 골랐는지 보려고 `~/.gemini/settings.json`만 읽는다.
- 사용량은 각 요금제의 한도(5시간·주간·일일)에서 차감된다. 한도에 닿으면 위 「사용량 한도에 닿으면」대로 다른 계정 →
  API 키로 넘어가고, 갈 곳이 없으면 결과와 검증 대상을 저장하며 메시지로 알린다.
- **개인 사용 전용.** 각 회사는 공식 프로그램을 자기 계정으로 쓰는 것은 허용하지만, 제3자 프로그램이 구독 로그인을
  가져가 쓰거나 다른 사람에게 나눠 주는 것은 허용하지 않는다(특히 Google은 Gemini CLI 로그인(OAuth)을 다른
  프로그램이 직접 쓰는 것을 약관으로 금한다). 다른 사람에게 줄 설치본이나 여러 사람이 쓰는 작업에는 API 키를 쓴다.

## 다른 점

- Claude Code는 검증 스키마를 직접 받는다(`--json-schema`). Codex CLI도 받는다(`--output-schema`).
  Gemini CLI는 스키마 옵션이 없어 지시문에 스키마를 넣고, 받은 답을 JSON으로 검사한다(``` 울타리는 벗긴다).
  JSON이 아니면 그 호출은 "완료되지 않음"으로 남고 엔진 판독을 쓴다.
- 그림: Claude는 stream-json 입력에 base64로, Codex는 `-i 파일`, Gemini는 지시문의 `@image1.png` 참조로 보낸다.
- 지시문은 셋 다 표준 입력으로 넘겨 Windows 명령줄 길이 제한(cmd.exe 8191자)에 걸리지 않는다.
  npm으로 설치한 `codex.cmd`, `gemini.cmd`도 그래서 쓸 수 있다.

## 동시 AI 요청 (1.2.7)

구독 계정으로 검증할 때 한 쪽의 검증 묶음을 여러 개 함께 보낸다(설정 「AI 판독기」 ③ 「동시 AI 요청」, 기본 3, `--local-ai-parallel`). 요청만 겹치고 응답 확인·기록은 차례대로다. 총 사용량은 같고 한도가 그만큼 빨리 찬다. API 키로 검증할 때는 하나씩 보낸다.

## 쪽 나눠 보내기 (1.2.8)

로그인된 구독이 둘 이상이면 계정마다 쪽을 맡아 함께 진행할 수 있다(설정 「AI 판독기」 ① 「쪽 나눠 보내기」, `--local-ai-split`, 1.2.9부터 기본 켬 — 끄려면 체크 해제 또는 `--no-local-ai-split`). 한 쪽은 한 계정이 끝까지 검증하고, 한도는 계정마다 나눠 쓴다. 쪽마다 검증한 모델이 다를 수 있으며 ChatGPT·Gemini의 검증 정확도는 아직 재지 않았다. 실제로 답한 계정·모델은 검증 기록에 남는다.

## 엔진은 기다리지 않는다 · 계정이 함께 맡는 쪽 · 쪽 판독과 검증을 함께

구독 계정으로 검증하는 실행에서는 엔진이 AI의 답을 기다리지 않고 다음 쪽을 계속 읽는다. 엔진을 마친 쪽은 판독을 먼저 저장하고 쪽 차례대로 AI 차례를 기다린다(쪽 띠의 **AI 대기**). 계정 하나는 한 번에 여러 쪽을 맡는다(설정 「AI 판독기」 ① 「계정이 함께 맡는 쪽」, 기본 2, `--local-ai-pages` 1~4). 한 쪽 안에서는 AI 쪽 판독과 의심 구간 검증을 함께 보낸다(서로의 결과를 쓰지 않고 기록에서 만난다).

- 전체 시간은 AI가 정한다(엔진은 GPU로 쪽당 몇 초~십몇 초, AI는 쪽당 수십 초~몇 분). 그래서 "엔진으로 전부 읽은 뒤 AI에 보내기"만으로는 전체 시간이 줄지 않는다 — 줄이는 것은 AI 쪽의 동시 처리(계정 수 × 함께 맡는 쪽 수 × 동시 AI 요청)다. 엔진이 앞서 읽으면 책 전체의 엔진 판독이 먼저 저장되고, AI 작업자가 쪽을 기다리며 쉬는 일이 없다.
- 총 사용량은 같고 한도(5시간·주간·하루)가 그만큼 빨리 찬다.
- 진행 수는 엔진이 읽은 쪽이 아니라 **끝난 쪽**(AI 부분까지)이다. [중지]를 누르면 답을 기다리던 쪽까지 끝내고, 차례를 기다리던 쪽은 엔진 판독만 남는다 — 다음 실행(「끝나지 않은 쪽만 점검」)에서 엔진을 다시 돌리지 않고 이어 검증한다.

## 연결 시험

설정 「AI 판독기」 ① 「로그인 상태」의 **[연결 시험]**(명령줄 `yeone-ocr plans --test`)은 쓸 수 있는 구독마다 작은 요청 하나(빈 그림 + 한 칸짜리 답)를 실행 때와 같은 방식으로 실제로 보낸다. 답하면 모델과 걸린 시간을, 실패하면 그 프로그램이 말한 이유를 보여 준다. 구독 사용량에서 조금 차감된다. 긴 작업 전에 눌러 보면 "로그인은 되어 있는데 실제로는 답하지 못하는" 계정을 미리 찾는다.

## 로그인 상태가 이상할 때

설정 「AI 판독기」 ①의 「로그인 상태」에 마우스를 올리면 계정마다 찾은 프로그램 경로와 이유가 나온다(명령줄 `yeone-ocr plans`도 같음).

- **설치 안 됨**: 그 회사의 공식 프로그램(Codex CLI · Gemini CLI)을 찾지 못함. Gemini 구독(Google AI Pro 등)이 있어도 연어OCR은 **Gemini CLI**를 통해서만 쓴다 — PowerShell에서 `npm install -g @google/gemini-cli` 뒤 `gemini`를 한 번 실행해 'Login with Google'. PATH에 없어도 npm 전역 폴더(`%APPDATA%\npm`)·Node 설치 폴더·nvm·Volta에서 찾는다. 다른 곳에 있으면 환경 변수 `YEONE_OCR_GEMINI_CLI_PATH`로 지정.
- **실행 실패**: 찾았지만 `gemini --version`이 실패함 — 이유(종료 코드·오류 문구)가 함께 나온다. 흔한 원인은 Node.js가 20보다 낮음.
- **로그인 필요**: 설치됐지만 Google 계정 로그인이 아님 — `gemini`에서 /auth로 'Login with Google'.
