# 여섯 로컬 OCR 모델 비교와 주력 선택

연어OCR 0.10.0은 기존 Tesseract·RapidOCR 모바일·EasyOCR와 PaddleOCR 서버형·GLM-OCR·Surya를 같은 편집기에 연결한다. 세로 읽기·책갈피 OCR·이미지 OCR·문서 내보내기는 기존 작업 흐름을 유지한다.

## 사용

상단 **OCR 모델 비교·교정**에서 원본을 열고 문서 종류와 모델 묶음을 선택한다.

- **권장 비교**: 문서 종류별 주력과 다른 모델 계열의 참고 판독, 총 세 개.
- **기존 3엔진**: Tesseract·RapidOCR·EasyOCR.
- **전체 6엔진**: 설치된 여섯 엔진을 모두 실행한다. 준비되지 않은 엔진은 오류로 남긴다.
- **주력만**: 새 쪽을 주력 하나로 판독한다. AI 불일치 검증은 같은 조건의 정상 판독 세 개 이상이 필요하다.

새 쪽에 주력 기준을 적용한다. 기존 프로젝트의 기준·교정문·AI 제안과 확정 이력은 모드 변경이나 새 모델 추가만으로 바뀌지 않는다. 기준을 바꾸려면 기준 선택을 명시적으로 사용한다. 명령줄에서는 `compare-engines ... --engine-set recommended`를 사용한다. 기존 인자만 쓰는 명령과 라이브러리 호출은 종전 세 엔진을 유지한다.

## 모델·실행 환경

| 엔진 | 비교하는 배포 모델 | 좌표와 제한 |
|---|---|---|
| Tesseract | 기존 고정 tessdata와 PSM | 단어 좌표, 혼용 언어 팩 |
| RapidOCR | PP-OCRv5 모바일 문자 인식 | 줄 좌표, 한국어 모델은 한자 미지원 |
| EasyOCR | 기존 고정 한국어·중문 모델 | 검출 영역, 한국어 모델은 한자 미지원 |
| PaddleOCR 서버형 | PP-OCRv5 서버 문자 인식 · ONNX · RapidOCR | 줄 좌표, 한글 서버 모델 미지원 |
| GLM-OCR | 공식 Ollama `glm-ocr:bf16` 태그의 실제 F16 GGUF | 문자·행 좌표와 신뢰도 없음 |
| Surya | 공식 Surya OCR 2 · 650M · GGUF | 블록 좌표, 원형 HTML과 파생 텍스트 구분 |

대용량 모델·별도 Python·Ollama·llama.cpp·CUDA는 앱 배포물에 넣지 않고 명시적으로 설치한다. 선택된 한 엔진 폴더에 모두 준비하며 다른 폴더나 언어로 묵시 대체하지 않는다. 설치 안내는 [로컬 OCR](LOCAL_OCR.md), [Paddle 서버형](PADDLE_SERVER.md), [GLM-OCR](GLM_OCR.md), [Surya](SURYA_LOCAL.md)를 따른다. 로컬 인식은 외부 API·API 키를 사용하지 않는다.

## 측정 정책

같은 세 문헌의 **혼용 상단 본문 2영역·번체 본문 58쪽·간체 본문 60쪽**, 합계 120단위·공백 제외 정답 66,463자를 비교한다. 원본 HWPX·DOCX에서 마련한 사전 고정 정답을 사후 채점에만 사용한다. 추론 모델에는 같은 PNG 이미지만 제공하고 정답 문장을 입력하지 않는다. 기존 360건은 입력 이미지 바이트 또는 픽셀 해시가 같음을 확인해 재사용하고 새 모델 360건은 로컬에서 실행한다.

주력은 결과를 보기 전에 고정한 정책에 따라 문서 종류별 **한글·한자 귀속 오류율**, 다음으로 전체 CER를 비교한다. 문자군 오류는 전체 문장 정렬에서 정답 글자의 종류로 귀속한 대치·누락과 해당 문자군 삽입을 센 수치이며, 문자군만 따로 정렬한 CER와 다르다. 쪽마다 정답을 보고 모델을 골라 합치는 방식은 사용하지 않는다.

주요 CER는 공백만 제거한다. Unicode 정규화, 간체·번체·이체자 치환, 중문부호 접기는 하지 않는다. 공백을 포함한 원시 CER와 쪽별 오류·완료 여부·모델 및 입력 해시는 별도로 보관한다. 한글 서버 모델이 없는 Paddle의 혼용 평가는 번체 모델을 명시한 결과다.

개인 문헌·정답·원시 결과·상세 수치는 Git에서 제외한 `work/new-engine-comparison`에만 둔다. 최종 로컬 보고서는 `report/report.html`, 수치와 해시 목록은 `report/summary.json`, CSV는 `report/metrics.csv`다.

### 측정 결과와 기본값

전체 문자 CER(%, 낮을수록 좋음)은 다음과 같다. 공백만 제외하고 부호·숫자·이체자 차이도 오류로 센다.

| 엔진 | 혼용 2영역 | 번체 58쪽 | 간체 60쪽 |
|---|---:|---:|---:|
| Tesseract | 17.877 | 18.833 | 22.340 |
| RapidOCR 모바일 | 25.698 | 16.012 | 15.348 |
| EasyOCR | 24.767 | 5.976 | 12.933 |
| PaddleOCR 서버형 | 91.993 | 15.435 | 14.820 |
| GLM-OCR | 10.801 | 12.942 | 10.667 |
| Surya | 1.676 | 15.705 | 15.065 |

한글·한자 최우선 정책으로 선정한 주력은 아래와 같다. **번체는 GLM의 한자 오류가 적지만, 부호 등까지 포함한 전체 CER는 EasyOCR가 더 낮다.** 이 차이를 숨기거나 부호를 몰래 변환하지 않는다.

| 문서 종류 | 주력 | 기존 세 엔진 중 최저 한글·한자 귀속 오류율 | 주력의 같은 오류율 | 권장 비교 |
|---|---|---:|---:|---|
| 혼용 | Surya | 19.955% (Tesseract) | 2.041% | Surya·GLM·Tesseract |
| 번체 | GLM-OCR | 2.633% (RapidOCR) | 1.072% | GLM·Surya·EasyOCR |
| 간체 | GLM-OCR | 1.780% (RapidOCR) | 0.988% | GLM·Surya·EasyOCR |

혼용에서 Paddle 서버형의 큰 오류는 한글 미지원 조건을 함께 해석해야 한다. 번체·간체의 권장 비교에는 부호 대조에 도움이 되는 EasyOCR를 남긴다. 세로쓰기는 이번 자료에서 측정하지 않았으므로 Tesseract 기준과 기존 세 엔진 비교를 유지한다. 이 기본값은 새 쪽에 적용하며 이미 저장한 판독·교정 기준을 자동 변경하지 않는다.

이 범위는 개발용 모델 선택 자료다. 독립된 보류 평가, PDF 전체 382쪽, 세로쓰기·표·도판·목차의 성능을 측정한 것으로 해석하지 않는다. HWPX·DOCX 정답도 완전한 독립 이중 검수 정답으로 주장하지 않는다. 서로 다른 CPU·GPU·배치 조건의 시간은 참고 기록이며 통제된 속도 순위가 아니다. 이번 모델 비교에서 외부 AI 재검증은 실행하지 않는다.

## 원시·제안·확정 보존

엔진 원시 Unicode와 실제 좌표·모델/런타임 해시를 보존한다. Surya의 원래 HTML·파싱 결과와 편집용 파생 텍스트를 구분하며 GLM에 가짜 글자 좌표나 신뢰도를 만들지 않는다. 생성이 잘렸거나 실패한 모델 응답은 원시 증거로 보존하고 비교·AI 기준에서 제외한다.

수천 개 파일을 포함한 실행 환경은 전체 파일을 검증한 뒤 이름·해시·크기의 지문과 원래 설치 manifest SHA-256을 쪽별 기록에 둔다. 전체 inventory는 로컬 설치 manifest에 보존한다. 반복되는 inventory 때문에 긴 문서의 프로젝트 저장 한도를 소진하지 않도록 하며 재개 시 실제 파일을 확인해 같은 지문인지 검사한다.

AI는 선택된 원본 이미지와 OCR 문맥에서 제안만 만든다. 원래 AI 응답·위치 복원 근거·제안과 사람의 채택·기각·되돌리기는 별도 기록한다. 원본이나 원시 OCR을 바꾸거나 AI 제안을 자동 확정하지 않는다. 저장·재열기에서 이력 의미와 원본 변경 여부를 확인한다.
