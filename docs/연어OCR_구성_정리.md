# 연어OCR 프로그램 구성 정리 (2026-11, 브랜치 `claude/vigilant-tesla-g7idfq`)

이 문서는 이번 개발에서 바꾸고 더한 것을 한곳에 모은 안내입니다. 세부 측정과 옵션 설명은 `docs/LOCAL_FIRST.md`에 있습니다.

## 1. 전체 흐름 (기본 "로컬 우선" 인식)

```
PDF ─▶ 쪽 그림(300dpi, 한 번만 그려 모든 엔진이 같이 씀)
     ─▶ ① 로컬 엔진 판독 (CPU·GPU 엔진을 동시에, 쪽마다 가장 좋은 판독 선택)
     ─▶ ② (Claude 구독에 로그인되어 있으면 자동) AI 쪽 판독: 쪽을 원래 해상도 띠로 잘라 Claude가 처음부터 읽음
     ─▶ ③ 의심 구간 AI 검증: 엔진끼리 다른 곳·확신 낮은 곳만 조각 이미지로 다시 봄 (구독이면 원래 해상도 조각 포함)
     ─▶ ④ 정리: 쪽 번호 분리 · 두 단 순서 · 한국 표준 한자 모양 · ②와 ③ 결과 합치기
     ─▶ ⑤ HWPX 문서: 불확실한 글자를 메모 없이 형광 바탕 + 빨강/파랑/초록 글자로 표시
```

비교·교정 창에는 엔진의 원래 판독이 그대로 남고, ②·④의 변경은 문서 글에만 들어갑니다(되돌릴 수 있음).

## 2. 엔진과 기본 설정

| 문서 | 기본으로 함께 읽는 엔진 | 근거(측정) |
|---|---|---|
| 가로쓰기 한문(번체·간체) | PP-OCRv6, RapidOCR, Tesseract + GPU 1개(GLM-OCR) | EasyOCR은 빼는 편이 한자가 더 정확하고 27~35% 빠름 |
| 가로쓰기 한글·한자 혼용 | Tesseract + GPU 1개(Surya) | 대조도감 91.1% → 6.88%, 쌍행소주 57.2% → 4.86% |
| 세로쓰기 한글·한자 혼용 | Tesseract + **Surya** | 풍수지리 6쪽: Tesseract 34.44% → Surya 2.39% (GLM-OCR 15.19%, 한글 전용 모델 52.72%) |

- GPU 엔진은 한 실행에 하나만 씁니다(8GB 그래픽카드와 PC 전체 GPU 대기열 때문). GPU가 없으면 CPU 엔진만 씁니다.
- 엔진 프로세스는 실행 내내 띄워 두고 다시 씁니다(모델을 쪽마다 다시 읽지 않음).
- 줄마다 다시 확인(PP-OCRv6·EasyOCR 추가 검증)은 기본 끔: 결과 글자는 같고 30~37% 느렸음.

## 3. Claude 구독 연결 (연어 포토 에디터와 같은 방식)

- PC에 설치된 공식 Claude Code(`claude -p`)를 실행만 합니다. 로그인 토큰은 읽지도 저장하지도 않습니다. 구독 사용량(5시간·주간)에서 차감, API 요금 없음. **개인 사용 전용**.
- 준비: PowerShell에서 `irm https://claude.ai/install.ps1 | iex` → `claude auth login` → `claude auth status`(subscriptionType 확인).
- **기본(가)**: 로그인되어 있으면 자동으로 ②+③을 합니다. 끄려면 설정 창의 「Claude 구독 판독」 체크를 끄거나 `--local-ai-page off --local-ai-auth api`.
- 구독일 때 자동 설정: 쪽 판독 prefer, 의심 구간 4개씩 묶어 검증, 1024화소 원래 해상도 조각, 확신한 제안 반영, 이번 실행 호출 상한 1000.
- 사용량: 쪽 판독 한 번에 대략 5시간 사용량의 0.2~0.3%(추정), 의심 구간 검증은 거의 표시되지 않음.

### ② AI 쪽 판독의 합치기 규칙 (`yeone_ocr/ai_page.py`)
| 경우 | 처리 |
|---|---|
| 두 판독이 같음 | 그대로 (서로 다른 두 판독이 일치) |
| 6자 이하로 다름 | AI 글자를 문서에 넣고 초록 |
| 부호만 다름 | 엔진 부호를 둠 (세로쓰기 마침표를 AI가 ·로 적음) |
| AI가 불확실하다고 한 낱말 | 엔진 글자를 두고 빨강 (두 판독이 같아도 빨강) |
| 긴 차이(순서·빠진 줄) | 엔진 글자를 두고 빨강 |
| 유사도 0.7 미만 | AI 판독을 쓰지 않음 |

판독 결과는 쪽 그림·모델·프롬프트 기준으로 저장해 같은 쪽을 다시 사지 않습니다.

### ③ 의심 구간 검증 개선
- 확신도 0~1/0~100 단위 혼동 버그를 고침(엔진별 기준값).
- Surya·GLM-OCR처럼 확신도가 없는 엔진이면 블록 단위로 한 번만 보냄(같은 글을 두 번 보내 호출 상한을 넘던 문제).
- 큰 이미지는 원래 해상도 조각을 함께 보냄: AI의 "불확실" 보류가 10개 → 4개로 줄고 반영이 3개 → 9개로 늘었음.
- 보류되면 쪽마다 이유를 로그에 남김.

## 4. 문서(HWPX) 출력

- 메모 없이 불확실 글자를 형광 바탕 + 글자색으로 표시(`--display`, 설정 「단순 표시」).
  - 빨강: 엔진끼리 다르거나, 알 수 없는 글자, AI가 다르게 제안했거나 불확실하다고 함
  - 파랑: 엔진 자신의 확신이 낮음, 또는 다른 증인(PDF 글자층·AI 대조)이 다르게 읽음
  - 초록: 엔진 판독에서 바뀐 글자(AI 채택, 다수결, 사람 교정)
- 저장 구조 단순화(`simple`), 쪽 번호는 본문에서 빼서 쪽 기록에만 둠(쪽의 첫·끝 줄이 가장자리의 맨 숫자일 때).
- 두 단 조판: 가로쓰기 두 단 본문 쪽은 왼쪽 단 → 오른쪽 단 순서(표·사진 설명은 그대로). 의방집해 102% → 17%.
- **한국 표준 한자 모양(기본)**: 한글·한자 혼용 문서는 KS X 1001에 없는 모양을 그 안의 짝으로 바꿈(説→說, 真→眞, 即→卽, 概→槪 등 286쌍). 한국 책에 쓰이는 글자(欠·缺, 余·餘)는 그대로. 끄려면 `--no-local-korean-forms`.

## 5. 속도

- 쪽 그림 캐시(한 번 그려 모든 엔진·미리보기·AI 조각이 같이 씀), 파일 해시 재사용, 글꼴 해시 캐시.
- 엔진 병렬 실행(CPU 코어·메모리에 맞춰 자동), 엔진 프로세스 상주, GPU 세션 전용 스레드.
- 줄 다시 확인 기본 끔: 의방집해 152.8 → 96.9초/쪽.
- EasyOCR 가로쓰기 기본 끔: 의방집해 70.3초/쪽, 중의역대 24~35초/쪽.

## 6. 측정 도구 (`tools/compare_local_options.py`)

- `TEST용 파일들` 폴더의 PDF와 같은 이름의 정답(.hwpx/.hwp/.docx/.txt)을 짝지어, 옵션 묶음(세트)별로 같은 쪽을 읽고 오류율(CER)을 냅니다: 전체 · 부호 제외 · 글자 모양도 무시.
- 주요 세트: `default`(엔진만), `auto`(로그인 시 기본 동작), `ai-page`, `ai-page+review`, `ai-subscription-tiles`, `gpu-vertical`, `no-easyocr`, `no-korean-forms` 등.
- 결과: `summary.md/csv`, 세트 폴더의 `errors.txt`(정답 → 판독 차이), `ai_proposals.txt`(AI 제안·보류 이유). 올릴 때는 `보고\<문서>\<세트>-errors.txt` 사본을 쓰세요(세트 폴더는 다음 실행 때 지워짐).
- `--resume`(끝난 세트 재사용), `--redo`, `--only`, `--max-pages`. 사용 중인 폴더는 다시 시도 → 새 폴더에서 읽음.
- 실행 예:

```
python tools\compare_local_options.py "C:\Projects\YeonE_OCR\TEST용 파일들" --out "C:\Projects\YeonE_OCR\측정" --engine-root C:\Projects\YeonE_OCR --only 풍수지리 --max-pages 6 --sets default,auto
```

## 9. 남은 과제

- 정답 파일(풍수지리)의 即·概·既·脱·様을 한국 표준 모양(卽·槪·旣·脫·樣)으로 고치기.
- 다른 세로쓰기·가로쓰기 문서에서도 `auto`(구독 판독)를 측정해 효과·사용량 확인.
- AI가 불확실하다고 했지만 맞았던 글자(예: 丈)를 더 살릴 방법(두 번째 의견 등).
- 남에게 배포할 때는 구독 대신 API 키를 쓰도록 안내(약관).
