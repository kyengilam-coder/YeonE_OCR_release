# AB_OCR 요구사항

## 목적과 현재 범위
- AB_OCR은 별도 Windows 데스크톱 프로젝트로 새로 개발한다.
- 한글·한자 혼용 문헌의 인식 정확성과 원본 대조 편집을 우선한다.
- 참고하는 사용자 흐름은 FineReader의 문서 열기 → 영역 확인 → OCR → 교정 → 저장·내보내기다.
- 기존 프로젝트의 코드·설정·비밀키·작업 자료를 자동으로 가져오지 않는다.
- 이 문서는 **개발 요구사항**이다. 아래 기능은 구현·검증 전까지 모두 계획 상태다.
- FineReader와 동등한 정확도·속도·레이아웃 재현성은 실측 전에는 보장하지 않는다.

## 1. 원본 보존과 문서 작업
- PDF, PNG, JPEG, 다중 페이지 TIFF를 입력하고 페이지 목록·썸네일을 표시한다.
- 원본을 수정하지 않으며 회전·기울기 보정·이진화는 작업용 파생 이미지에 적용한다.
- 확대·축소·이동 가능한 원본 화면과 편집 가능한 인식문을 나란히 제공한다.
- 제목·본문·주석·단순표·그림·머리말·쪽번호 영역을 구분한다.
- 영역 추가·삭제·경계 조정·읽기 순서 변경과 실행 취소·다시 실행을 지원한다.
- 전체 문서·선택 페이지·선택 영역을 처리하고 진행률·취소·실패 원인을 표시한다.
- 부분 성공과 미처리 페이지를 구분하며 중단 후 완료된 작업을 재사용한다.

## 2. 한글·한자 인식 및 교정
- 가로쓰기와 세로쓰기의 방향·열 순서를 영역별로 기록한다.
- 현대 한글뿐 아니라 한글·한자 혼용, 작은 주석, 숫자·기호를 평가 대상으로 삼는다.
- 이체자·확장 한자·옛한글을 보존한다. 지원하지 않는 문자는 추측 대신 미확인으로 남긴다.
- 원문 전사와 선택적인 정자화·현대화 결과를 분리하며 자동 치환을 기본으로 적용하지 않는다.
- 엔진 신뢰도와 사람의 검수 상태를 구분한다. 신뢰도가 높다고 검수 완료로 표시하지 않는다.
- 불확실한 글자, 영역, 대안 후보를 원본 위치와 연결해 검수한다.
- 로컬 및 클라우드 인식기를 교체할 수 있는 공통 인터페이스를 제공한다.
- 클라우드 전송은 사용자가 해당 엔진을 선택하고 실행한 경우에만 한다.
- 클라우드 실행 전 전송 범위와 가능한 비용 추정·추정 불가 여부를 보여 준다.

## 3. 프로젝트 저장 및 내보내기
- 별도 프로젝트에 원본 지문, 페이지·영역 구조, 인식 결과, 수정 내역, 검수 상태를 저장한다.
- 저장은 임시 파일 작성·검증 후 원자적으로 교체하고 마지막 정상 저장본을 보존한다.
- 재열기 때 원본 지문을 확인한다. 파일이 이동하면 사용자가 원본을 다시 연결할 수 있다.
- 원본 내용이 달라졌을 때 기존 좌표와 교정을 새 원본에 자동 적용하지 않는다.
- TXT는 확인된 읽기 순서를, DOCX는 문단·표와 실제 도판 이미지를 보존한다.
- 검색 가능한 PDF는 원본 외관을 유지하며 교정한 글자층을 별도 결과 파일에 넣는다.
- 미처리·누락·지원하지 않는 내용과 글자층 검증 실패를 내보내기 결과에 명시한다.
- API 키는 프로젝트·로그·내보내기에 포함하지 않고 운영체제 자격 증명 저장소를 사용한다.

## 4. 정확도 평가와 출시 판단
- 사용 권한을 확보한 대표 원본과 사람이 대조한 정답을 고정된 평가 세트로 만든다.
- 가로/세로, 한글/한자/혼용, 본문/주석/표, 깨끗한 스캔/저해상도/기울어짐으로 구분한다.
- 엔진·설정 조정용 자료와 최종 비교용 자료를 분리해 평가 자료에 맞춘 과적합을 줄인다.
- 기본 지표는 CER = (대체 + 삭제 + 삽입 문자 수) / 정답 문자 수다.
- 정답 문자가 없는 페이지는 CER 평균에 억지로 넣지 않고 삽입 오류를 별도로 보고한다.
- 원문 Unicode 기준 CER와 명시된 정규화 규칙 적용 후 CER를 함께 보고한다.
- NFC·공백·문장부호·호환 한자·이체자 처리 규칙을 버전 관리하며 원문 점수를 숨기지 않는다.
- 전체 문자 가중 CER와 자료 유형별 CER를 모두 제시한다. 한글·한자별 오류도 분리한다.
- 읽기 순서 오류, 영역 누락, 표 셀 정확도, 처리 시간, 메모리, API 비용을 별도 측정한다.
- 같은 입력·언어·장치·출력 조건에서 비교하며 제품·엔진 버전과 실행 설정을 기록한다.
- FineReader 비교는 적법하게 사용 가능한 실행 환경과 동등 조건이 있을 때만 수행한다.
- 출시 기준 수치는 기준선 측정 후 확정한다. 비교 데이터 없이 '동급'·'더 정확함'을 표시하지 않는다.

## 단계별 완료 조건
1. 프로젝트 기반: 독립 실행, 설정, 입력 검사, 테스트 실행 수단을 마련한다.
2. 수동 편집: 입력 → 영역·텍스트 편집 → 저장 → 재열기를 자동 시험으로 확인한다.
3. OCR 연결: 실제 엔진 한 종류로 인식·취소·부분 실패·결과 반영을 확인한다.
4. 내보내기: 실제 파일의 재열기, 본문·도판 보존, PDF 외관과 추출 글자를 검증한다.
5. 품질 비교: 고정 평가 세트의 수치와 실패 사례를 기록하고 후속 개선 우선순위를 정한다.
