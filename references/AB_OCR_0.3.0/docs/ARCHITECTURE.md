# AB_OCR 설계 초안

## 현재 구현 (0.3.0)
- `editor_gui.py`: Tk 교정 편집기. 원본 렌더·OCR·파일 저장은 작업 스레드에서 실행하고 큐로 UI에 반영한다.
- `document.py`: 쪽별 원시 OCR·이전 인식·교정문·검수 상태를 분리한다. `.abocr.json` 원자 저장, 원본 지문 확인, 복구 사본을 제공한다.
- `ocr.py`: 공통 인식 진입점과 로컬 Tesseract 어댑터, PDF/이미지 렌더, 쪽 수 확인, 좌표와 인식 조건을 반환한다.
- `local_engines.py`: 프로젝트 전용 Python 환경의 RapidOCR/EasyOCR worker를 실행한다. 모델 해시와 JSON·좌표를 검증하고 취소·시간 제한을 적용한다.
- `rapidocr_worker.py`, `easyocr_worker.py`: 로컬 모델만 사용하는 별도 프로세스다. 원시 인식 문자열을 정규화하지 않고 보존한다. 반환 영역은 글자 단위가 아니라 검출한 줄/영역 단위일 수 있다.
- `gui.py`, `evaluation.py`, `benchmark.py`, `reports.py`: 별도 정확도 평가 작업대와 재현 가능한 결과 보고서다.
- 원본은 외부 파일로 참조하며 미리보기는 파생 이미지다. 좌표는 **OCR 렌더 이미지 픽셀 xyxy**로 저장하고 미리보기 크기에 맞추어 표시한다.
- 프로젝트는 원본 SHA-256, 페이지 기록, 원시 엔진 결과와 사람의 교정문을 보존한다. 여러 쪽 TXT는 `\n\f\n`으로 구분한다.
- 실제 로컬 엔진은 Tesseract·RapidOCR·EasyOCR다. 반환 결과에 엔진명·모델·언어·처리 조건을 기록하며 기존 Tesseract 프로젝트와 호환된다. 임의 플러그인 등록·클라우드 어댑터는 아직 구현하지 않았다.

## 향후 설계와 경계
아래 전체 구조는 **제안 설계**다. 영역·읽기 순서 편집, 공통 엔진 capability 등록,
검색 PDF·DOCX 출력 등 현재 구현 목록에 없는 항목은 계획 상태다.

## 계층과 책임
| 계층 | 책임 | 경계 |
| --- | --- | --- |
| Desktop UI | 페이지·영역·원본 대조·텍스트 편집 | 파일 저장과 엔진 호출을 직접 구현하지 않음 |
| Application | 작업 큐, 명령, 실행 취소, 진행 상태, 내보내기 흐름 | GUI 이벤트 루프를 막지 않음 |
| Domain | 문서·페이지·영역·읽기 순서·검수 상태 | GUI 및 특정 엔진에 의존하지 않음 |
| Input/render | PDF·이미지 읽기, 렌더링, 파생 이미지 | 원본은 읽기 전용 |
| OCR adapters | 로컬·클라우드 요청과 결과 변환 | 엔진별 좌표·신뢰도를 명시적으로 변환 |
| Project storage | 버전 검사, 지문, 스냅샷, 원자적 저장 | 원본·다른 프로젝트 덮어쓰기 방지 |
| Export | TXT, DOCX, 검색 PDF | 편집 모델을 읽으며 원본·프로젝트를 변경하지 않음 |
| Evaluation | 정답 비교, CER, 실행 조건·산출물 기록 | 제품 UI의 검수 완료 상태와 별개 |

## 공통 문서 모델
- `Document`: ID, 원본 참조, 콘텐츠 SHA-256, 페이지 순서, 프로젝트 형식 버전.
- `Page`: 원본 페이지 ID, 원본 크기, 표시 변환, 영역 순서, 처리 상태.
- `Region`: 안정적인 ID, 종류, 경계, 읽기 방향, 문단/줄/표 구조, 원본 좌표 참조.
- `Recognition`: 엔진·모델·설정·시각, 원시 전사, 글자/단어 좌표, 가능한 신뢰도, 경고.
- `Correction`: 교정 전·후 값, 대상 ID, 수정 사유(선택), 사람의 검수 상태.
- 원시 OCR 결과와 현재 교정본을 따로 보존하며 재인식이 수동 교정을 자동 덮어쓰지 않는다.
- 영역 좌표는 정규화한 원본 페이지 좌표계 하나로 저장한다. 회전·확대는 명시적 변환으로 다룬다.
- 이미지 보존 영역과 미인식 영역을 구분하고, 그림 내부 글자를 본문에 자동 혼합하지 않는다.

## 엔진 계약과 작업 실행
- `capabilities()`는 언어, 세로쓰기, 영역 인식, 표, 글자 좌표 등의 실제 지원 범위를 반환한다.
- `recognize(request, cancellation)`는 독립된 결과 객체를 반환한다. 프로젝트를 직접 수정하지 않는다.
- 요청에는 작업 ID, 파생 이미지, 좌표 변환, 언어·방향, 사용자 선택 설정만 전달한다.
- 응답 좌표와 페이지 식별자를 검증한 뒤 애플리케이션 계층에서 한 번의 편집 명령으로 반영한다.
- 공급자별 신뢰도 척도는 의미를 보존한다. 없는 신뢰도를 임의로 100점으로 채우지 않는다.
- 렌더링·OCR·내보내기는 작업 스레드 또는 프로세스에서 실행한다. UI 갱신은 UI 스레드만 한다.
- 문서 변경 후 도착한 오래된 결과는 문서 ID·수정 버전으로 가려내 반영하지 않는다.
- 취소는 새 작업 제출을 중단하고 완료된 결과를 보존한다. 원격 요청 비용 발생 여부를 구분한다.
- 로컬 엔진 부재·언어팩 부재·네트워크 실패를 구분해 복구 방법과 재시도 범위를 보여 준다.

## 프로젝트 저장
- 초기 형식은 버전이 있는 JSON 프로젝트와 파생 이미지 캐시를 별도로 두는 방안을 검토한다.
- 원본 경로와 콘텐츠 지문을 함께 기록하되 경로 이동과 내용 변경을 구분한다.
- 임시 파일 쓰기 → 재읽기·스키마 검사 → 원자적 교체 순서로 저장한다.
- 디스크 부족·중단·형식 불일치가 생겨도 이전 정상 프로젝트를 유지한다.
- 스키마 이행은 명시적으로 수행하고, 알 수 없는 미래 버전을 덮어쓰지 않는다.
- 썸네일·파생 이미지는 다시 만들 수 있는 캐시다. 교정 데이터의 유일한 저장소로 쓰지 않는다.
- 로그에 API 키와 원문 전체를 기본 기록하지 않는다. 진단 수집 범위는 사용자가 선택한다.

## 내보내기와 검증
- TXT: 읽기 순서와 페이지 경계를 보존하며 비문자 영역·미처리 페이지 처리 방식을 명시한다.
- DOCX: 제목·문단·단순표를 실제 구조로 작성하고 도판은 관련 본문 위치에 삽입한다.
- PDF: 스캔 외관을 유지하고 중복 글자층을 방지한다. 보이는 원문 글자의 처리 방침을 별도로 정한다.
- PDF 결과를 다시 열어 페이지 수, 렌더링 외관, 한글·확장 한자를 포함한 추출 문자를 확인한다.
- 내보내기 성공과 문자 정확도 검증을 구분한다. 일부 페이지 실패 시 부분 결과를 명시한다.

## 검증 순서
1. 도메인: 좌표 변환, 읽기 순서, 교정·실행 취소, 불확실성 보존.
2. 저장: 왕복 저장, 원본 변경 감지, 손상·쓰기 실패 시 마지막 정상본 보존.
3. 엔진: 고정 fixture로 요청·응답 변환, 취소, 부분 실패, 오래된 결과 반영 방지.
4. 통합: 원본 → 실제 OCR → 교정 → 재열기 → 실제 내보내기 경로를 점검.
5. 평가: 고정 정답과 원문/정규화 CER, 누락·순서 오류, 시간·비용을 반복 측정.
