# AB_OCR 0.3.0 검증 범위

## 구현과 확인

2026-10-16 Windows/Python 3.14.5에서
`unittest discover -s tests -q` **134개 통과**(10.020초). 엔진 연결부 통합 당시 131개에 이어 worker의 프로필·실패 경로 시험을 확장했다.
GUI·문서 저장·정확도 계산·로컬 엔진 경계를 검증하며, 자동 시험 통과를 실제 인식률로 표시하지 않는다.

- 독립 평가기: 원문/명시적 정규화 CER, 정확한 편집 거리, S/D/I, 오류 좌표·문맥·혼동쌍.
- 한글 자모 결합과 CJK 호환 한자·확장 한자·이체자 선택자 보존.
- 빈 정답, 100%를 넘는 CER, 문자 종류별 오류 분류, 계산·표시 한도.
- 무작위 작은 문자열과 별도 단순 알고리즘의 거리/정렬 결과를 교차 검증.
- manifest 검증, 파일 지문, 빈 쪽 삽입, 자료 누락, UTF-8 오류, 공통 평가 범위, dev/test 구분.
- 실제 Tk 화면에서 입력·오류 선택·취소·오래된 결과 차단·원시 결과 보존을 확인.
- HTML 이스케이프, CSV 정규화 조건, 저장 실패 시 이전 파일 보존, 원본 덮어쓰기 방지.
- Tesseract 연결부는 잘못된 언어, 취소·시간 제한, TSV 좌표·따옴표, 원본 변경 감지, 원시 줄바꿈 보존을 시험.
- RapidOCR/EasyOCR 연결부는 지원하지 않는 언어 조합, 누락·변경 모델, 엄격한 worker JSON·좌표·신뢰도 검증, 취소, 원본 변경, 원시 문자 보존을 시험.
- 엔진별 결과의 프로젝트 왕복 저장과 이전 인식 이력·교정문 보존, GUI 엔진 전달·복원, Tesseract 전용 PSM의 분리를 시험.
- 실제 PDF의 선택 쪽 렌더링과 고비트 회색조의 대비 보존을 시험.
- 프로젝트 왕복 저장, 원본 지문 변경·이동, 원시 결과/교정/이전 인식 보존, 손상 JSON, 쓰기 실패 시 정상본 보존을 시험.
- 다른 창의 저장 충돌, 저장 도중 편집, 원본·하드링크 덮어쓰기 차단, 원본이 없어져도 복구 사본 보관을 시험.
- 실제 스캔을 새 Tk 편집기에 표시한 뒤 문장을 수정하여 프로젝트 저장·재열기·TXT 내보내기를 실행. 원시 결과 불변과 교정문의 문자 단위 일치를 확인.

## 실제 로컬 엔진 실행

Tesseract 5.5.3.20260724 및 고정 버전 tessdata_best 8개 데이터의 SHA-256 확인을 통과했다.
`python -X utf8 scripts/install_tesseract.py --verify-only`로 이 설치 상태를 다시 확인할 수 있다.

공개 [대한독립선언서 스캔](https://commons.wikimedia.org/wiki/File:Declaration_of_Independence_of_Korea_(February_1919).jpg)을 실제 인식했다.
원출처는 독립기념관 자료이며 파일 설명 페이지의 public domain 표시를 확인했다.
해당 스캔은 6078 × 4322픽셀, SHA-256은
`358f2b3f443fd1678655ef33ca871de1a89499fbf4da392b81f49164c2408fc9`다.
원본·출처 기록·서로 다른 설정의 원시 결과는 `work/public-scan`에 분리 보관한다.

`chi_tra_vert+kor_vert`, PSM 5 실행은 약 23.6초에 원시 텍스트 1,883자와 단어 좌표 1,228개를 반환했다.
이 값은 **한 차례 실행 기록**이며 정확도나 속도 벤치마크가 아니다.
고문헌의 세로쓰기·붓글씨 형태에서 오독과 읽기 순서 문제가 다수 보인다.
해당 결과를 높은 인식률 또는 일반 스캔 문서의 대표 결과로 해석하지 않는다.

가로/자동 설정 시험에서는 Tesseract가 영면적 단어 상자 3개를 반환하는 사례를 발견했다.
원시 TXT를 그대로 보존하면서 해당 상자만 표시에서 제외하고, 원래 좌표와 사유를 기록한다.
유효한 상자만 남는지와 TXT의 모든 문자가 유지되는지 회귀 시험을 추가했다.

`work/public-scan/declaration-1919.abocr.json`은 실제 원시 결과를 열어 대조할 수 있는 프로젝트다.
UI 저장 검증용으로 추가한 문구는 별도 `work/gui-verification` 프로젝트에만 보관한다.
화면 기록은 `work/editor-public-scan.png`다.

RapidOCR/PP-OCRv5와 EasyOCR는 격리된 로컬 Python 환경에 설치했다. 설치 기록과 모델 SHA-256을 확인하고,
실제 합성 이미지 인식 결과를 공통 인터페이스로 받아 프로젝트 저장·재열기까지 확인했다.
RapidOCR의 제품 기본값은 서버 검출기와 mobile 인식기이며, 서버 인식기 실험과 구분한다.
두 새 엔진은 PSM 대신 자체 영역 검출을 사용한다. 한국어 모델과 중국어 모델의 지원 범위도 구분한다.
GUI는 최소 창 크기에서 엔진·언어·DPI와 원본/결과 표시를 확인했다.
실제 간체 60쪽 결과 프로젝트를 GUI에서 재열어 원본 29쪽 렌더, EasyOCR·간체 설정 복원,
원시 결과와 편집 위젯의 문자 일치, 프로젝트 파일 불변을 확인했다. 시험용 프로세스는
쓰기 가능한 `work`를 TEMP/TMP로 지정했다. 기본 sandbox 임시 폴더에서는 렌더 파일 생성 권한 오류가 있었다.

## 사용자 자료의 동일 입력 비교

비교 도중 이동된 원본은 새 위치의 SHA-256 일치를 확인한 후 프로젝트에 재연결했다.
입력 manifest와 기존 원시 인식 기록은 보존했고, 새 엔진 프로젝트 8개 모두 다시 열었다.
별도 Levenshtein 구현으로 195개 쪽/영역 비교의 편집거리와 집계 CER를 교차 확인했다.

사용자가 지정한 PDF/HWPX와 PDF/DOCX 자료의 기존 시험은 Git 제외 경로
`work/private-validation/report.html`, 추가 간체 시험은 `work/private-validation/simplified/report.html`에 보관한다.
0.3.0의 세 엔진 비교는 `work/private-validation/engine-comparison/report.html`과 `summary-all.json`에 보관한다.
공개 스캔 결과와 섞지 않으며 개인 원문·정답·개인 경로를 소스나 시험 fixture에 넣지 않는다.

- 간체 본문 60쪽, 번체 본문 3쪽, 한글·한자 혼용 본문 2영역의 총 65개 입력을 같은 정답으로 비교했다.
- PDF 63쪽은 원본에서 다시 렌더링한 300 DPI RGB 픽셀과 새 엔진의 입력 PNG가 일치함을 해시로 확인했다. 혼용 2영역도 기존 Tesseract 입력 이미지와 동일하다.
- 기준선은 자료별 기존 최선 설정을 사용했다. 간체 Tesseract `chi_sim`/PSM 6, 번체 `chi_tra`/PSM 3, 혼용 `kor+chi_tra`/PSM 6이다. 새 엔진에는 중국어 또는 한국어 모델을 명시했으며 한글+한자 혼용 지원을 가정하지 않았다.
- 정답과 PDF 내장 텍스트를 엔진에 전달하지 않았다. 공백만 제외한 micro CER로 비교하고 원문 점수도 보관했다. 간체·번체·이체자·문장부호는 변환하지 않았다.
- EasyOCR는 간체·번체 본문에서 오류율이 개선됐다. RapidOCR 기본 프로필은 간체에서 개선되고 번체에서는 악화됐다. 두 새 엔진의 한국어 모델로 처리한 한글·한자 혼용에서도 개선되지 않았다. 문자 검출 누락·읽기 순서·모델 문자 범위 문제는 남아 있다.
- 정답은 편집 원본과 PDF의 대응 및 일부 시각 대조를 사용한 잠정 기준이다. 최종 독립 수동 검수 정답이 아니며, 이미 튜닝에 사용한 개발 자료이므로 보류 평가나 일반화 성능을 주장하지 않는다.

## 자체 교정의 검증 범위

교정 후보·자동 적용·사용자 확정은 서로 구분한다. 현재 제품에는 자체 자동 교정 기능을 넣지 않았다.
별도 개발 실험에서 정책을 먼저 고정하고 Tesseract와 RapidOCR 출력의 차이 중 동일 길이 1~3글자의
완성형 한글 대치만 후보로 만들었다. 한자·문장부호·추가·삭제는 보호하고 원래 공백을 그대로 두었다.
정답은 후보 파일을 고정한 뒤 사후 평가에만 사용했다.

혼용 본문 2영역에서 후보 3개 중 2개는 개선됐지만 1개는 맞던 글자를 틀리게 바꿨다.
원시 OCR 변경과 사용자 채택은 모두 0건이다. 해당 결과와 정책·입력 지문·원문/후보는
`work/private-validation/engine-comparison/hangul-candidates/report.html`에 보관한다.
이는 후보 제시의 가능성과 오교정 위험을 보여 주는 소규모 개발 실험이며 제품 자동 교정의 성능 검증이 아니다.

## 검증하지 않은 성능

연결부의 일부 자동 시험은 외부 프로세스 응답을 대체하여 실패·저장 경로를 점검한다.
합성 문장의 실제 엔진 실행은 설치·연결 검증이며 대표 문헌 품질의 증거가 아니다.
전체 수동 검수 정답, 독립 보류 자료, 복잡한 표·사진 설명·세로쓰기의 체계적인 비교는 아직 부족하다.

동일 조건의 ABBYY 출력이 없어 ABBYY 대비 우열이나 동급 성능을 평가하지 않았다.
예제 텍스트의 오류율은 수작업으로 넣은 오류를 세는 결과다.

## 남은 제품 기능

영역 경계·읽기 순서 편집, 교정문 글자와 원본 좌표의 정밀 연결, 엔진 불일치/교정 후보 표시, 독립 AI 재판독,
검색 PDF·DOCX 내보내기, 자체 Windows 설치판.
현재 단어 좌표 표시는 원시 OCR을 기준으로 하며 교정한 글자의 위치를 추측해서 연결하지 않습니다.
